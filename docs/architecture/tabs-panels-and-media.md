# Tabs, Panels & Media

This guide elaborates on WIS.md. If anything here conflicts, WIS.md wins.

## Memory model: sleep, wake, restore

- Background tab webviews are discarded ("slept") after an idle threshold and recreated on focus; at launch only visible tabs spin up a webview (`useTabWebviews.ts`, gated by `tab_sleep_enabled` / `tab_sleep_minutes`). Never-sleep: active tab, popped-out tab, and audibly-playing tabs (per the `audio.rs` poll, since cutting live sound is never intended); pinned tabs sleep like any background tab once past the idle threshold. Members of a collapsed folder sleep immediately, bypassing the idle timer.
- Teardown is race-proof: the webview map slot is held PENDING until the native close completes, so a quick wake cannot spawn a second webview under the same label while the old one tears down (an orphan would leak invisibly, still playing audio). Rejoin mid-teardown recreates once the close lands.
- Wake is not a cold reload (`interaction_state.rs`): before discard, the WKWebView `interactionState` (back/forward list, scroll, form data; macOS 12+) is read as base64 and cached in chrome memory (30 most-recent). On wake `create_tab_webview` starts on `about:blank` and applies the blob, whose restore navigates itself.
- Sessions survive a restart (`tab_session.rs` + `tab_sessions`, M0018). Each finished load marks the tab dirty; after a ~1.2s quiet period `TabSessionSaver` reads `interactionState` off the main thread and upserts it (periodic, not quit-time, which would deadlock the same-thread `with_webview` hop from `ExitRequested`). At launch `lib.rs` purges sessions orphaned by tabs closed last run (`purge_tab_sessions_except`) and seeds survivors into `AppState::pending_restore_states`, which `create_tab_webview` consumes. `setInteractionState:` silently no-ops on a blob from an incompatible WebKit, so the restore arms a ~3s guard that cold-loads the URL if still on `about:blank`. Ephemeral tabs never persist.
- Chrome pages keep scroll across tab switches (`useScrollMemory.ts`): Settings/History/Downloads are React components that unmount on switch-away, so a module-level per-tab-id store restores position on remount. Session-scoped.

## Task manager

- Live per-webview memory (`memory.rs` + `TaskManagerSection`), polling every 3s while the settings page shows. Pid from WebKit `_webProcessIdentifier` (guarded by `respondsToSelector`), footprint from `proc_pid_rusage` `ri_phys_footprint` (the Activity Monitor figure); tabs and widget panels get a one-click Close. macOS only: `collect_webview_memory` is `#[cfg]`-split and returns empty off macOS, since WebView2 shares one process and exposes no per-webview pid; the widget memory-cap sweep is inert there rather than wrong.

## Quick browser features

- Per-tab zoom (Cmd +/-/0) persisted via `apply_tab_zoom` (`setPageZoom:` / WebView2 `ZoomFactor` / GTK `set_zoom_level`). Shortcuts: every `KeyAction` is a rebindable native menu item; a live rebind rebuilds via `apply_menu`, which must run on the main thread (off-main `NSMenu` mutation silently fails) and call `Menu::set_as_app_menu` (plain `set_menu` does not refresh live key equivalents). `keybindings` deserialize leniently (`deserialize_keybindings` drops unknown ids) so removing an action never bricks the profile.
- Find-in-page (`find.rs`) with a live count: a `_WKFindDelegate` per webview (retained as an associated object since `_setFindDelegate:` is weak) plus `_findString:options:maxCount:`, emitted over `wis-find-result`, with a public-API fallback lacking the count. Windows uses a CSS Custom Highlight engine; Linux `FindController` reports total only.
- Numbered switching (Cmd+1..8) follows on-screen order, not raw `tab_order`: `numberedTabsFor` (`useKeyActions.ts`) lists expanded-folder members then loose tabs, excluding pinned and collapsed-folder members. Cmd+9 (`switch_to_last_tab`) ping-pongs to the previous tab; the palette omits the positional actions.
- Reopen (Cmd+Shift+T) restores the full session (`interactionState` captured into the `ClosedTab` ring, handed via `pending_restore_states`) and is folder-faithful (recreated loose, re-assigned to its original `folder_id`) and inert in private workspaces.
- Print / Save as PDF (Cmd+P, `print.rs`): macOS `printOperationWithPrintInfo:` panel covers PDF export; Windows `ShowPrintUI`, Linux `webkit_print_operation_run_dialog`. `about:` pages have no native webview and are skipped.
- Hover tab previews (`tab_preview.rs` + `useTabHoverPreview` + the `tabpreview` overlay): dwell on a tab row (delegated over `[data-tab-id]`/`[data-mtab-id]`/`[data-pin-id]`, covering both strips, folder members, and pinned tabs) and a card appears beside it with a downscaled snapshot over a title/host caption. Capture per engine (`screenshot::preview_snapshot`): macOS scales at capture (`WKSnapshotConfiguration.snapshotWidth`, `afterScreenUpdates` off); Windows/Linux reuse `capture_visible` plus a box-filter downscale (`downscale_png`). Captures happen at switch-away, pre-sleep, and post-load of the active tab (cached in `AppState.tab_previews`, capped, mirrored to `<app data>/previews` for non-private tabs so restored-asleep tabs preview across launches; startup-purged against restored tab ids); hover serves the cache, live-captures the active tab, and best-effort-attempts hidden webviews (outcome logged; failures render the placeholder card). Windows/Linux arms are CI-compile-validated, runtime-unverified.

## Swipe navigation

- Two-finger swipe goes back/forward (`swipe_nav.rs`): a builder-level page script watches wheel overscroll at the page's true horizontal edge, and past a commit threshold fills a themed half-circle progress indicator isolated in a shadow root, calling `history.back()` / `history.forward()` on release. `overscroll-behavior-x: none` is pinned on the root scroller so the gesture, not the page, owns horizontal overscroll. On macOS `install_phase_monitor` is an `NSEvent` scroll-phase monitor that commits exactly at finger lift.
- History availability drives the arrows: `push_nav_state` pushes `canGoBack` / `canGoForward` per direction after each load and title change (macOS + Windows), with the Windows `eval` run OUTSIDE the `with_webview` hop, since running it inside wedges the UI thread. The same engine read (`read_nav_state`) also lands in the tab model (`Tab.can_go_back` / `can_go_forward` via `with_tab_nav_state`, in-memory like `loading`), which dulls the chrome's Back/Forward buttons per direction; a 150ms delayed re-read after `tab_go_back/forward` covers same-document history steps that fire no load or title event. `set_swipe_accent` / `useSwipeAccentSync` push the resolved `--primary-400` into every live tab webview on a theme or accent change, so the indicator tracks the current accent.

## Peek

- Find-in-peek: while a preview is up, `tab_find_string`/`tab_find_clear` retarget to it (`peek::live_peek_label`); results carry the peek label and the FindBar accepts both keys. Clear covers tab and peek (per-webview highlight state). Windows peeks get the shim + JS find engine plus a find-scoped message receiver (`win_dispatch::install_find_only`, never the full dispatcher); Linux peeks wire `find::install_linux`. While a peek is up, the "current page" shortcuts are modal to it: the palette and URL-bar focus are ignored (both address the hidden tab), reload / hard-reload become a plain preview reload (`peek_reload`, resetting the reader toggle), and close-tab dismisses the peek instead of closing the tab behind it.
- In-peek navigation: the preview carries the same swipe back/forward gesture as tabs (the builder injects the swipe scripts; `swipe_nav::swipe_target` widens the macOS phase-monitor and accent pushes to `peek-page-*` labels), plus header arrows with per-direction dulling and the tab nav shortcuts (the surface handles `wis-keyaction` itself while the main chrome swallows go_back/go_forward during a peek). `peek_go_back`/`peek_go_forward` eval history steps with a 150ms nav-state re-read; every preview navigation emits `wis-peek-nav-state` (window, back, fwd, url, fresh `assess_link` of that url) so the arrows, host label, "Open as tab", the warning banner, and the high-risk confirm gate all follow where the preview actually is (the creation-time assessment, which carries anchor-text context, applies only while still on the peeked link).
- Opt+click a link (intercepted at `mousedown`, since macOS turns Option+click into a download) previews it in an isolated card. The preview (`peek-page-<window>`) is incognito (separate ephemeral store) and routed through the workspace proxy, so a scam link cannot touch the browser. A banner warns via pure heuristics (`wis_core::link_safety::assess_link`). Trigger is the `wisPeek` handler plus an Opt+click detector baked in at builder level (`peek::page_script` as an `initialization_script`, so a page loading at launch can still be peeked). A reader toggle runs the shared `reader::reader_script`; opening a High-risk link as a tab needs a red "Proceed anyway".

## Reader mode

- Clean-article view (`reader.rs`, `tab_set_reader`), toggled from the toolbar, `ToggleReader` (`Alt+Cmd+R`), or the palette. The transform (`reader::reader_script`, shared with Peek) runs inside the tab's own webview and rebuilds the tree via `documentElement.innerHTML`, not `document.write` (which WebKit leaves blank on some pages, e.g. Wikipedia), so no untrusted markup reaches the chrome; exit reloads. A session-only `Tab.reader` flag drives the button; a real navigation resets it. Disabled on chrome pages.

## Video popout

- Switching away from a tab playing video floats it as an always-on-top borderless mini player (`video_popout/`) visible on every Space. A second video pipeline is impossible under WKWebView (MSE/DRM cannot re-open elsewhere), so the popout is the tab's own webview: `Webview::reparent` moves it into the floating window and back into `ActivePopout.origin_window` on restore. WebKit pauses media on every hierarchy move, so each reparent is followed by a page-side resume kick (`__wisPopoutResume`) that never overrides a user pause.
- A builder-level init script pins the chosen `<video>` across the tiny viewport, reparenting it to the document root while popped so no wrapper can re-anchor or crop it; `<body>` goes visibility-hidden over a black root. An injected overlay supplies controls (X, hover volume mirroring `volumechange`, a hover seek scrubber mirroring `timeupdate` that hides for live streams (`duration` Infinity), click pause, double-click seek, drag via native `start_dragging`, aspect-locked corner resize). Opens unfocused but responds to its first click (`accept_first_mouse`); hover works while non-key via an always-active `NSTrackingArea`. Payloads arrive over `wisPopout`, sender identified by the WKWebView `accessibilityIdentifier`, every field validated.
- The chrome decides when. Automatic: the script reports the dominant qualifying video (unmuted, on-screen, >=180x100) via `wis-popout-media`; `useVideoPopout` adopts a tab at its visible-to-hidden transition (gated by `video_popout_enabled`). Manual: a hit-tested pop-out button plus the `PopOutVideo` action (unbound by default); works on paused videos, leaves the tab over a black placeholder, folds back only on X / placeholder / action / navigation / close. One popout at a time; the popped tab is sleep-exempt; window height locks to the live aspect ratio; every popout starts 440px wide with only position persisted. Main-frame videos only.

## Tab audio indicator and mute

- A speaker appears beside any audibly-playing tab (`audio.rs`, 2s poll of `_isPlayingAudio`, so iframe/Web Audio count). Clicking mutes without activating the tab; a muted tab shows a slashed speaker persistently. Muting is engine-level (`_setPageMuted:`), so pages cannot un-mute themselves; state is session-scoped on `AppState`, re-applied when a slept webview is recreated, and forgotten on close (where `forget_tab` runs `stop_all_media`, since wry over-retains the WKWebView on drop and a closed tab, especially a popout, would keep playing until quit).
- Broadcast as `wis-tab-audio`, rendered via `useTabAudio` + `TabAudioButton` in both layouts (favicon and speaker are `flex: 0 0 auto`, so the title yields first). Widget panels get the same mute as a header toggle (`set_widget_panel_muted`). Cross-platform: Windows `ICoreWebView2_8::SetIsMuted` + `IsDocumentPlayingAudio`; Linux `webkit_web_view_set_is_muted` (mute works, indicator not yet wired).

## Page capture

- Capture copies to the clipboard by default, with a toast offering Save (`screenshot.rs`, macOS). `capture_to_clipboard(id, mode)` (`visible` / `region` / `window`) writes the PNG to the pasteboard and stashes bytes in `AppState::last_screenshot`; `save_last_screenshot` runs the save panel over those bytes so Save never re-captures.
- Window capture composites without Screen Recording permission (deliberate, for a privacy browser): `capture_window` snapshots the chrome webview as the base, then draws every visible `tab-*` webview over it into one `NSBitmapImageRep`, each clipped to its on-screen corner radius. Uses `takeSnapshotWithConfiguration:` (macOS 11+) at backing scale. Region mode is window-level (selection can span the chrome): a full-window `overlay-screenshot-region` webview dims, captures the pointer, takes first-responder focus (Escape cancels), and passes a rect to `capture_window` as a `crop`. Actions `CaptureVisible` / `CaptureRegion` / `CaptureWindow` unbound by default. Windows: visible via WebView2 `CapturePreview` (page-only), region crops it (`crop_png`); Linux capture not yet wired. Capture is held for Save even if the clipboard write fails.

## Downloads

- Remote-webview downloads are intercepted via wry's hook (`downloads.rs`), safety-first. Destination `~/Downloads/<leaf>`: the server name is reduced by `wis_core::sanitize_filename` and collision-resolved by `unique_filename` against disk and in-flight items, never overwriting; a directory escape is denied. Completed files get the `com.apple.quarantine` xattr.
- `DownloadItem` lives in `AppState.downloads` (sync mutex, since wry callbacks are synchronous main-thread code); every change emits `downloads-changed`. macOS limits: the finish event carries only url+success (matched to the oldest in-flight of that url), and wry exposes no progress or cancel, so progress is the file size polled every 500ms; cancel comes from the vendored wry's fifth patch (`cancel_download_to`, a main-thread registry of live WKDownloads keyed by destination path) driven by `cancel_download`, which marks the item cancelled and unlinks the partial file (the X on in-flight rows is macOS-only); the total comes from the vendored wry's fourth patch (`last_download_expected_bytes`, the response's Content-Length read in the started callback's stack), `None` when the server sends no length or off macOS, in which case the chrome shows the indeterminate spinner instead of the determinate pie. Content-Length counts encoded bytes vs the poll's decoded ones, so the pie clamps and completion only ever comes from the finish event. Private-workspace and Peek downloads save but are flagged `private` and never recorded. Completed non-private ones persist in the `downloads` table (M0014); `open_download` / `reveal_download` validate the recorded path is still a regular file inside its recorded directory (ruling out symlink swaps), else resolve `false`. UI: an `overlay-downloads` popup and a full `about:downloads` page; ask-where (`download_ask_where`) reads settings through the `AppState.download_prefs` sync mirror, since the callback cannot await the state lock.

## Favicons

- Favicon resolution (`favicons.rs`) falls back past `<origin>/favicon.ico`: when that yields no usable image (Discord, Gemini, DeepSeek, most SPAs), a hand-rolled scanner reads the page's `<link rel="icon">` declarations directly, no HTML-parser dependency. The widget-dock `WidgetFavicon` path pre-warms through `prefetch_favicon` (in-memory + on-disk cache), rendering a letter tile when nothing resolves.

## Sidebar quick-launch widgets

- A global ordered set of social + AI shortcuts (`UserSettings.sidebar_widgets`; catalog in `src/lib/widgets.ts`). Clicking opens its widget panel (`widget_panel.rs`): a per-widget, per-window webview (`widget-panel-<window>-<id>`) floating above the tab webviews, sharing the calling window's workspace store (logins persist), proxy, UA, and `WKContentRuleList` filtering; no Tauri capability.
- Switching is a hide/show of loaded webviews, not a navigation, so it is instant and keeps in-page state. The pool is bounded by a count cap (`widget_panel_limit`, default 2, LRU-evicting, since each is a full page worth 100MB to ~2GB), an idle window (`widget_sleep_minutes`), and a memory cap (`widget_memory_cap_mb`, swept every 30s). A panel is not a tab: it dismisses on re-click, Escape, an outside chrome click, a tab-webview click, or an active-tab change. Dismissal hides rather than destroys (re-open keeps drafts/sockets) and suspends media (`setAllMediaPlaybackSuspended`); hard-destroyed on workspace switch and in private workspaces. Header bar (`overlay-widgetheader`) shows the live host with mute + cache-bypassing `reloadFromOrigin`. Resizing rides an invisible `overlay-widgetresize` strip; stacking is actively maintained tabs < panels < overlays (`promote_panels_to_front`).
- `UserSettings.widget_keep_loaded` (default on) is a control distinct from the count, idle, and memory caps above: with it off, a panel's webview is destroyed the moment it is dismissed or switched away, reclaiming its WebContent process, while logins still persist in the store.
- Destroying any remote-content webview goes through `webview_close::terminate_page` first: wry's macOS `Drop` deliberately leaks the `WKWebView`, so a bare `Webview::close` strands the page's WebContent process (multi-GB for heavy apps) invisible to the task manager. The `_close` SPI exits that process; applied on every widget/tab/peek destroy path, on secondary-window close (`terminate_window_pages`), and reachable from the frontend via the `close_tab_webview` command (tab labels only). Panel webview creation itself is serialized (`PANEL_CREATE_LOCK`): overlapping WebView2 creations can deadlock in the Win32 message pump while the runtime holds its web-context lock (rapid widget opens silently failing).
- Some widgets carry a theme-sensitive URL (`effectiveWidgetUrl` / `navigate_widget_panel`): Instagram's web dark mode is a `?theme=dark` query param, applied at open time and re-navigated on a live light/dark flip, tracked via a `data-mode` MutationObserver. Telegram is pinned to the lighter WebA client (`web.telegram.org/a/`); records that stored the old bare-origin catalog URL (heavy WebK) are rewritten at open time.

## Bookmarks

- Per-workspace, optional folders (`folder_id` NULL = unfiled), persisted in SQLite (`wis_storage::bookmarks`, never in `BrowserState`). A glyph opens `overlay-bookmarks`. The address-bar star bookmarks into the last-used folder and auto-pins while the quick-access row has room (`PIN_CAP` = 6); clicking again removes it. Disabled in private workspaces. Pinning is independent of folder membership (`pinned` / `pin_position`): a bookmark can be pinned and live in a folder. Every mutation broadcasts `bookmarks-changed`; surfaces refetch via `useBookmarkSync` and the popup optimistically patches its cache (`setQueryData`). Overlay webviews call `disable_drag_drop_handler()` so wry does not swallow in-page HTML5 DnD; a folder reorder uses a dedicated grip handle (a draggable toggle would swallow drops on it).
- HTML import/export (Settings > Bookmarks): the pure Netscape-format parser/serializer lives in `wis_core::netscape` (hand-rolled linear scanner; only http(s) hrefs kept, entities decoded, names clamped, file/count caps). Wis folders do not nest, so nested `<DL>` levels flatten into one `" / "`-joined folder name. `Storage::import_bookmarks` writes one transaction: folders reused by name or created, duplicate (folder, url, title) rows skipped, everything appended unpinned; the command (`import_bookmarks_html` / `export_bookmarks_html`) drives the `panels.rs` file dialogs and broadcasts `bookmarks-changed` once. Export writes unfiled entries then each folder as a flat level, carrying `created_at` as `ADD_DATE` so other browsers keep the dates; import parses `ADD_DATE` but drops it at the storage boundary (nothing in Wis reads creation dates). Pin state has no slot in the format and does not survive export.

## History and cookies

- Per-workspace deduped history with search; dedupe keys on the fragment-stripped URL, so anchor jumps update one row. Native cookie/site-data clear via `WKHTTPCookieStore` + `removeDataOfTypes`. An untitled page's title is the bare site name (`wis_core::tab::placeholder_title`), never the raw URL.
- Stay logged in across restarts (`cookies.rs`): WebKit keeps session cookies in memory only. A workspace's expiry-less cookies snapshot to `session_cookies` (after each load and on a 60s timer) and restore on the first tab each run, once per workspace via `AppState::restored_cookies`; empty snapshots never overwrite a saved one. Encrypted with ChaCha20-Poly1305 under a dedicated key (`session_key_load_or_create`, not Touch ID gated, so available at launch); if the key is unavailable nothing is persisted. Blast-radius bound: `created_at` stamped once, and a restored session auto-expires after `SESSION_COOKIE_TTL_DAYS` = 14, forcing re-auth; stale snapshots purged at launch. Gated on `persist_sessions`; never ephemeral.

## Browser identity and default-browser handoff

- Remote webviews present a modern Safari-class UA by default (`wis_core::user_agent`), since WKWebView's default omits the `Version/.../Safari/...` tokens and sites flag it unsupported. Configurable in Settings, Compatibility: a default `UaProfile` plus per-host overrides (`ua_site_overrides`). Set at webview-build time on tab and Peek webviews; chrome/overlay untouched. The platform token follows the running OS (`UaPlatform::host` reads `std::env::consts::OS`; Mac strings locked byte-for-byte, `from_os` unit-tested from any host).
- Open in default browser (`external::open_in_external_browser`) hands the current `http(s)` page to the OS default (`open` / `xdg-open` / `start`), an exit hatch for pages embedded WebKit cannot fully handle (e.g. Widevine). Scheme-validated to `http(s)`; on macOS, if Wis is itself the default handler it falls back to Safari so the handoff cannot loop back.
