# Tabs, Panels & Media

This guide elaborates on WIS.md. If anything here conflicts, WIS.md wins.

## Memory model: sleep, wake, restore

- Background tab webviews are discarded ("slept") after an idle threshold and recreated on focus; at launch only visible tabs spin up a webview (`useTabWebviews.ts`, gated by `tab_sleep_enabled` / `tab_sleep_minutes`). Never-sleep: active tab, popped-out tab, and audibly-playing tabs (per the `audio.rs` poll, since cutting live sound is never intended); pinned tabs sleep like any background tab once past the idle threshold. Members of a collapsed folder sleep immediately, bypassing the idle timer.
- Teardown is race-proof: the webview map slot is held PENDING until the native close completes, so a quick wake cannot spawn a second webview under the same label while the old one tears down (an orphan would leak invisibly, still playing audio). Rejoin mid-teardown recreates once the close lands.
- Wake is not a cold reload (`interaction_state.rs`): before discard, the WKWebView `interactionState` (back/forward list, scroll, form data; macOS 12+) is read as base64 and cached in chrome memory (30 most-recent). On wake `create_tab_webview` starts on `about:blank` and applies the blob, whose restore navigates itself.
- Sessions survive a restart (`tab_session.rs` + `tab_sessions`, M0018). Each finished load marks the tab dirty; after a ~1.2s quiet period `TabSessionSaver` reads `interactionState` off the main thread and upserts it (periodic, not quit-time, which would deadlock the same-thread `with_webview` hop from `ExitRequested`). At launch `lib.rs` purges sessions orphaned by tabs closed last run (`purge_tab_sessions_except`) and seeds survivors into `AppState::pending_restore_states`, which `create_tab_webview` consumes. `setInteractionState:` silently no-ops on a blob from an incompatible WebKit, so the restore arms a ~3s guard that cold-loads the URL if still on `about:blank`. Ephemeral tabs never persist.
- Chrome pages keep scroll across tab switches (`useScrollMemory.ts`): Settings/History/Downloads are React components that unmount on switch-away, so a module-level per-tab-id store restores position on remount. Session-scoped.

## Task manager

- Live per-webview memory (`memory.rs` + `TaskManagerSection`), polling every 3s while the settings page shows. Pid from WebKit `_webProcessIdentifier` (guarded by `respondsToSelector`), footprint from `proc_pid_rusage` `ri_phys_footprint` (the Activity Monitor figure); tabs and widget panels get a one-click Close. macOS only: `collect_webview_memory` is `#[cfg]`-split and returns empty off macOS, since WebView2 shares one process and exposes no per-webview pid; the widget memory-cap sweep is inert there rather than wrong.

## Quick browser features

- Per-tab zoom (Cmd +/-/0) persisted via `apply_tab_zoom` (`setPageZoom:` / WebView2 `ZoomFactor` / GTK `set_zoom_level`). Shortcuts: every `KeyAction` is a rebindable native menu item; a live rebind rebuilds via `apply_menu`, which must run on the main thread (off-main `NSMenu` mutation silently fails) and call `Menu::set_as_app_menu` (plain `set_menu` does not refresh live key equivalents). `keybindings` deserialize leniently (`deserialize_keybindings` drops unknown ids) so removing an action never bricks the profile.
- Find-in-page (`find.rs`) with a live count: a `_WKFindDelegate` per webview (retained as an associated object since `_setFindDelegate:` is weak) plus `_findString:options:maxCount:`, emitted over `wis-find-result`, with a public-API fallback lacking the count. Windows uses a CSS Custom Highlight engine; Linux `FindController` reports total only.
  - **Colours**: the Windows engine paints the desktop accent, read per search from `HKCU\Software\Microsoft\Windows\DWM\AccentColor` (Blink paints its own blue for the `Highlight` keyword): a 35% tint for every match and solid for the current one, with black or white text by luminance, leaning white. macOS and Linux keep WebKit's native find and its system yellow.
  - **Teardown**: matches never outlive the page or the tab. A navigation clears them as it starts (`find::clear_webview` on page-load start), while the old document is still current, so none come back from the back-forward cache.
- Numbered switching (Cmd+1..8) follows on-screen order, not raw `tab_order`: `numberedTabsFor` (`useKeyActions.ts`) lists expanded-folder members then loose tabs, excluding pinned and collapsed-folder members. Cmd+9 (`switch_to_last_tab`) ping-pongs to the previous tab; the palette omits the positional actions.
- Reopen (Cmd+Shift+T) restores the full session (`interactionState` captured into the `ClosedTab` ring, handed via `pending_restore_states`) and is folder-faithful (recreated loose, re-assigned to its original `folder_id`) and inert in private workspaces.
- Print / Save as PDF (Cmd+P, `print.rs`): macOS `printOperationWithPrintInfo:` panel covers PDF export; Windows `ShowPrintUI`, Linux `webkit_print_operation_run_dialog`. `about:` pages have no native webview and are skipped.
- Hover tab previews (`tab_preview.rs` + `useTabHoverPreview` + the `tabpreview` overlay): dwell on a tab row (delegated over `[data-tab-id]`/`[data-mtab-id]`/`[data-pin-id]`, covering both strips, folder members, and pinned tabs) and a card appears beside it with a downscaled snapshot over a title/host caption. Capture per engine (`screenshot::preview_snapshot`): macOS scales at capture (`WKSnapshotConfiguration.snapshotWidth`, `afterScreenUpdates` off); Windows/Linux reuse `capture_visible` plus a box-filter downscale (`downscale_png`). Captures happen at switch-away, pre-sleep, and post-load of the active tab (cached in `AppState.tab_previews`, capped, mirrored to `<app data>/previews` for non-private tabs so restored-asleep tabs preview across launches; startup-purged against restored tab ids); hover serves the cache, live-captures the active tab, and best-effort-attempts hidden webviews (outcome logged; failures render the placeholder card). Windows/Linux arms are CI-compile-validated, runtime-unverified.

## Swipe navigation

- Two-finger swipe goes back/forward (`swipe_nav.rs`): a builder-level page script watches wheel overscroll at the page's true horizontal edge, and past a commit threshold fills a themed half-circle progress indicator isolated in a shadow root, calling `history.back()` / `history.forward()` on release; the release snaps the fill to full with its transition suppressed, holds the indicator 150ms (`HOLD`) and then fades it, and a new finger-down or `pagehide` ends the hold early (on the wheel-quiet fallback, momentum events after the commit can start a new sequence and end it sooner). `overscroll-behavior-x: none` is pinned on the root scroller so the gesture, not the page, owns horizontal overscroll. On macOS `install_phase_monitor` is an `NSEvent` scroll-phase monitor that commits exactly at finger lift. A swipe stays a scroll when anything under the pointer can still scroll that way, found through the event's composed path so scrollers inside shadow roots count, with a right-to-left scroller measured from its left edge. Shift turns a mouse wheel sideways, so a shifted wheel never navigates, and a popped-out tab (`html.__wis-popout-mode`) ignores the gesture.
- History availability drives the arrows: `push_nav_state` pushes `canGoBack` / `canGoForward` per direction after each load and title change (macOS + Windows), with the Windows `eval` run OUTSIDE the `with_webview` hop, since running it inside wedges the UI thread. The same engine read (`read_nav_state`) also lands in the tab model (`Tab.can_go_back` / `can_go_forward` via `with_tab_nav_state`, in-memory like `loading`), which dulls the chrome's Back/Forward buttons per direction; a 150ms delayed re-read after `tab_go_back/forward` covers same-document history steps that fire no load or title event. `set_swipe_accent` / `useSwipeAccentSync` push the resolved `--primary-400` into every live tab webview on a theme or accent change, so the indicator tracks the current accent.

## Peek

- Find-in-peek: while a preview is up, `tab_find_string`/`tab_find_clear` retarget to it (`peek::live_peek_label`); results carry the peek label and the FindBar accepts both keys. Clear covers tab and peek (per-webview highlight state). Windows peeks get the shim + JS find engine plus a find-scoped message receiver (`win_dispatch::install_find_only`, never the full dispatcher); Linux peeks wire `find::install_linux`. While a peek is up, the "current page" shortcuts are modal to it: the palette and URL-bar focus are ignored (both address the hidden tab), reload / hard-reload become a plain preview reload (`peek_reload`, resetting the reader toggle), and close-tab dismisses the peek instead of closing the tab behind it.
- In-peek navigation: the preview carries the same swipe back/forward gesture as tabs (the builder injects the swipe scripts; `swipe_nav::swipe_target` widens the macOS phase-monitor and accent pushes to `peek-page-*` labels), plus header arrows with per-direction dulling and the tab nav shortcuts (the surface handles `wis-keyaction` itself while the main chrome swallows go_back/go_forward during a peek). `peek_go_back`/`peek_go_forward` eval history steps with a 150ms nav-state re-read; every preview navigation emits `wis-peek-nav-state` (window, back, fwd, url, fresh `assess_link` of that url) so the arrows, host label, "Open as tab", the warning banner, and the high-risk confirm gate all follow where the preview actually is (the creation-time assessment, which carries anchor-text context, applies only while still on the peeked link).
- Opt+click a link (intercepted at `mousedown`, since macOS turns Option+click into a download) previews it in an isolated card. The preview (`peek-page-<window>`) is incognito (separate ephemeral store) and routed through the workspace proxy, so a scam link cannot touch the browser. A banner warns via pure heuristics (`wis_core::link_safety::assess_link`). Trigger is the `wisPeek` handler plus an Opt+click detector, both in Wis's content world on macOS (see `cross-platform-and-page-channel.md`). A reader toggle runs the shared `reader::reader_script`; opening a High-risk link as a tab needs a red "Proceed anyway".

## Reader mode

- Finding the article (`reader::MAIN_CONTENT_FINDER`, shared with the assistant's page text): the largest named container (`article`, `main`, `[role=main]` and the usual content classes) with 200 characters or more; otherwise the `div` or `section` with the most paragraph text across at least two paragraphs. Blocks marked as comments, sidebars, related links and the like never count, nor do their paragraphs toward a block around them, and a tie goes to the deeper block. A page with no body yields nothing rather than throwing.
- Clean-article view (`reader.rs`, `tab_set_reader`), toggled from the toolbar, `ToggleReader` (`Alt+Cmd+R`), or the palette. The transform (`reader::reader_script`, shared with Peek) runs inside the tab's own webview and rebuilds the tree from nodes (`documentElement.replaceChildren`), not `document.write` (which WebKit leaves blank on some pages, e.g. Wikipedia) and not an HTML string (which a page enforcing Trusted Types refuses), so no untrusted markup reaches the chrome; exit reloads. A session-only `Tab.reader` flag drives the button; a real navigation resets it. Disabled on chrome pages.

## Video popout

- Switching away from a tab playing video floats it as an always-on-top borderless mini player (`video_popout/`) visible on every Space. A second video pipeline is impossible under WKWebView (MSE/DRM cannot re-open elsewhere), so the popout is the tab's own webview: `Webview::reparent` moves it into the floating window and back into `ActivePopout.origin_window` on restore. WebKit pauses media on every hierarchy move, so each reparent is followed by a page-side resume kick (`__wisPopoutResume`) that never overrides a user pause.
- A document-start script in Wis's content world (a builder init script off macOS) pins the chosen `<video>` across the tiny viewport, reparenting it to the document root while popped so no wrapper can re-anchor or crop it; `<body>` goes visibility-hidden over a black root. An injected overlay supplies controls (X, hover volume mirroring `volumechange`, a hover seek scrubber mirroring `timeupdate` that hides for live streams (`duration` Infinity), click pause, double-click seek, drag via native `start_dragging`, aspect-locked corner resize). Opens unfocused but responds to its first click (`accept_first_mouse`); hover works while non-key via an always-active `NSTrackingArea`. Payloads arrive over `wisPopout`, sender identified by the WKWebView `accessibilityIdentifier`, every field validated.
- The chrome decides when. Automatic: the script reports the dominant qualifying video (unmuted, on-screen, >=180x100) via `wis-popout-media`; `useVideoPopout` adopts a tab at its visible-to-hidden transition (gated by `video_popout_enabled`). Manual: a hit-tested pop-out button plus the `PopOutVideo` action (unbound by default); works on paused videos, leaves the tab over a black placeholder, folds back only on X / placeholder / action / navigation / close. One popout at a time; the popped tab is sleep-exempt; window height locks to the live aspect ratio; every popout starts 440px wide with only position persisted. Main-frame videos only.

## Tab audio indicator and mute

- A speaker appears beside any audibly-playing tab (`audio.rs`, 2s poll of `_isPlayingAudio`, so iframe/Web Audio count). Clicking mutes without activating the tab; a muted tab shows a slashed speaker persistently. Muting is engine-level (`_setPageMuted:`), so pages cannot un-mute themselves; state is session-scoped on `AppState`, re-applied when a slept webview is recreated, and forgotten on close (where `forget_tab` runs `stop_all_media`, since wry over-retains the WKWebView on drop and a closed tab, especially a popout, would keep playing until quit).
- Broadcast as `wis-tab-audio`, rendered via `useTabAudio` + `TabAudioButton` in both layouts (favicon and speaker are `flex: 0 0 auto`, so the title yields first). Widget panels get the same mute as a header toggle (`set_widget_panel_muted`). Cross-platform: Windows `ICoreWebView2_8::SetIsMuted` + `IsDocumentPlayingAudio`; Linux `webkit_web_view_set_is_muted` (mute works, indicator not yet wired).

## Page capture

- Capture copies to the clipboard by default, with a toast offering Save (`screenshot.rs`, macOS). `capture_to_clipboard(id, mode)` (`visible` / `region` / `window`) writes the PNG to the pasteboard and stashes bytes in `AppState::last_screenshot`; `save_last_screenshot` runs the save panel over those bytes so Save never re-captures.
- Window capture composites without Screen Recording permission (deliberate, for a privacy browser): `capture_window` snapshots the chrome webview as the base, then draws every visible `tab-*` webview over it into one `NSBitmapImageRep`, each clipped to its on-screen corner radius. Uses `takeSnapshotWithConfiguration:` (macOS 11+) at backing scale. Region mode is window-level (selection can span the chrome): a full-window `overlay-screenshot-region` webview dims, captures the pointer, takes first-responder focus (Escape cancels), and passes a rect to `capture_window` as a `crop`. Actions `CaptureVisible` / `CaptureRegion` / `CaptureWindow` unbound by default. Windows: visible via WebView2 `CapturePreview` (page-only), region crops it (`crop_png`); Linux capture not yet wired. Capture is held for Save even if the clipboard write fails.

## Downloads

- Remote-webview downloads are intercepted via wry's hook (`downloads.rs`), safety-first. Destination `~/Downloads/<leaf>`: the server name is reduced by `wis_core::sanitize_filename` and collision-resolved by `unique_filename` against disk and in-flight items, never overwriting; a directory escape is denied. Completed files get the `com.apple.quarantine` xattr. On macOS a main-frame PDF or a `Content-Disposition: attachment` response from any frame is forced into this pipeline instead of WebKit's inline viewer (seventh vendored wry patch, `set_main_frame_download_policy`), since that viewer's HUD calls private hooks wry lacks and leaves the tab stuck, and a hidden iframe's attachment would otherwise render unseen; subframe PDFs without one still render inline. Google Docs' own Print is the exception (`print_export.rs`, macOS): outside Chrome it exports a print-flagged PDF (`2=print&3=1` among its numbered export options) into a hidden iframe, so that download goes to a temporary file instead, is read and removed when it finishes, and opens in the native print sheet (PDFKit) on the tab's window, never reaching the downloads list. Sheets and Slides request the same URL to print as to download, so theirs still download. A navigation that turns into a download fails provisionally with WebKitErrorDomain 102 (frame load interrupted by policy change); the tab page-load handler reconciles the model with the engine on that code: a tab still showing a page gets its URL and title back (`with_tab_url_synced` + the live document title), and a tab that never rendered anything (a tab opened for the download) is closed, or reset to the new-tab page when it is the workspace's last tab.
- `DownloadItem` lives in `AppState.downloads` (sync mutex, since wry callbacks are synchronous main-thread code); every change emits `downloads-changed`. macOS limits: the finish event carries only url+success (matched to the oldest in-flight of that url), and wry exposes no progress or cancel, so progress is the file size polled every 500ms; cancel comes from the vendored wry's fifth patch (`cancel_download_to`, a main-thread registry of live WKDownloads keyed by destination path) driven by `cancel_download`, which marks the item cancelled and unlinks the partial file (the X on in-flight rows is macOS-only); the total comes from the vendored wry's fourth patch (`last_download_expected_bytes`, the response's Content-Length read in the started callback's stack), `None` when the server sends no length or off macOS, in which case the chrome shows the indeterminate spinner instead of the determinate pie. Content-Length counts encoded bytes vs the poll's decoded ones, so the pie clamps and completion only ever comes from the finish event. Private-workspace and Peek downloads save but are flagged `private` and never recorded. Completed non-private ones persist in the `downloads` table (M0014); `open_download` / `reveal_download` validate the recorded path is still a regular file inside its recorded directory (ruling out symlink swaps), else resolve `false`. UI: an `overlay-downloads` popup and a full `about:downloads` page; ask-where (`download_ask_where`) reads settings through the `AppState.download_prefs` sync mirror, since the callback cannot await the state lock.

## Favicons

- Favicon resolution (`favicons.rs`) falls back past `<origin>/favicon.ico`: when that yields no usable image (Discord, Gemini, DeepSeek, most SPAs), a hand-rolled scanner reads the page's `<link rel="icon">` declarations directly, no HTML-parser dependency. The widget-dock `WidgetFavicon` path pre-warms through `prefetch_favicon` (in-memory + on-disk cache), rendering a letter tile when nothing resolves.

## Sidebar quick-launch widgets

- A global ordered set of shortcuts in four dock rows: social, AI, productivity, and user-added custom-URL sites (`UserSettings.sidebar_widgets`; curated catalog in `src/lib/widgets.ts`, customs via `WidgetKind::Custom`). A custom widget is editable in place from the settings chips and carries an optional `WidgetGroup` override chosen at add time, on edit, or by dragging its favicon onto another dock row (rows all render as drop targets mid-drag, empty ones included, so a misplaced custom can always be dragged back out). Curated widgets only reorder within their own row, enforced at the boundary. The drag is tracked on the window, and no widget moves in the DOM until the drop commits. The dock caps at 30vh and scrolls, so it creeps when the pointer rests near an edge, refuses to arm a drop on a row outside its visible port, and fades whichever edge has widgets past it. Every widget in a settings patch passes `Widget::validate` at the IPC boundary (http(s) URL with a host, bounded label), so a stored widget is always a plain web load; the settings UI normalizes a bare domain to https and mirrors the check inline. Clicking opens its widget panel (`widget_panel.rs`): a per-widget, per-window webview (`widget-panel-<window>-<id>`) floating above the tab webviews, sharing the calling window's workspace store (logins persist), proxy, UA, and `WKContentRuleList` filtering; no Tauri capability.
- Switching is a hide/show of loaded webviews, not a navigation, so it is instant and keeps in-page state. The pool is bounded by a count cap (`widget_panel_limit`, default 2, LRU-evicting, since each is a full page worth 100MB to ~2GB), an idle window (`widget_sleep_minutes`), and a memory cap (`widget_memory_cap_mb`, swept every 30s). A panel is not a tab: it dismisses on re-click, Escape, an outside chrome click, a tab-webview click, or an active-tab change. Dismissal hides rather than destroys (re-open keeps drafts/sockets) and suspends media (`setAllMediaPlaybackSuspended`); hard-destroyed on workspace switch and in private workspaces. Header bar (`overlay-widgetheader`) shows the live host with mute + cache-bypassing `reloadFromOrigin`. Resizing rides an invisible `overlay-widgetresize` strip; stacking is actively maintained tabs < panels < overlays (`promote_panels_to_front`). Links: a plain click on a cross-site `<a href>` (registrable domain differs from the panel's, the `popup_chrome::same_site` rule mirrored in `link_open::panel_page_script`; `download` anchors excluded) is intercepted at capture phase and posted to `wisOpenInTabFg`, which the focused window opens as a foreground tab (the panel then dismisses on the active-tab change; a private workspace destroys it); same-site clicks navigate the panel so SPA routing works; Cmd/middle-click rides the tab `link_open::page_script` for a background tab; `target=_blank`/`window.open` still go through `on_new_window`, so a same-site `_blank` link also opens a foreground tab. Windows bakes the shim and a link-only receiver (`win_dispatch::install_link_open_only`), Linux registers the two names on the panel's user content manager (`gtk_dispatch::install_link_open_only`); both are CI-compiled only.
- `UserSettings.widget_keep_loaded` (default on) is a control distinct from the count, idle, and memory caps above: with it off, a panel's webview is destroyed the moment it is dismissed or switched away, reclaiming its WebContent process, while logins still persist in the store.
- Destroying any remote-content webview goes through `webview_close::terminate_page` first: wry's macOS `Drop` deliberately leaks the `WKWebView`, so a bare `Webview::close` strands the page's WebContent process (multi-GB for heavy apps) invisible to the task manager. The `_close` SPI exits that process; applied on every widget/tab/peek destroy path, on secondary-window close (`terminate_window_pages`), and reachable from the frontend via the `close_tab_webview` command (tab labels only). Panel webview creation itself is serialized (`PANEL_CREATE_LOCK`): overlapping WebView2 creations can deadlock in the Win32 message pump while the runtime holds its web-context lock (rapid widget opens silently failing).
- Some widgets carry a theme-sensitive URL (`effectiveWidgetUrl` / `navigate_widget_panel`): Instagram's web dark mode is a `?theme=dark` query param, applied at open time and re-navigated on a live light/dark flip, tracked via a `data-mode` MutationObserver. Telegram is pinned to the lighter WebA client (`web.telegram.org/a/`); records that stored the old bare-origin catalog URL (heavy WebK) are rewritten at open time.

## Bookmarks

- Per-workspace, optional folders (`folder_id` NULL = unfiled), persisted in SQLite (`wis_storage::bookmarks`, never in `BrowserState`). A glyph opens `overlay-bookmarks`. The address-bar star bookmarks into the last-used folder and auto-pins while the quick-access row has room (`PIN_CAP` = 6); clicking again removes it. Disabled in private workspaces. Pinning is independent of folder membership (`pinned` / `pin_position`): a bookmark can be pinned and live in a folder. Every mutation broadcasts `bookmarks-changed`; surfaces refetch via `useBookmarkSync` and the popup optimistically patches its cache (`setQueryData`). Like every webview, overlays are built with `disable_drag_drop_handler()` so wry does not swallow in-page HTML5 DnD (see the webviews doc); a folder reorder uses a dedicated grip handle (a draggable toggle would swallow drops on it).
- HTML import/export (Settings > Bookmarks): the pure Netscape-format parser/serializer lives in `wis_core::netscape` (hand-rolled linear scanner; only http(s) hrefs kept, entities decoded, names clamped, file/count caps). Wis folders do not nest, so nested `<DL>` levels flatten into one `" / "`-joined folder name. `Storage::import_bookmarks` writes one transaction: folders reused by name or created, duplicate (folder, url, title) rows skipped, everything appended unpinned; the command (`import_bookmarks_html` / `export_bookmarks_html`) drives the `panels.rs` file dialogs and broadcasts `bookmarks-changed` once. Export writes unfiled entries then each folder as a flat level, carrying `created_at` as `ADD_DATE` so other browsers keep the dates; import parses `ADD_DATE` but drops it at the storage boundary (nothing in Wis reads creation dates). Pin state has no slot in the format and does not survive export.
- Browser import (Settings > Import): `wis-import` finds Chromium-family profiles (per-OS user-data dirs, Linux flatpak and snap included; profiles from `Local State`) and reads `Bookmarks` plus `AccountBookmarks` into a `wis_core::bookmark_tree`, which `flatten` names like the HTML import. The bar and mobile roots become folders and "Other bookmarks" stays unfiled. Opera's `custom_root` (user, unsorted, speed dial) maps to folders and its trash is skipped. Only regular files are read, and a file holding more JSON objects than the import caps allow is refused before parsing. The webview only sees opaque source ids, re-resolved against a fresh discovery. Storage and dedup are the HTML import's (`bookmarks::import_parsed`). History: `History` and its journals are copied into the app cache (`browser-import`) and the copy is opened query-only, in defensive mode with `trusted_schema` off and a 30-second query budget, then deleted. URLs over 8 KiB and over-long titles are cut inside SQLite, so oversized values never reach Wis's memory. Visible http(s) visits from the last 180 days (20k cap) go through `Storage::import_history`, which keeps the later visit, the higher count and an existing title, so a repeat import changes nothing. On Windows a running browser's lock surfaces as "quit X first". Firefox-family profiles (Firefox, Zen, LibreWolf; Linux XDG, snap and flatpak, Windows Store) come from `profiles.ini`, install defaults first; relative profile paths must stay inside the data dir and absolute ones need `IsRelative=0`. Bookmarks and history both come from a copy of `places.sqlite`: menu items sit at the top level, the toolbar, unfiled and mobile roots become folders, tags are skipped, and a folder loop or nesting past 32 levels cannot recurse further.

## Load-failure error pages

- A failed navigation surfaces a per-tab `load_error` (`wis_core::LoadError`: kind + native code + failing URL; transient, in-memory only like `loading`). `SplitPaneHost` treats a tab with `load_error` like a chrome URL: the native webview drops out of the DOM-derived layout (hidden but kept alive, so retry is a plain `tab_reload`) and `ChromePane` renders `NetErrorPage` in its place.
- macOS: the vendored wry patch adds `didFailProvisionalNavigation:` (upstream implements none), stashes the `NSError` code + domain in a thread-local, and re-uses `PageLoadEvent::Finished` to deliver it (a Failed variant would force vendoring tauri-runtime/tauri). The shell's `on_page_load` closure reads `wry::take_last_page_load_error()` synchronously. The failing URL comes from the error itself (`NSURLErrorFailingURLErrorKey`), since an in-page link that fails leaves the tab on the page it was clicked from; the tab's URL is synced to it, so the address bar, the error page and Try again all name the link. Tab state is the fallback when the error carries none. Clears on `Started`, sets on a failed `Finished`. Provisional failures only; user cancels (NSURLErrorCancelled) map to no error, and a policy interruption (code 102, the download conversion) reconciles the tab model instead (see Downloads).
- Windows: `load_failure::install` registers a second `add_NavigationCompleted` (wry's ignores the args) reading `IsSuccess`/`WebErrorStatus`. Linux: WebKitGTK `load-failed` / `load-failed-with-tls-errors` signals (kind is coarse: TLS is distinguished, everything else is a generic failure). Both report through `report()` into `Tab.load_error`; `OPERATION_CANCELED` / `NetworkError::Cancelled` show no error page. A crashed page process reloads the tab on every platform: wry's handler on macOS, WebView2 `ProcessFailed` (render process exited) on Windows, WebKitGTK `web-process-terminated` (crash or memory limit) on Linux. Windows/Linux are compile-verified on CI.

## History and cookies

- **Folder collapse and sleep**: a collapsed folder hides its tabs, so `with_active_tab` opens the folder a newly activated tab sits in. The reverse case is collapsing the folder the *current* tab is in: the force-sleep pass exempts the active tab, so it also re-runs when the active tab changes, and the tab is discarded the moment the user moves away.
- **Recently closed tabs** (`wis_storage::closed_tabs`, migration `M0019`): closing a tab records url, title, folder, slot and pinned state in its own table, capped at 25 by a prune on every write, so "reopen closed tab" and the palette's browsable list both survive a restart. Private (ephemeral) workspaces never record, and only `http(s)` pages do. **Clearing browsing history clears this too** (same workspace and time-range scoping), and deleting a single history row takes its closed-tab row with it. Deleting a workspace drops its rows. The live session blob (WebKit `interactionState`) captured at close is deliberately *not* stored, rather it stays in `AppState.closed_tab_sessions` keyed by the row id, and a reopen after a restart cold-loads the URL instead. The map is pruned to the surviving rows on every close and cleared when history is cleared. Reopening takes the row (a read plus delete), to prevent the same tab from reopening twice (`restore_closed_tab` walks backwards past entries whose workspace has since been deleted). A slot of `-1` means the tab's position was unknown, so a reopen appends.
- **Page zoom** (`wis_core::zoom`, whole percentages so settings keep their `Eq` and round-trip JSON exactly): zoom belongs to the *site*, not the tab. `UserSettings.default_zoom_percent` covers sites with no zoom of their own, `zoom_site_overrides` remembers the rest by normalised host, and a zoom keypress steps the site's percentage, stores it, and applies the factor. Zoom moves along a fixed ladder (20% to 500%, in tens to 200%, twenties to 300%, then hundreds) rather than by repeated multiplication. WebView2 clamps its own factor, so the topmost rungs may land short on Windows. Anything stored off-ladder is snapped, so hand-edited and older values still step. Reset returns the default *and* forgets the host. The whole read-step-write runs inside the state transition, under the browser lock. `commands/webview.rs` re-applies on every main-frame load start. A page with no host is zoomed without being remembered. `AppState.zoom` mirrors the settings for that main-thread read, the way `AppState.autoplay` does.
- **Autoplay policy** (`UserSettings.autoplay_policy`, default block audible, plus `autoplay_site_overrides` by host): macOS sets WebKit's per-page policy on every main-frame navigation through the vendored wry webpage-preferences hook (`autoplay.rs`, `WKWebpagePreferences` `_setAutoplayPolicy:` SPI guarded by `respondsToSelector:`; a change reaches a page on its next load). Linux flips `media-playback-requires-user-gesture` per webview at creation and when each main-frame load starts (block audible blocks all). Windows keeps WebView2's built-in rule.
- Per-workspace deduped history with search; dedupe keys on the fragment-stripped URL, so anchor jumps update one row. Native cookie/site-data clear via `WKHTTPCookieStore` + `removeDataOfTypes:modifiedSince:`. The clear-data dialog picks kinds (cookies, cache, storage map to `WKWebsiteDataType` subsets in `cookies.rs`. Windows maps the same kinds onto `COREWEBVIEW2_BROWSING_DATA_KINDS` and calls `ClearBrowsingData` or `ClearBrowsingDataInTimeRange`. An untitled page's title is the bare site name (`wis_core::tab::placeholder_title`), never the raw URL.
- Stay logged in across restarts (`cookies.rs`): WebKit keeps session cookies in memory only. A workspace's expiry-less cookies snapshot to `session_cookies` (after each load and on a 60s timer) and restore on the first tab each run, once per workspace via `AppState::restored_cookies`; empty snapshots never overwrite a saved one. Encrypted with ChaCha20-Poly1305 under a dedicated key (`session_key_load_or_create`, not Touch ID gated, so available at launch); if the key is unavailable nothing is persisted. Blast-radius bound: `created_at` stamped once, and a restored session auto-expires after `SESSION_COOKIE_TTL_DAYS` = 14, forcing re-auth; stale snapshots purged at launch. Gated on `persist_sessions`; never ephemeral.

## Site usage

- `usage.rs` ticks once a second and feeds a pure `wis_core::usage::UsageMeter`. The observed site is the focused pane's tab (`Workspace.active_tab_id`) of the focused Wis window (`AppState.focused_window`, from `WindowEvent::Focused`), grouped by `wis_core::site::registrable_domain`. Private workspaces, Wis pages and tabs showing an error page are not counted.
- The focused site is credited while input is recent (`idle.rs`: `CGEventSourceSecondsSinceLastEventType` on macOS, `GetLastInputInfo` on Windows) or while it is audible (`AppState.audible_tabs` minus muted tabs). Otherwise an audible site in any pane of a visible window is credited, and failing that the focused site's seconds are held: input commits them, and idle reaching `usage_idle_timeout_secs` drops them. Background tabs never count, so a day's total cannot exceed real time. Linux has no idle source, so focused time counts without a cutoff. On Windows the OS foreground window confirms focus, since a window's blur can go unreported while a child webview holds focus.
- The meter and its unstored credits live in `AppState.usage` (`UsageLedger`) and are written every 15 seconds and on exit (`Storage::add_usage`, table `site_usage`, keyed by local day, workspace and site) with a `usage-changed` event; a failed write keeps its credits. `clear_history` clears usage from the local hour its range starts, and deleting a workspace clears its usage; both also drop held and unstored credits, under the same lock as the flush so a write in flight cannot land after the clear, and emit `usage-changed`. Usage queries never go stale on their own, so that event is what refreshes an open panel or page. Turning tracking off drops held time.
- The Usage panel (`UsagePanel`) docks on the sidebar's side, opposite the assistant, sharing its shell (`kb-ai-panel`, `useDockWidth`). It reads `usage_summary(from, to)` over local dates across workspaces; `wis_core::usage::summarize` folds the hourly rows (`site_usage.hour`, M0021) into a total, sites busiest first, 24 hourly buckets and every day of the range. Bars and share fills use the theme's `--primary` ramp (light 400/500/600, dark 500/400/200), with the current hour or day in the emphasis step, over faint gridlines at two round durations labelled at the right edge; a readout line shows the busiest slot or the one under the pointer or focus.
- Weeks start on `week_start` (`wis_core::usage::WeekStart`): Monday, Sunday, or `auto`, which reads the region's first day from `Intl.Locale` week info (Monday when unavailable).
- `about:usage` (`UsagePage`) steps through weeks, never past the current one; changing the start day re-aligns a stepped-back week to the one holding its first day. It shows total, daily average (over days already started) and busiest day, then `UsageLine`: dots joined by a 2 px line over a 10% wash, days after today left blank, round duration gridlines (`durationTicks`, a low-opacity tint of the text colour), and a crosshair tooltip for the hovered or focused day that drops below the dot near the top. One query fetches the week and the 8 weeks ending with it together, so the two never mix while stepping weeks: `weekTotals` turns the latter into a "Last 8 weeks" chart (one "Week" axis title rather than dates, and a dotted average of the finished weeks since tracking began, `weeklyAverage`), and `weekChange` compares the viewed week with the one before over the weekdays that have started, so a running week is not set against a full one. The day chart's dotted line is the Daily average tile's value. Each chart sits in a `UsageChartCard` whose Chart/Table switch shows the same points as a table, in a fixed-height body. The panel's expand button opens it in place of a Wis page or in a new tab. Both charts share `useSlotCursor` (one tab stop, arrow keys, Home and End) and `useUsageClock` (minute tick, refetch on `usage-changed`).

## Canvases

- A canvas tab is a normal tab webview whose URL is `wis-canvas://localhost/?canvas=<id>`. `create_tab_webview` registers its label with its workspace (`canvas::register`) just before the webview is added and installs the macOS `wisCanvas` handler; `close_tab_webview` forgets it. Windows and Linux show the not-available toast (`platformSupport` `canvases`).
- `canvas::handle_request` serves the scheme only to registered canvas tabs: `/` is `canvas.html` (a second Vite entry, `src/canvas/`) and `/assets/*` the built files, under a CSP with no network, frames or forms. An asset that resolves to HTML is refused, since Tauri falls back to the chrome's `index.html`. In development the handler proxies the dev server instead.
- Canvas tabs stay on the scheme and web tabs never reach it (`canvas::navigation_allowed`, ahead of the app-launch handoff); `wis-canvas` is a blocked launch scheme, popups to it are denied, and `useOpenInTab` ignores canvas URLs.
- The page posts JSON strings (`lib/canvasChannel.ts`); the handler accepts only main-frame messages from a webview still on the scheme. One worker runs them in order from a bounded queue and replies by evaluating `window.__wisCanvas.reply(...)`. The workspace always comes from the registered tab, never the message.
- `CanvasMemory` (`canvas_store.rs`) holds documents saved since the last write, keyed by workspace and canvas, and private workspaces' canvases, which never reach the disk. Pending documents are written every two minutes, when a canvas tab closes, and in the exit hook (`Storage::save_canvas_docs`; a document for a deleted canvas is dropped). Caps: 64 pending canvases, 200 private canvases, 32 MiB of private documents, 8 MiB per document (`wis_core::canvas`).
- The document is the page's JSON (`lib/canvas.ts`): a version, the resting view and cards (id, position, width, Markdown). Rust stores it opaquely; `parseDoc` reads it back defensively. The page saves 0.5 s after a change and at once on `pagehide`.
- `CanvasSurface` renders cards with the assistant's Markdown component; pan (two-finger scroll, Space-drag or middle-drag), pinch (Safari `gesture*` events and ctrl+wheel) and drags write transforms on one `will-change` layer once per frame. Dragging empty canvas draws a selection box (`cardsTouching`); Shift or Cmd adds to the selection, and dragging a selected card moves them all (`moveCards`). Double-click opens a draft that becomes a card only once it has text. Delete, Cmd+A, Escape, Cmd+Z and Shift+Cmd+Z act on the canvas unless a field has focus. Below 35% zoom cards hide their content (`is-far`), which keeps 200 visible cards at 120 Hz. The zoom pill top right reads the scale and returns to 100%.
- Arrows (`CanvasDoc.edges`, `addEdge`, `removeEdge`) are drawn in one SVG behind the cards: each curves from the middle of one card's side to the middle of the facing side of the other (`edgeGeometry`, `curvedArrow`), its last control point leaning toward the source so the head turns with the cards' positions, and stops `ARROW_LENGTH` short so the head's tip lands on that middle; card heights come from a `ResizeObserver`, with a wide transparent stroke for clicking. Dragging a dot on a card's side and dropping on another card adds one (never twice, never to itself). While cards move, `paint` rewrites the paths of the arrows they touch. Removing a card removes its arrows, and `parseDoc` drops arrows whose cards are gone. Below 35% zoom the click strokes and arrowheads are dropped.
- Groups (`CanvasCard.group`, `groupCards`, `ungroupCards`) select and move as one: a click, Shift-click or selection box widens to whole groups (`expandToGroups`), and a dashed outline marks each group with a selected card (`groupsIn`), reshaping live while part of it moves. Holding Cmd picks single cards instead: Cmd-click, Cmd+Shift-click, Cmd-drag (that card alone) and Cmd box select. Groups do not nest: grouping cards picked out of a group moves them to the new one, and a lone card left behind counts as ungrouped. Cmd+G groups, Shift+Cmd+G ungroups and Alt+Cmd+G frames the selection, matched by `e.code` (Option changes `e.key`) and only while cards are selected, so Cmd+G otherwise stays find-next.
- Frames (`CanvasDoc.frames`) sit behind the arrows and cards, larger ones first, and let clicks through except on the title (a grip and the name), a grab band along each edge (wider below 35% zoom) and the corner handle. Dragging the title or an edge moves the frame, the cards whose centres are inside it (`cardsInFrame`, widened to whole groups) and the frames wholly inside it (`framesInside`), through the same per-frame `paint` as card drags (`moveFrames`). The corner resizes (`resizeFrame`, 160 by 120 at least), a double-click on the title renames, and Delete removes only the frame. Membership is positional, so a card dropped inside joins. Below 35% zoom titles grow so they stay readable.
- A right-click menu (`CanvasMenu`) offers New card, New HTML card, New frame, Group, Ungroup, Frame selection and Delete with their shortcuts (and Edit HTML on an HTML card); right-clicking a card, frame title or arrow selects it first.
- HTML cards (`kind: 'html'`, fixed `w` and `h`, resized from the corner) run their page in `<iframe sandbox="allow-scripts" src="/frame">`. WebKit gives `srcdoc`, `data:` and `blob:` frames the parent's CSP, which forbids inline scripts, so `canvas::handle_request` serves `/frame` itself (`canvas_frame.html`) under its own CSP: inline scripts and eval, no network, no frames, forms or base URL, and `sandbox allow-scripts` even when opened directly. Its bootstrap takes one message from `parent` holding the HTML and the canvas theme, writes it in place, adds a `color-scheme` meta, and relays Escape. The page's `frame-src` names that one URL, which also stops a card navigating anywhere else; the Rust navigation guard runs for subframes too, and `wisCanvas` refuses any frame but the main one. CSP does not cover WebRTC or `<link rel=preconnect|dns-prefetch>`, so `canvas_webview.rs` turns off `PeerConnectionEnabled`, `LinkPreconnect` and `LinkDNSPrefetchEnabled` for canvas tabs, and the bootstrap refuses to run a card if any of them is still on. Canvas tabs also skip the permissions gate and cosmetic filtering, whose page-world channels do not check the frame. Cards have an opaque origin, so no storage and no access to the page. At rest a shield takes the pointer, so cards drag, select and pan like any other; double-click makes one live (focus moves in), and a click outside or Escape (`isEscapeFrom`, only from that card's frame) hands keys back to the canvas. The `</>` button or Edit HTML opens the source; saving reloads the card.
- HTML cards share the canvas page's WebContent process, so only cards on or near the screen run (`useAwakeCards`, an `IntersectionObserver` on the viewport with a 10% margin; a card that leaves unloads after 1.5 s), and none run once the view settles below 35%. A paused card shows its page's `<title>` (`htmlTitle`). With 40 cards, panning stays at a 10 ms p95 whether they run or not; each running card costs about 4 MB (8 MB with an animated canvas), freed within seconds of pausing.
- A card that loops forever would freeze the canvas again every time it opens, so cards run only after Rust has noted a start (`useCardHealth`, the `pulse` request): the page then beats every 2 s and stops when no card runs or the page hides. `canvas_health::CardHealth` answers a start "safe" when that canvas's tab closed, or Wis quit, more than 5 s after its last beat while running, when another tab's run of it has gone 10 s silent, or when the same tab starts again without stopping; the canvas then opens with every card paused and a notice offering Run cards, so the culprit can be found and deleted. Stuck canvases are kept in `canvas-stuck.json` in the app data folder, so a relaunch opens them safe too. Hidden tabs (`wv.hide()` raises `visibilitychange`) stop and pause their cards.
- `CanvasApp` keeps an undo history of document changes (cards, arrows, groups, frames; `record`, `undo`, `redo`, 100 steps, reset per canvas); view changes are saved but not recorded, and undo keeps the current view.
- On macOS a canvas tab gets its own WebKit configuration (`canvas_webview.rs`): a fresh non-persistent store, so the workspace proxy only reaches that store, and WebKit's internal `PreferPageRenderingUpdatesNear60FPSEnabled` turned off so it renders at the display's rate. Canvas tabs skip the session-cookie restore. The page sets its address (`?canvas=`) before its title, and the title change syncs the tab's URL (`note_in_page_navigation` accepts canvas URLs, without history).
- Active state on the canvas is a 2px accent edge inside the element. Elements carry `--edge-off` at rest so the change fades (`canvas.css`).
- Pushed values: the accent follows the browser theme through `window.__wisSwipeAccent`, which Rust evaluates into every tab after each load and on theme change (`swipe_nav.rs`); the canvas theme (`UserSettings.canvas_theme`, Light or Dark; default Dark) arrives as `window.__wisCanvasTheme`, baked into canvas tabs at document start and re-evaluated on change (`canvas::push_theme`). The page turns both into setters (`lib/canvasPushed.ts`), so other readers such as the swipe indicator still see them.
- `CanvasSwitcher` is the name pill top left: click lists canvases (newest first; typing filters with the palette's `fuzzyMatch`, `matchCanvases`) under "New canvas"; double-click or the right-click menu renames (the new name, tidied as Rust tidies it, shows at once and reverts if Rust refuses), and the menu's two-step Delete removes the open canvas, opening the most recent remaining one or a new one. Switching writes the pending save first.

## Browser identity and default-browser handoff

- Remote webviews present a modern Safari-class UA by default (`wis_core::user_agent`), since WKWebView's default omits the `Version/.../Safari/...` tokens and sites flag it unsupported. Configurable in Settings, Compatibility: a default `UaProfile` plus per-host overrides (`ua_site_overrides`). Set at webview-build time on tab and Peek webviews; chrome/overlay untouched. The platform token follows the running OS (`UaPlatform::host` reads `std::env::consts::OS`; Mac strings locked byte-for-byte, `from_os` unit-tested from any host).
- Open in default browser (`external::open_in_external_browser`) hands the current `http(s)` page to the OS default (`open` / `xdg-open` / `start`), an exit hatch for pages embedded WebKit cannot fully handle (e.g. Widevine). Scheme-validated to `http(s)`; on macOS, if Wis is itself the default handler it falls back to Safari so the handoff cannot loop back.
