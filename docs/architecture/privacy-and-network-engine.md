# Privacy & Network Engine

This guide elaborates on WIS.md. If anything here conflicts, WIS.md wins.

`wis-network` is the privacy decision engine that sits between `wis-storage` and the Tauri shell. It owns no I/O policy of its own; it turns a workspace's `PrivacyMode` plus the compiled filter engine into a per-request verdict, and exposes that verdict through a loopback proxy the webviews are pointed at. The shell layers the page-side privacy features (cosmetic hiding, scriptlets, user scripts, the fraud warning) on top.

## The decision engine

- `RequestPolicy` (`crates/network/src/policy.rs:36`) is the pure core: it holds a `PrivacyMode`, an `Arc<TrackerBlocker>`, an `HttpsUpgrader`, per-site overrides (`Vec<PerSitePolicy>`), and an optional `UpstreamProxy`. `RequestPolicy::decide` (`policy.rs:81`) returns a `Decision` (`policy.rs:27`): `Allow`, `Rewrite { url }` (an HTTPS-First upgrade), or `Block { reason }` (the matched rule text or policy name). No network happens inside `decide`; it is a function of the request plus loaded rules, so it is unit-testable in isolation.
- `TrackerBlocker` (`blocker.rs`) wraps the `adblock` crate and parses EasyList/EasyPrivacy once. The compiled engine is memoized to disk as `engine-<hash>.bin` beside the filter-list cache, keyed by a hash of the input texts; a warm launch deserializes instead of re-parsing. The DAT format is self-versioned, so a crate upgrade or corruption falls back to a fresh parse rather than loading a stale engine. Both the startup build and the runtime EasyPrivacy refresh route through this cache.
- `DohResolver` / `StubResolver` (`resolver.rs`) implement the `Resolver` trait: DNS-over-HTTPS via `hickory-resolver`. `DohProvider` is the set of endpoints this build can honour (Cloudflare, Quad9, Google), each backed by a `hickory` preset carrying the bootstrap addresses needed to reach it without DNS. `UserSettings.doh_resolver` stores the chosen provider's URL and `doh_provider_for` maps it back; an unrecognised or unset value resolves through Cloudflare rather than failing, because the direct-connect path has no OS-DNS fallback and a dead resolver would kill every connection. `SwappableResolver` wraps the active resolver so proxies hold a handle rather than the resolver itself. Done such that changing the provider in settings takes effect on the next lookup instead of the next launch. The chrome's picker (`features/network/doh.ts`, `NetworkSection`) offers exactly the `DohProvider` set, and because a blocked endpoint would take browsing down with nothing else to show for it, a change is awaited and then probed with a real lookup, reporting the result on the row. The swap is compared by provider rather than by patch presence, so re-picking the active one keeps its warm cache and open connection. A workspace routed through Tor resolves at the exit and never asks the provider, which the row says when that is the case.
- `HttpsUpgrader` (`upgrader.rs`) enforces HTTPS-First: it produces the `Rewrite` target that `decide` returns for an eligible plaintext request.

## The per-workspace proxy

- Each workspace gets its own loopback HTTP proxy (`ProxyServer`, `crates/network/src/proxy/mod.rs:35`), built on hyper. It forwards plain HTTP, tunnels HTTPS via `CONNECT`, applies HTTPS-First redirects, and drops trackers, all by consulting the current `RequestPolicy` per request.
- Policy is **hot-swappable**. `ProxyServer` carries a `policy_tx: watch::Sender<Arc<RequestPolicy>>` (`mod.rs:39`) read per request, so a privacy-mode change or a filter-list rebuild pushes a new policy without rebinding the port (which would drop live connections). A separate `shutdown_tx: watch::Sender<bool>` (`mod.rs:37`) signals the accept loop; `Drop for ProxyServer` (`mod.rs:111`) fires it so tearing down the value stops the listener and its spawned tasks.
- The direct connect path (`proxy/connect.rs`) DoH-resolves the host, then dials **every** returned address in turn, each under a per-address connect timeout (and the lookup itself under a resolve timeout). An unreachable answer (for example an AAAA record on a network with no IPv6 route) falls through to the next address instead of stalling the `CONNECT` tunnel forever.
- An optional `upstream` (`proxy/upstream.rs`) routes through SOCKS5 or Tor instead of dialing directly. Settings offers the choice per workspace (Direct / Tor / SOCKS5, the Tor option only when the feature is compiled in), with the host and port typed for SOCKS5 and validated at the IPC boundary by `UpstreamProxy::validate` (a bare host and port; a scheme, credentials or path would silently become part of the hostname). `probe_upstream` confirms the proxy answers, speaks SOCKS5 and accepts the unauthenticated method the proxy uses, reported on the row. The switch fails closed: the upstream is resolved before it is recorded, so a Tor client that will not bootstrap refuses the change instead of leaving the workspace on its previous route while the chrome shows the new one, and a resolve failure later switches the workspace's proxy to refusing everything (`RequestPolicy::refusing_all`) rather than letting it serve on the old policy. It keeps its port, so open tabs reach a refusal rather than a dead port, and the next tab created in the workspace retries the route (`ensure_proxy_for`). Changing the route also severs connections already open (`ProxyServer::sever_open_connections` bumps a watch epoch the tunnels select on), including ones still dialing, which answer 502 at once. Plain-HTTP forwards take the same signals as tunnels (`proxy/signals.rs`), so a response still streaming also ends at a route or network change. Each request marks its receiver current before reading the route. A plain-HTTP response already streaming is not cut, which is narrow because HTTPS-First upgrades http in every mode but Permissive. The proxy's own hostname resolves through the same DoH resolver as everything else. A SOCKS5 upstream resolves its own DNS, so the DoH provider is not used for that workspace either.

## Idle teardown

- Proxies are lazy and per-workspace: `AppState::ensure_proxy_for` (`crates/shell/src-tauri/src/state.rs:448`) spawns one on the first webview creation for a workspace and is idempotent thereafter. A 60s sweep in `lib.rs` (near `crates/shell/src-tauri/src/lib.rs:408`) drops a workspace's `ProxyServer` once it has had no live tab webviews for `PROXY_IDLE_SECS` (10 minutes). The active workspace is exempt, since Peek and widget panels always attach to it and would otherwise race a teardown. Dropping the server frees its sockets and tasks; the next webview creation respawns it. Nothing else drops a live workspace's proxy: an open tab keeps the port it was built with, so a filter-list rebuild re-points each proxy at the new blocker in place (`refresh_all_proxy_policies`) rather than restarting it. On macOS a system wake also severs every proxy's open tunnels (`system/wake.rs`), since one that died during sleep would otherwise hang its page until a kernel timeout, and swaps a fresh DoH resolver into the shared `SwappableResolver`. The engine never sees a network change behind the loopback proxy, so a Network.framework path monitor does the same once the path is usable again with a different status, set of interfaces or sending address, a second after the burst of updates settles. The sending address is what a connected UDP socket reports, which sends nothing, kept to its /64 for IPv6 so a rotated privacy address is not a new network. Windows and Linux poll that address every two seconds and read a sleep from a tick that ran far too long on either clock. Both use `ProxyServer::network_changed`, which cuts the tunnels and starts any dial under way once more over the new network, since a CONNECT that has not answered 200 can redial and the engines would not retry a 502. A reload, plain or hard, first revives its workspace's proxy: `ProxyServer::revive` restarts the dials running for 3 s or more, and within two minutes of a wake or network change also ends the tunnels quiet for that long. The choice is made from a registry at the moment of the call (`proxy/live.rs`), so a busy transfer keeps going; outside that window quiet tunnels are left alone, since a WebSocket or a warm keep-alive is idle rather than dead. Outbound sockets carry TCP keepalive (30 s idle, 10 s probes) for connections that die without sleep, and a SOCKS5 connect (Tor included) gives up after 30 s.

## Tor

- `TorProxy` (`crates/network/src/tor.rs:21`) runs a built-in Tor client (`arti-client`) and exposes it as a loopback SOCKS5 endpoint (`TorProxy::port`, `tor.rs:73`). It is behind the `tor` cargo feature, which is **on by default**; build `--no-default-features` to omit it. The shell holds a single lazy `tor_proxy` on `AppState`; the sidebar/top-tabs VPN toggle flips a workspace's `UpstreamProxy` to `Tor` and reloads its tabs to re-route. The toggle icon lights only when connected and shows a connecting state.

## Lockdown Mode and fingerprinting protection

A workspace can run its pages in WebKit's Lockdown Mode (`Workspace.lockdown`, Settings > Network, macOS 14+; Windows and Linux hide the switch). It is the attack-surface half of Tor Browser's Safer level and is independent of the route and the privacy mode. WebKit only reads `WKWebpagePreferences.lockdownModeEnabled` from the configuration a webview is created with, and Tauri's `add_child` merely posts the creation to the main thread, so `hardening::mark` records the label's `Hardening` (or clears it) from a fresh read (`hardening::wanted`) just before each tab, Peek, widget panel and assistant page-reading creation, and the one wry configuration hook (`webkit_features::install_configuration_hook`) reads the mark and sets it on `defaultWebpagePreferences`. Marks for reused labels stay until that label's next creation sets or clears them. One-off assistant labels are forgotten at teardown. `set_workspace_lockdown` then rebuilds the workspace's web and `file:` tabs through the sleep path (`wis-rebuild-tabs`), audible ones included, with a tab still being created rebuilt once it exists (`useTabWebviews`), and closes the workspace's Peek and widget panels. Popped-out videos keep their mode until replaced, and canvas tabs are never locked down. Measured in a harness on the installed WebKit, it removes WebGL, WebRTC, WebAssembly, speech synthesis, gamepads, service workers, `mediaDevices` and notifications, and WebKit also drops the JIT.

The same marks carry WebKit's Advanced Tracking and Fingerprinting Protection (`_setNetworkConnectionIntegrityEnabled:`, SPI, macOS 13.3+, behind `respondsToSelector:`), on for every workspace whose privacy mode is not Permissive. Measured in a harness, it works through the workspace proxy and on `defaultWebpagePreferences`: canvas and audio readouts carry noise salted per page and site (`Page::noiseInjectionHashSaltForDomain`), so a site reads the same values on every reload in one tab but different ones in another tab, after the tab is reopened or woken, and on another site; `screen` reports the window's size; and cross-site link clicks lose `fbclid` and `gclid`. `set_workspace_privacy_mode` rebuilds the workspace as above when the change crosses Permissive privacy. A site whose panel switch is off gets `_setNetworkConnectionIntegrityEnabled:NO` on each navigation's preferences, which the harness showed overrides the default.

## Tracker blocking layers

Blocking is defense in depth across three layers, each catching what the others cannot:

- **Proxy-level** request blocking through `RequestPolicy::decide`, which drops tracker requests and applies HTTPS-First before they leave the machine.
  - **CNAME uncloaking** (`cloaking.rs`, `proxy/uncloak.rs`, `RequestPolicy::cloaking_alias`). On a direct route the CONNECT's dial resolves through `Uncloaking`, which takes the addresses and the CNAME chain from one cached hickory lookup (`resolve_with_aliases`), inside the dial's own redialling on network changes, and fails the host when an alias on another site is blocked with the host as its source (`blocks_alias`), so the `$third-party` rules EasyPrivacy names most cloaking vendors with apply (a `metrics.newsite.fr` behind `*.eulerian.net`). Every alias in the chain counts. Like uBO, it spares a host a list blocks and then excepts, and the pages being opened. Each workspace keeps the hosts its tabs, Peek and panels are opening (`Cloaking`, the 256 most recent), marked from the macOS main-frame hook, Windows' navigation handlers and the shell's own loads (new tabs, typed URLs, panel and guard navigations) so they land before WebKit preconnects; `uncloak::register` maps each webview to the workspace whose proxy it uses. The assistant's page reads are not registered, so a URL a model picks never spares a host. Closing a workspace's window clears its state in place (the live proxy holds the same object), and deleting the workspace drops it. Sites with blocking off in the site panel are spared by registrable domain, since a cloaked host is a subdomain of its site; a site panel change rebuilds the proxies' policies only when that set changes. Balanced and Strict privacy only, direct routes only (Tor and SOCKS resolve names themselves), and not on Linux, whose navigation handler also sees iframes, so a page could spare its own hosts by framing them. Refusals count in the site panel. A spared host stays spared for its workspace's next 256 page loads, and plain-HTTP requests are not uncloaked.
- **Engine-level** `WKContentRuleList` blocking (`protection/content_filter.rs`). Filter rules compile once to a `WKContentRuleList` spec; the `WKContentRuleListStore` persists compiled lists by identifier, and the identifier hashes the filter text (plus `RULES_VERSION`, bumped when the conversion changes), so a refreshed list misses naturally and a version's expensive compile runs once (not per tab or launch). Hashing the JSON never hit: the converter emits each rule's resource types in hash order, so every launch recompiled and restored tabs loaded before the list was attached. Startup prunes stale `wis-cb-*` store entries from older versions. A per-`PrivacyMode` compiled cache lives on `AppState.content_rules`. Strict privacy starts its list with a rule blocking every third-party script, then `ignore-previous-rules` exceptions that let a page run scripts from its owner's other domains (`site_entities.rs`: one rule per owned domain, the page matched by `if-domain`), and only then the filter lists; a list's own `@@` exceptions can lift the script block for what they name. Owners come from `crates/network/data/site_entities.txt`, Wis's own list (about 140 owners, no shared CDNs, customer hosting or ad and analytics domains), and `related_website_sets.txt`, regenerated from Google's Related Website Sets (Apache-2.0); sets sharing a domain merge. A site that is not listed and serves its scripts from another domain still needs the site panel's switch under Strict privacy.
- **Cosmetic** hiding of what the network layer leaves behind, covered next.

Per site, the padlock's panel can turn the in-page layers off (`UserSettings.site_protection_overrides`, keyed by `normalize_host`, mirrored in `AppState.site_protection` for main-thread reads). Changes made in a private workspace go to `AppState.site_protection_session` instead, in memory until quit, and win over saved ones. On macOS the per-navigation hook (`pages/preferences.rs`) sets `allowsContentJavaScript` on the page's `WKWebpagePreferences`, turns fingerprinting protection off when the site's switch is, and, with blocking off, `_setContentRuleListsEnabled:YES exceptions:` naming Wis's own lists, so an extension's declarativeNetRequest lists keep applying (`_contentBlockersEnabled` would skip those too). The hook runs for every wry webview, so non-http(s) pages and the dev chrome's origin always keep the defaults. Scriptlets follow the navigation's host and list-based element hiding follows the tab's top-level page, on every platform. The proxy keeps refusing listed servers: one proxy serves the whole workspace, a CONNECT carries no page, and WebKit sends plain http through it as CONNECT too. The panel also lists the site's other saved rules (`features/site/lib/siteRules.ts` matches each per-site map by its own key: frame origin for camera and microphone, raw host for open-in-app and hidden elements, normalised host for the rest) and forgets one by patching its map; Settings > Privacy > Site protection lists the hosts with a switch off.

The panel's count of what was blocked (`protection/page_blocks.rs`, macOS) comes from two places, since a rule-list block never reaches the network and a proxy refusal is invisible to WebKit's rule lists. Wry's navigation delegate passes each `blockedLoad` action on to a hook, which keeps those from lists named `wis-cb-*` and finds the tab through the webview's `accessibilityIdentifier`. Every tab webview also gets one shared `_resourceLoadDelegate`; a failed load counts when `TrackerBlocker::blocks_tunnel` refuses its host, the same `tunnel_url` judgement the CONNECT handler makes, so network errors are left out. WebKit sends resource-load messages (three per load) only to webviews with that delegate, which is why Peek and widget panels go without; measured on 600 images, the app process spent about 56 ms of CPU against 25 ms without it, with no change in load time. Tallies are capped at 64 servers per page, dropped when a page commits, and dropped with the delegate detached in `terminate_page` when a tab closes. Two limits: a refusal from the network process can finish after the next page commits and count there, and a page restored from the back/forward cache starts from zero.

## Cosmetic filtering, element picker, zapper

- Cosmetic filtering (`crates/shell/src-tauri/src/protection/cosmetic.rs`) hides empty ad slots, placeholders, and overlay nags that network blocking cannot remove. A document-end user script collects the page's classes/ids (initial scan plus mutation-batched deltas, capped per message) and posts them with the URL to the narrow `wisCosmetic` handler. Rust answers from the adblock engine and evaluates two style slots into the sender's frame: a `host` slot (host rules plus zapped selectors) the page **replaces** so it can be re-asserted cheaply, and a `generic` slot (`cosmetic_generic_css`) the page **appends**, honoring per-host exceptions and `generichide`.
- Host rules include **procedural selectors expressible in plain CSS**, chiefly `:has(...)` (WebKit-native), so containers like sponsored feed cards are caught where class/id hiding misses them; JS-only operators (`:has-text`, `:upward`) are dropped. `build_cosmetic_apply` (`protection/cosmetic.rs:185`) builds the CSS shared across platforms. Cosmetic filtering is skipped for Permissive workspaces.
- On **SPA navigation** (History API pushState/replaceState/popstate) the injected script re-asserts the host slot on real URL changes (debounced), so host and zapper rules survive a framework that clears the injected style, without re-scanning every class.
- **Element picker / zapper** (Cmd+Shift+X, or View -> Hide Element): an on-demand overlay highlights the element under the cursor and, on click, computes a stable-ish selector (id, else tag plus stable classes, else an `:nth-of-type` path), hides it locally, and posts it to `wisZap`. Rust appends it to `UserSettings.user_cosmetic_rules` keyed by exact host; a sync read-cache on `AppState` lets the cosmetic handler re-apply per-host rules on every future load. Managed in Settings -> Privacy -> Filter lists (Hidden elements list). The zapped host is read from the webview URL, never from page data.

## Scriptlets and user scripts

- **Scriptlets**: uBO's scriptlet library, as Ghostery's adblocker publishes it on GitHub (`ubo-scriptlets.json`, 7-day TTL), is converted to the engine's resources (`scriptlet_library.rs`: `.fn` helpers become `fn/javascript` dependencies, uBO's redirect resources are dropped since nothing can redirect) and loaded with `load_resources`, expanding `+js(...)` rules into injectable JS. Wis used to fetch Brave's `dist/resources.json`, which holds only Brave's own extras, so every uBO rule was inert. Scriptlets uBO marks as needing trust, and any named `trusted-`, carry a permission bit (clicking elements, setting cookies and storage, faking responses). Only uBO's two default lists, `filters.txt` and `quick-fixes.txt` (`wis_core::privacy::trusted_lists`), are parsed with it: narrower than uBO, which trusts all its own lists. The engine cache key covers which lists are trusted. A library with no scriptlets, a name used twice or a missing helper is refused whole. `scriptlets_for_page` wraps a page's scriptlets in one function that defines the `scriptletGlobals` binding uBO's helpers read and keeps the scriptlets' functions out of the page's reach. All run in the page world, including the ones uBO runs isolated. Each tab webview's `on_navigation` hook (inside WebKit's decide-policy, before page scripts) swaps a marker-prefixed document-start user script with `scriptlets_for_page(url)` for the upcoming main-frame document. The swap removes only the marked scripts (`_removeUserScript:`). It never removes everything and re-adds the rest: `removeAllUserScripts` leaves web extensions' scripts in place, so re-adding them doubled an extension's scripts on every navigation. Without the SPI, the fallback re-adds only the scripts that were actually removed. The first URL is seeded at webview creation, so a direct fresh-tab load does not miss its scriptlets before the first `on_navigation`. This is what makes YouTube ad blocking work: `json-prune`-style scriptlets strip ad entries from player responses.
- **User scripts** (`wis_core::extensions::userscript`, `UserSettings.userscripts`): Tampermonkey-style scripts imported from a `.user.js` file (`import_userscript`), each parsed for its `==UserScript==` metadata (`@name`/`@match`/`@include`/`@exclude`/`@run-at`). Matching is glob-based (`Userscript::matches_url`, `crates/core/src/extensions/userscript.rs:110`, a pragmatic stand-in for Chrome match patterns). Injection rides the same per-navigation `swap_scriptlets` path (`protection/cosmetic.rs:35`) as adblock scriptlets, gated to non-Permissive workspaces via a sync `AppState.userscripts` cache: document-start scripts bundle after the adblock scriptlets, document-end/idle scripts inject as a separate end script, both under a shared `/*wis-inject` marker the swap strips. Scripts run in the **page world with no GM_* APIs** (DOM/CSS tweaks and self-contained logic only), wrapped in try/catch IIFEs. Toggled/removed in Settings -> Privacy -> User scripts.
- The scriptlet/user-script swap is macOS-only for now: it needs WebView2's `AddScriptToExecuteOnDocumentCreated` document-start timing. Proxy-level network blocking is unaffected on other platforms.

## Filter lists and subscriptions

- **EasyPrivacy** ships bundled as a fallback (`filter_lists/bundled.rs`) with a background `fetch` of a fresh copy (`filter_lists/fetch.rs`), cache-staleness gated.
- **EasyList** feeds the engine (`refresh_easylist`, 24h TTL, engine cache keyed over all texts) but is deliberately kept out of the `WKContentRuleList` compiler, whose rule cap it would exceed. The engine gains EasyList's cosmetic rules plus proxy-level ad blocking.
- **User filter-list subscriptions** (`UserSettings.filter_subscriptions`, https-only, defaulting to uBO filters plus quick-fixes which carry the YouTube rules): fetched/cached per URL hash (`sub-<hash>.txt`), engine-only like EasyList. Managed in Settings -> Privacy -> Filter lists (built-in rows plus add/remove; adds trigger a fetch and rebuild). `refresh_filter_lists` force-refreshes every source, rebuilds the engine, and re-attaches the `WKContentRuleList` rules to live tabs, reporting each step (`wis-filter-refresh-progress`, one per source and one for applying) to the progress bar under Settings' "Refresh now" row.
- **Directives** (`filter_lists/directives.rs`): adblock-rust reads `!#if` and `!#include` as comments, so every list is preprocessed when fetched. `!#if` follows uBO's preparser for a desktop WebKit browser that is neither uBO Lite nor able to filter HTML: of uBO's tokens only `ext_ublock` holds, `cap_` tokens do not, a condition it cannot read keeps its branch (an unknown first token reads as JavaScript's `undefined`, as in uBO), and `&&`/`||` read left to right. `env_safari` branches are rewrites for WebKit's restricted content-blocker regexes, which the engine does not need. Includes in kept branches are resolved against the parent's directory and must stay inside it on the same origin (uBO only refuses `..`, which `%2e%2e` slips past); nested ones are followed too, each list once, at most 32 lists, 16 MiB each, 64 MiB together and two minutes in all, over https only. Like uBO, an include is refused only when it is a web page, and one failure fails the refresh: the previous copy stays cached, though it is no longer loaded once it is over a day old. The assembled text is cached under the parent's URL, so included lists share its trust. uBO's `filters.txt` has ten includes (filters-2020 to 2026, general, link shorteners, and mobile, which is skipped): 10.8k lines alone, 41.4k assembled, about 4 MB more. The Fanboy lists include their uBO-specific rules the same way.
- **Cookie notices and annoyances** (`wis_core::privacy::notice_lists`): two switches above the list. `block_cookie_notices` (on by default, existing profiles included) subscribes the EasyList Cookie List, and `block_annoyances` Fanboy's Annoyance list, which contains the cookie list and replaces it (`UserSettings::notice_list`). In other words, turning annoyances on turns cookie notices on, and vice versa. `subscribed_lists` adds it to what gets fetched and `filter_engine::Subscriptions` to the engine, and its network rules alone (`wis_network::content_filter::network_rules`, hiding and scriptlet rules dropped) compile into a `WKContentRuleList` of their own (`wis-cb-notices-<hash>`, about 2k rules for cookies and 4k for annoyances) attached beside the mode's tracker list in Strict and Balanced. It is separate because WebKit applies a list's `ignore-previous-rules` only within that list: merged, the list's unbreak exceptions would lift Strict's third-party script block and EasyPrivacy's rules, and every switch change would recompile EasyPrivacy. A switch change fetches the new list unless cached and rebuilds in the background (`apply_notice_list`). Rebuilds run one at a time on a blocking thread (`filter_engine::build`), and re-attaching swaps only Wis's lists (`replace_rule_lists`; WebKit's `removeAllContentRuleLists` spares extensions' lists). A compile that finishes after a later rebuild replaced its list is dropped rather than attached. The launch-time refresh re-attaches too, so restored tabs pick up a list fetched after they opened. Banners are hidden, never answered. A cached engine measured 3 MB more with the cookie list and 6 MB more with annoyances. uBO's own cookie list is left out.

## Clean links

`protection/clean_links.rs` takes tracking parameters off links as they are followed, using `wis_core::clean_followed_link`: the narrow name table behind "Copy clean link", except that subscriber ids stay on pages whose path names an unsubscribe, opt-out, preference, subscription or email web view page. Destinations whose site has blocking off are skipped. On macOS, wry's main-frame navigation hook sees each main-frame decision with its `WKNavigationType` and method: a link-activated GET whose URL would change is cancelled and the tab, found by its `accessibilityIdentifier`, navigates to the clean URL on the next event-loop turn. Server redirects keep the type of the click that set them off, so a link shim's `fbclid` is caught; Wis's own re-navigation is type "other", so it cannot loop, and typed loads, `location` changes, reloads and back/forward pass untouched. A jump within the page (same URL but for the fragment) and a download are never cancelled. The re-navigation sends no Referer and `Sec-Fetch-Site: none`. The cancelled navigation's "frame load interrupted" failure is skipped while the webview is loading its replacement (`superseded` in `commands/webview.rs`), so the tab never shows the pending URL with the old title. New-tab paths (`link_open::emit`, new-window requests from tabs and widget panels), Peek, the page menu (`clean_followed_link`), the navigation guard's carry-out and links from other apps (`default_browser::handle_external_urls`) clean on every platform. Windows and Linux same-tab clicks are not covered yet.

## Fraudulent website warning

- `platform/webview_prefs.rs` enables WebKit's `fraudulentWebsiteWarningEnabled` (Apple-proxied Safe Browsing, off by default in WKWebView) on every remote webview (tabs, Peek, widget panels), showing a full-page warning before a suspected phishing/malware site. It complements `wis_core::navigation::link_safety`'s structural heuristics with a real threat database. A Settings -> Privacy toggle (default on, since the check performs network lookups) re-applies to all live remote webviews without reloads. Local chrome/overlay webviews are never touched.

## Global Privacy Control

- `UserSettings.global_privacy_control` (default on) drives two halves. The proxy stamps `Sec-GPC: 1` on every request it forwards itself (`proxy/upstream.rs`, read from `RequestPolicy::global_privacy_control`). `protection/gpc.rs` defines `navigator.globalPrivacyControl` in every frame of every remote webview (tabs, Peek, widget panels) at document start. A settings change re-points every running proxy (`AppState::refresh_all_proxy_policies`) and, on every live remote webview, flips the top frame of the current document through `window.__wisGpcSet` and installs one more document-start all-frames script that flips every later document. Flip scripts accumulate one per toggle per webview, the last one winning; loaded iframes follow on their next navigation.
