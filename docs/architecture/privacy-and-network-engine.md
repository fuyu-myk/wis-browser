# Privacy & Network Engine

This guide elaborates on WIS.md. If anything here conflicts, WIS.md wins.

`wis-network` is the privacy decision engine that sits between `wis-storage` and the Tauri shell. It owns no I/O policy of its own; it turns a workspace's `PrivacyMode` plus the compiled filter engine into a per-request verdict, and exposes that verdict through a loopback proxy the webviews are pointed at. The shell layers the page-side privacy features (cosmetic hiding, scriptlets, user scripts, the fraud warning) on top.

## The decision engine

- `RequestPolicy` (`crates/network/src/policy.rs:36`) is the pure core: it holds a `PrivacyMode`, an `Arc<TrackerBlocker>`, an `HttpsUpgrader`, per-site overrides (`Vec<PerSitePolicy>`), and an optional `UpstreamProxy`. `RequestPolicy::decide` (`policy.rs:81`) returns a `Decision` (`policy.rs:27`): `Allow`, `Rewrite { url }` (an HTTPS-First upgrade), or `Block { reason }` (the matched rule text or policy name). No network happens inside `decide`; it is a function of the request plus loaded rules, so it is unit-testable in isolation.
- `TrackerBlocker` (`blocker.rs`) wraps the `adblock` crate and parses EasyList/EasyPrivacy once. The compiled engine is memoized to disk as `engine-<hash>.bin` beside the filter-list cache, keyed by a hash of the input texts; a warm launch deserializes instead of re-parsing. The DAT format is self-versioned, so a crate upgrade or corruption falls back to a fresh parse rather than loading a stale engine. Both the startup build and the runtime EasyPrivacy refresh route through this cache.
- `DohResolver` / `StubResolver` (`resolver.rs`) implement the `Resolver` trait: DNS-over-HTTPS via `hickory-resolver`. `DohProvider` is the set of endpoints this build can honour (Cloudflare, Quad9, Google), each backed by a `hickory` preset carrying the bootstrap addresses needed to reach it without DNS. `UserSettings.doh_resolver` stores the chosen provider's URL and `doh_provider_for` maps it back; an unrecognised or unset value resolves through Cloudflare rather than failing, because the direct-connect path has no OS-DNS fallback and a dead resolver would kill every connection. `SwappableResolver` wraps the active resolver so proxies hold a handle rather than the resolver itself. Done such that changing the provider in settings takes effect on the next lookup instead of the next launch. The chrome's picker (`lib/doh.ts`, `NetworkSection`) offers exactly the `DohProvider` set, and because a blocked endpoint would take browsing down with nothing else to show for it, a change is awaited and then probed with a real lookup, reporting the result on the row. The swap is compared by provider rather than by patch presence, so re-picking the active one keeps its warm cache and open connection. A workspace routed through Tor resolves at the exit and never asks the provider, which the row says when that is the case.
- `HttpsUpgrader` (`upgrader.rs`) enforces HTTPS-First: it produces the `Rewrite` target that `decide` returns for an eligible plaintext request.

## The per-workspace proxy

- Each workspace gets its own loopback HTTP proxy (`ProxyServer`, `crates/network/src/proxy/mod.rs:35`), built on hyper. It forwards plain HTTP, tunnels HTTPS via `CONNECT`, applies HTTPS-First redirects, and drops trackers, all by consulting the current `RequestPolicy` per request.
- Policy is **hot-swappable**. `ProxyServer` carries a `policy_tx: watch::Sender<Arc<RequestPolicy>>` (`mod.rs:39`) read per request, so a privacy-mode change or a filter-list rebuild pushes a new policy without rebinding the port (which would drop live connections). A separate `shutdown_tx: watch::Sender<bool>` (`mod.rs:37`) signals the accept loop; `Drop for ProxyServer` (`mod.rs:111`) fires it so tearing down the value stops the listener and its spawned tasks.
- The direct connect path (`proxy/connect.rs`) DoH-resolves the host, then dials **every** returned address in turn, each under a per-address connect timeout (and the lookup itself under a resolve timeout). An unreachable answer (for example an AAAA record on a network with no IPv6 route) falls through to the next address instead of stalling the `CONNECT` tunnel forever.
- An optional `upstream` (`proxy/upstream.rs`) routes through SOCKS5 or Tor instead of dialing directly. Settings offers the choice per workspace (Direct / Tor / SOCKS5, the Tor option only when the feature is compiled in), with the host and port typed for SOCKS5 and validated at the IPC boundary by `UpstreamProxy::validate` (a bare host and port; a scheme, credentials or path would silently become part of the hostname). `probe_upstream` confirms the proxy answers, speaks SOCKS5 and accepts the unauthenticated method the proxy uses, reported on the row. The switch fails closed: the upstream is resolved before it is recorded, so a Tor client that will not bootstrap refuses the change instead of leaving the workspace on its previous route while the chrome shows the new one, and a resolve failure later switches the workspace's proxy to refusing everything (`RequestPolicy::refusing_all`) rather than letting it serve on the old policy. It keeps its port, so open tabs reach a refusal rather than a dead port, and the next tab created in the workspace retries the route (`ensure_proxy_for`). Changing the route also severs connections already open (`ProxyServer::sever_open_connections` bumps a watch epoch the tunnels select on), including ones still dialing, which answer 502 at once. Plain-HTTP forwards take the same signals as tunnels (`proxy/signals.rs`), so a response still streaming also ends at a route or network change. Each request marks its receiver current before reading the route. A plain-HTTP response already streaming is not cut, which is narrow because HTTPS-First upgrades http in every mode but Permissive. The proxy's own hostname resolves through the same DoH resolver as everything else. A SOCKS5 upstream resolves its own DNS, so the DoH provider is not used for that workspace either.

## Idle teardown

- Proxies are lazy and per-workspace: `AppState::ensure_proxy_for` (`crates/shell/src-tauri/src/state.rs:448`) spawns one on the first webview creation for a workspace and is idempotent thereafter. A 60s sweep in `lib.rs` (near `crates/shell/src-tauri/src/lib.rs:408`) drops a workspace's `ProxyServer` once it has had no live tab webviews for `PROXY_IDLE_SECS` (10 minutes). The active workspace is exempt, since Peek and widget panels always attach to it and would otherwise race a teardown. Dropping the server frees its sockets and tasks; the next webview creation respawns it. Nothing else drops a live workspace's proxy: an open tab keeps the port it was built with, so a filter-list rebuild re-points each proxy at the new blocker in place (`refresh_all_proxy_policies`) rather than restarting it. On macOS a system wake also severs every proxy's open tunnels (`wake.rs`), since one that died during sleep would otherwise hang its page until a kernel timeout, and swaps a fresh DoH resolver into the shared `SwappableResolver`. The engine never sees a network change behind the loopback proxy, so a Network.framework path monitor does the same once the path is usable again with a different status, set of interfaces or sending address, a second after the burst of updates settles. The sending address is what a connected UDP socket reports, which sends nothing, kept to its /64 for IPv6 so a rotated privacy address is not a new network. Windows and Linux poll that address every two seconds and read a sleep from a tick that ran far too long on either clock. Both use `ProxyServer::network_changed`, which cuts the tunnels and starts any dial under way once more over the new network, since a CONNECT that has not answered 200 can redial and the engines would not retry a 502. A reload, plain or hard, first revives its workspace's proxy: `ProxyServer::revive` restarts the dials running for 3 s or more, and within two minutes of a wake or network change also ends the tunnels quiet for that long. The choice is made from a registry at the moment of the call (`proxy/live.rs`), so a busy transfer keeps going; outside that window quiet tunnels are left alone, since a WebSocket or a warm keep-alive is idle rather than dead. Outbound sockets carry TCP keepalive (30 s idle, 10 s probes) for connections that die without sleep, and a SOCKS5 connect (Tor included) gives up after 30 s.

## Tor

- `TorProxy` (`crates/network/src/tor.rs:21`) runs a built-in Tor client (`arti-client`) and exposes it as a loopback SOCKS5 endpoint (`TorProxy::port`, `tor.rs:73`). It is behind the `tor` cargo feature, which is **on by default**; build `--no-default-features` to omit it. The shell holds a single lazy `tor_proxy` on `AppState`; the sidebar/top-tabs VPN toggle flips a workspace's `UpstreamProxy` to `Tor` and reloads its tabs to re-route. The toggle icon lights only when connected and shows a connecting state.

## Tracker blocking layers

Blocking is defense in depth across three layers, each catching what the others cannot:

- **Proxy-level** request blocking through `RequestPolicy::decide`, which drops tracker requests and applies HTTPS-First before they leave the machine.
- **Engine-level** `WKContentRuleList` blocking (`content_filter.rs`). Filter rules compile once to a `WKContentRuleList` spec; the `WKContentRuleListStore` persists compiled lists by identifier, and the identifier hashes the filter text (plus `RULES_VERSION`, bumped when the conversion changes), so a refreshed list misses naturally and a version's expensive compile runs once (not per tab or launch). Hashing the JSON never hit: the converter emits each rule's resource types in hash order, so every launch recompiled and restored tabs loaded before the list was attached. Startup prunes stale `wis-cb-*` store entries from older versions. A per-`PrivacyMode` compiled cache lives on `AppState.content_rules`.
- **Cosmetic** hiding of what the network layer leaves behind, covered next.

Per site, the padlock's panel can turn the in-page layers off (`UserSettings.site_protection_overrides`, keyed by `normalize_host`, mirrored in `AppState.site_protection` for main-thread reads). Changes made in a private workspace go to `AppState.site_protection_session` instead, in memory until quit, and win over saved ones. On macOS the per-navigation hook (`page_preferences.rs`) sets `allowsContentJavaScript` on the page's `WKWebpagePreferences` and, with blocking off, `_setContentRuleListsEnabled:YES exceptions:` naming Wis's own lists, so an extension's declarativeNetRequest lists keep applying (`_contentBlockersEnabled` would skip those too). The hook runs for every wry webview, so non-http(s) pages and the dev chrome's origin always keep the defaults. Scriptlets follow the navigation's host and list-based element hiding follows the tab's top-level page, on every platform. The proxy keeps refusing listed servers: one proxy serves the whole workspace, a CONNECT carries no page, and WebKit sends plain http through it as CONNECT too. The panel also lists the site's other saved rules (`lib/siteRules.ts` matches each per-site map by its own key: frame origin for camera and microphone, raw host for open-in-app and hidden elements, normalised host for the rest) and forgets one by patching its map; Settings > Privacy > Site protection lists the hosts with a switch off.

The panel's count of what was blocked (`page_blocks.rs`, macOS) comes from two places, since a rule-list block never reaches the network and a proxy refusal is invisible to WebKit's rule lists. Wry's navigation delegate passes each `blockedLoad` action on to a hook, which keeps those from lists named `wis-cb-*` and finds the tab through the webview's `accessibilityIdentifier`. Every tab webview also gets one shared `_resourceLoadDelegate`; a failed load counts when `TrackerBlocker::blocks_tunnel` refuses its host, the same `tunnel_url` judgement the CONNECT handler makes, so network errors are left out. WebKit sends resource-load messages (three per load) only to webviews with that delegate, which is why Peek and widget panels go without; measured on 600 images, the app process spent about 56 ms of CPU against 25 ms without it, with no change in load time. Tallies are capped at 64 servers per page, dropped when a page commits, and dropped with the delegate detached in `terminate_page` when a tab closes. Two limits: a refusal from the network process can finish after the next page commits and count there, and a page restored from the back/forward cache starts from zero.

## Cosmetic filtering, element picker, zapper

- Cosmetic filtering (`crates/shell/src-tauri/src/cosmetic.rs`) hides empty ad slots, placeholders, and overlay nags that network blocking cannot remove. A document-end user script collects the page's classes/ids (initial scan plus mutation-batched deltas, capped per message) and posts them with the URL to the narrow `wisCosmetic` handler. Rust answers from the adblock engine and evaluates two style slots into the sender's frame: a `host` slot (host rules plus zapped selectors) the page **replaces** so it can be re-asserted cheaply, and a `generic` slot (`cosmetic_generic_css`) the page **appends**, honoring per-host exceptions and `generichide`.
- Host rules include **procedural selectors expressible in plain CSS**, chiefly `:has(...)` (WebKit-native), so containers like sponsored feed cards are caught where class/id hiding misses them; JS-only operators (`:has-text`, `:upward`) are dropped. `build_cosmetic_apply` (`cosmetic.rs:185`) builds the CSS shared across platforms. Cosmetic filtering is skipped for Permissive workspaces.
- On **SPA navigation** (History API pushState/replaceState/popstate) the injected script re-asserts the host slot on real URL changes (debounced), so host and zapper rules survive a framework that clears the injected style, without re-scanning every class.
- **Element picker / zapper** (Cmd+Shift+X, or View -> Hide Element): an on-demand overlay highlights the element under the cursor and, on click, computes a stable-ish selector (id, else tag plus stable classes, else an `:nth-of-type` path), hides it locally, and posts it to `wisZap`. Rust appends it to `UserSettings.user_cosmetic_rules` keyed by exact host; a sync read-cache on `AppState` lets the cosmetic handler re-apply per-host rules on every future load. Managed in Settings -> Privacy -> Filter lists (Hidden elements list). The zapped host is read from the webview URL, never from page data.

## Scriptlets and user scripts

- **Scriptlets**: Brave's prebuilt uBO resource library (`resources.json`, 7-day TTL) loads into the engine (`load_resources`), expanding `+js(...)` rules into injectable JS. Each tab webview's `on_navigation` hook (inside WebKit's decide-policy, before page scripts) swaps a marker-prefixed document-start user script with `scriptlets_for_page(url)` for the upcoming main-frame document. The swap removes only the marked scripts (`_removeUserScript:`). It never removes everything and re-adds the rest: `removeAllUserScripts` leaves web extensions' scripts in place, so re-adding them doubled an extension's scripts on every navigation. Without the SPI, the fallback re-adds only the scripts that were actually removed. The first URL is seeded at webview creation, so a direct fresh-tab load does not miss its scriptlets before the first `on_navigation`. This is what makes YouTube ad blocking work: `json-prune`-style scriptlets strip ad entries from player responses.
- **User scripts** (`wis_core::userscript`, `UserSettings.userscripts`): Tampermonkey-style scripts imported from a `.user.js` file (`import_userscript`), each parsed for its `==UserScript==` metadata (`@name`/`@match`/`@include`/`@exclude`/`@run-at`). Matching is glob-based (`Userscript::matches_url`, `crates/core/src/userscript.rs:110`, a pragmatic stand-in for Chrome match patterns). Injection rides the same per-navigation `swap_scriptlets` path (`cosmetic.rs:35`) as adblock scriptlets, gated to non-Permissive workspaces via a sync `AppState.userscripts` cache: document-start scripts bundle after the adblock scriptlets, document-end/idle scripts inject as a separate end script, both under a shared `/*wis-inject` marker the swap strips. Scripts run in the **page world with no GM_* APIs** (DOM/CSS tweaks and self-contained logic only), wrapped in try/catch IIFEs. Toggled/removed in Settings -> Privacy -> User scripts.
- The scriptlet/user-script swap is macOS-only for now: it needs WebView2's `AddScriptToExecuteOnDocumentCreated` document-start timing. Proxy-level network blocking is unaffected on other platforms.

## Filter lists and subscriptions

- **EasyPrivacy** ships bundled as a fallback (`filter_lists/bundled.rs`) with a background `fetch` of a fresh copy (`filter_lists/fetch.rs`), cache-staleness gated.
- **EasyList** feeds the engine (`refresh_easylist`, 24h TTL, engine cache keyed over all texts) but is deliberately kept out of the `WKContentRuleList` compiler, whose rule cap it would exceed. The engine gains EasyList's cosmetic rules plus proxy-level ad blocking.
- **User filter-list subscriptions** (`UserSettings.filter_subscriptions`, https-only, defaulting to uBO filters plus quick-fixes which carry the YouTube rules): fetched/cached per URL hash (`sub-<hash>.txt`), engine-only like EasyList. Managed in Settings -> Privacy -> Filter lists (built-in rows plus add/remove; adds trigger a fetch and rebuild). `refresh_filter_lists` force-refreshes every source, rebuilds the engine, and re-attaches the `WKContentRuleList` rules to live tabs.

## Clean links

`clean_links.rs` takes tracking parameters off links as they are followed, using `wis_core::clean_followed_link`: the narrow name table behind "Copy clean link", except that subscriber ids stay on pages whose path names an unsubscribe, opt-out, preference, subscription or email web view page. Destinations whose site has blocking off are skipped. On macOS, wry's main-frame navigation hook sees each main-frame decision with its `WKNavigationType` and method: a link-activated GET whose URL would change is cancelled and the tab, found by its `accessibilityIdentifier`, navigates to the clean URL on the next event-loop turn. Server redirects keep the type of the click that set them off, so a link shim's `fbclid` is caught; Wis's own re-navigation is type "other", so it cannot loop, and typed loads, `location` changes, reloads and back/forward pass untouched. A jump within the page (same URL but for the fragment) and a download are never cancelled. The re-navigation sends no Referer and `Sec-Fetch-Site: none`. The cancelled navigation's "frame load interrupted" failure is skipped while the webview is loading its replacement (`superseded` in `commands/webview.rs`), so the tab never shows the pending URL with the old title. New-tab paths (`link_open::emit`, new-window requests from tabs and widget panels), Peek, the page menu (`clean_followed_link`), the navigation guard's carry-out and links from other apps (`default_browser::handle_external_urls`) clean on every platform. Windows and Linux same-tab clicks are not covered yet.

## Fraudulent website warning

- `webview_prefs.rs` enables WebKit's `fraudulentWebsiteWarningEnabled` (Apple-proxied Safe Browsing, off by default in WKWebView) on every remote webview (tabs, Peek, widget panels), showing a full-page warning before a suspected phishing/malware site. It complements `wis_core::link_safety`'s structural heuristics with a real threat database. A Settings -> Privacy toggle (default on, since the check performs network lookups) re-applies to all live remote webviews without reloads. Local chrome/overlay webviews are never touched.

## Global Privacy Control

- `UserSettings.global_privacy_control` (default on) drives two halves. The proxy stamps `Sec-GPC: 1` on every request it forwards itself (`proxy/upstream.rs`, read from `RequestPolicy::global_privacy_control`). `gpc.rs` defines `navigator.globalPrivacyControl` in every frame of every remote webview (tabs, Peek, widget panels) at document start. A settings change re-points every running proxy (`AppState::refresh_all_proxy_policies`) and, on every live remote webview, flips the top frame of the current document through `window.__wisGpcSet` and installs one more document-start all-frames script that flips every later document. Flip scripts accumulate one per toggle per webview, the last one winning; loaded iframes follow on their next navigation.
