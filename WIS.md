# WIS.md

Wis loads `WIS.md` from the workspace root as agent memory (similar to AGENTS.md / CLAUDE.md). This file is also the project's living architecture doc.

**Read it before making changes, and update it whenever you change architecture, add a crate/module, or ship a user-facing feature.** Keeping this file accurate is part of "done" for any change.

## Project

**Wis**: open-source, fast, safe and lightweight browser that draws inspiration from browsers like Zen and Firefox. macOS-first; Linux/Windows are build targets but feature parity for native pieces (cookies, biometrics, zoom) is macOS-only today.

- Bundle id: `app.myk.wis`
- Package manager: **pnpm**
- Run/build: use the `Makefile` (`make dev`, `make build`, `make check`, `make test`, `make lint`, `make fmt`). `make dev` runs `pnpm tauri dev`; the built-in Tor client is a **default cargo feature**, so a plain `make dev` already includes it.
- Frontend check: `cd crates/shell && pnpm build` (= `tsc && vite build`; this is the typecheck gate, there is no separate test script yet).
- Rust checks: `make lint` (`cargo clippy --workspace --all-targets -- -D warnings`) and `make test` (`cargo test --workspace --all-targets`).

## Quality bar

Production-grade or it does not ship. Every change is judged against all of these, not just "it works":

- **Correctness**: edge cases, failure modes, concurrent access. No "works for now".
- **Performance**: ultra-lightweight is the product. For every change ask: how much RAM it costs, whether it adds IPC round-trips or redundant requests, whether it triggers extra re-renders or wasted work, whether it pulls a heavy dependency. Unused features consume zero resources (gate heavy deps behind cargo features, start subsystems lazily).
- **Security**: no critical security holes. Validate at every boundary (IPC, fs, network). Secrets are never logged. Page webviews (`tab-<uuid>`) are never granted Tauri capabilities.
- **UI/UX**: polished, professional, premium. Every state and detail considered.
- **Architecture**: new or changed logic lives in pure, dependency-light functions (functional core); tauri commands and React components stay thin (imperative shell). Keeps it testable without a later rewrite.

Verify before claiming done: `pnpm build` (frontend), `make lint`, `make test`. A change to a core subsystem (main browser, storage, network) needs a test that locks the invariant.

## Conventions

- **Comments**: default to none, the code should explain itself. If genuinely needed, 1-2 lines on *why*, never *what*. No AI-generic filler.
  - Avoid the use of "we" in comments, be explicit and direct: "this runs on startup" instead of "we run this on startup".
- **No em-dash** anywhere: code, comments, commits, docs.
- **No emojis** anywhere.
- **Imports**: always `@/...` on the frontend, never relative across modules.
- **pnpm only**, never npm/npx/yarn.
- **References to plans**: references to phases in the implementation plan/roadmap should be avoided in code/comments/docs.
- **Immutability**: every state transition returns a new value; never mutate in place. (`Tab` is `Clone + PartialEq` but not `Eq` because it carries an `f64` zoom.)

## Architecture

### Crate overview

Cargo workspace, five crates. Dependencies flow strictly downward: upper layers import lower ones, never the reverse.

```text
wis-browser-app  (crates/shell/src-tauri)  - Tauri shell, IPC commands, AppState, native macOS glue
       |
  wis-network    (crates/network)           - privacy decision engine, proxy, DoH, Tor
       |
  wis-storage    (crates/storage)           - Storage trait + SQLite implementation
       |                 \
   wis-core      (crates/core)   wis-secrets (crates/secrets) - vault crypto + keychain
   (pure data model, no I/O)
```

**`wis-core`**: dependency-light, pure data model. Defines `BrowserState` (root aggregate), `Workspace`, `Tab`, `UserSettings`/`UserSettingsPatch`, and typed IDs (`WorkspaceId`, `TabId`, `TabFolderId`, `WidgetId`). Modules: `state`, `workspace`, `tab`, `tab_folder` (`TabFolder` live-tab grouping), `settings`, `layout` (`LayoutMode`/`RailSide`/`ThemeMode`), `pane` (`PaneNode`/`SplitDir` binary split tree), `privacy` (`PrivacyMode`/`PerSitePolicy`), `proxy` (`UpstreamProxy`: `Socks5`/`Tor`), `search` (`SearchEngine`), `keybinding` (`KeyAction` enum + default/effective keymaps), `link_safety` (pure heuristic `assess_link` for Peek), `user_agent` (`UaProfile` + pure UA-string builders / `ua_for_host`), `download` (`DownloadStatus` transitions + `sanitize_filename`/`unique_filename`, the security boundary for server-suggested download names), `background` (`Background::Gradient/Image` + boundary validation for per-workspace backgrounds), `icon` (`parse_icon_ref` validating encoded `glyph:`/`glyph-fill:`/`emoji:` references), `theme` (`CustomTheme`/`ThemeTokens` + validation, versioned `.wistheme` envelope), `widget`, `ids`, `error`. All mutation operations are pure `with_*` builders returning a new value.

**`wis-secrets`**: vault cryptography and master-key storage, isolated from the rest. Entries are sealed with ChaCha20-Poly1305 (AEAD, fresh random nonce per seal) under a 32-byte master key. The master key is generated with the OS CSPRNG, stored in the macOS login Keychain (this-device-only), and released into memory only after a Touch ID check; the in-memory copy zeroizes on drop (`zeroize`). Plaintext exists only transiently and is never logged or persisted.

**`wis-storage`**: persistence layer. `Storage` trait is the only interface the rest of the app codes against; `SqliteStorage` is the sole production implementation (bundled SQLite via `rusqlite` + `rusqlite_migration`, WAL + `synchronous=NORMAL`). Persistence is **normalized tables, not a JSON blob**: `BrowserState` is saved/loaded across `workspaces`, `tabs`, `essentials`, `settings`, `meta` in one atomic transaction. Separate append-style stores live alongside it: `history` (per-workspace, deduped by url), `credentials` (vault ciphertext), `searches` (URL-bar search history), and `bookmarks` (+ `bookmark_folders`, per-workspace, foldered; `folder_id` NULL = unfiled; `pinned`/`pin_position` flag the quick-access row independently of the folder), `session_cookies` (per-workspace **encrypted** snapshot of in-memory session cookies, for stay-logged-in across restarts), and `downloads` (global completed-download history; in-flight/failed/cancelled downloads live only in shell memory). Migrations are append-only `M0001`..`M0014` (`migrations.rs`; `M0010` adds `pinned` + `pin_position` to `bookmarks`, `M0011` adds `session_cookies`, `M0012` adds `session_cookies.created_at` for the absolute session TTL, `M0013` adds a JSON `tab_folders` column on `workspaces` + `folder_id` on `tabs` for live-tab folders, `M0014` adds `downloads`, `M0015` adds a JSON `background` column on `workspaces`, `M0016` adds `workspaces.custom_accent`, `M0017` adds a JSON `workspaces.background_drafts` column). Live-tab folders persist like `pane_tree` (JSON column); a workspace's transient `selected_folder_id` is **session-only** and reset to `None` on load. Crash resilience: `backup_to()` writes a consistent standalone copy via `VACUUM INTO`, and the shell's resilient open refreshes that backup on a healthy launch and recovers from it (or starts fresh) if the primary DB is corrupt. Ephemeral (private) workspaces are skipped on save, so they never touch disk.

**`wis-network`**: privacy decision engine. Contains:

- `TrackerBlocker` (`blocker.rs`): wraps the `adblock` crate; parses EasyList/EasyPrivacy rules once. The compiled engine is memoized on disk (`engine-<hash>.bin` beside the filter-list cache, keyed by a hash of the input texts, stale versions pruned): a warm launch deserializes the engine instead of re-parsing the list, and the self-versioned DAT format falls back to a fresh parse on any mismatch (crate upgrade, corruption). Both the startup build and the runtime EasyPrivacy refresh go through the cache.
- `filter_lists/`: bundled fallback list plus background `fetch` of fresh EasyPrivacy (cache-staleness gated).
- `content_filter.rs`: compiles filter rules to a WKWebView `WKContentRuleList` spec for engine-level blocking. Attachment is **lookup-first**: the `WKContentRuleListStore` persists compiled lists by identifier (the identifier hashes the rule JSON, so a refreshed filter list misses naturally), so the expensive compile (a full parse of EasyPrivacy-size JSON) runs once per filter-list version instead of on every tab creation and launch; startup prunes stale `wis-cb-*` entries from older list versions.
- `HttpsUpgrader` (`upgrader.rs`): HTTPS-First enforcement.
- `DohResolver` / `StubResolver` (`resolver.rs`): DNS-over-HTTPS via `hickory-resolver`; stub is the no-endpoint fallback.
- `RequestPolicy` (`policy.rs`): combines a workspace's `PrivacyMode` with the blocker into an allow/block/redirect `Decision` per request.
- `proxy/`: loopback HTTP proxy (hyper) per workspace. Forwards plain HTTP, tunnels HTTPS `CONNECT`, applies HTTPS-First redirects, drops trackers. Policy is **hot-swappable via `tokio::sync::watch`** (read per request) so changes never rebind the port. Supports an optional `upstream` (`proxy/upstream.rs`, `connect.rs`): SOCKS5 or Tor.
- `tor.rs`: built-in Tor via `arti-client`, exposed as a loopback SOCKS5 endpoint (`TorProxy`). Behind the `tor` cargo feature (**on by default**; build `--no-default-features` to omit).

**`wis-browser-app`** (`shell/src-tauri`): Tauri app wiring. `AppState` holds: `browser: Mutex<BrowserState>`, `storage: Arc<dyn Storage>`, `tracker_blocker: RwLock<Arc<TrackerBlocker>>`, `resolver: Arc<dyn Resolver>`, `content_rules` (per-`PrivacyMode` compiled rule cache), `filter_cache_dir`, `proxies: Mutex<HashMap<WorkspaceId, ProxyServer>>` (lazy, one per workspace), `vault_key: Mutex<Option<MasterKey>>`, `pending_capture` (save-password prompt), `closed_tabs` (reopen ring), and `tor_proxy` (lazy, `tor` feature). Native modules: `commands` (IPC), `state`, `menu` (accelerators -> `wis-keyaction` events), `overlay` (floating webviews), `find`, `cookies`, `favicons`, `biometrics` (LocalAuthentication / Touch ID), `vault`, `capture` (`WKScriptMessageHandler` for save-password), `suggest`, `content_filter`, `pane_focus` (native click-to-focus), `peek` (Opt+click link preview), `navguard` (navigation safety interstitial), `bookmarks` (per-workspace foldered bookmark CRUD), `external` (hand a URL to the OS default browser), `error_compat`.

### IPC command pattern

Every mutating command goes through `mutate`:

1. Acquire the async mutex on `BrowserState`.
2. Snapshot previous state for rollback.
3. Compute next state via a pure `with_*` transition from `wis-core` (no I/O inside the closure).
4. Persist next state via `Storage::save_state`.
5. On persist failure: revert in-memory state and surface `WisError::PersistenceFailed`.

After a successful mutation the command emits `browser-state-changed`; the frontend re-fetches `BrowserState` via React-Query (the query cache is the single source of truth on the JS side). Read-only commands hold the mutex only long enough to clone the relevant slice.

### Webview compositing and overlays (important)

Native tab webviews (`tab-<uuid>`) composite **above** the chrome webview, so HTML chrome cannot draw on top of a page. Any floating UI that must sit over a page (find bar, command palette, URL-bar suggestions, clear-data dialog, vault menu, pane-split menu, Peek) is therefore a separate **overlay webview** (`overlay-<name>`), positioned natively and routed in `overlay/OverlayRoot.tsx` to a surface in `overlay/surfaces/`.

The capability boundary is **local vs remote content**, not just the window: the `default` capability has no `remote` block, so it applies only to local app webviews (the `main` chrome and the `overlay-*` surfaces, which load the bundled `index.html`). Tab pages and the Peek preview (`peek-page`) load remote `http(s)` URLs and match no command-granting capability, so they can never call a command. (The one exception is `tab-devtools.json`, which grants only the devtools-toggle to `tab-*` remote webviews.) Tab webviews set `on_new_window(... Allow)` so `window.open`/`target=_blank` popups (e.g. "Continue with Google" and other OAuth flows) open as a native wry window using the opener's WKWebView configuration, sharing the workspace session + proxy and keeping the `window.opener` link OAuth needs (postMessage / window.close). That popup is a bare wry webview with no Tauri capability, so the remote-content boundary holds.

### Frontend (React / TypeScript)

Lives in `crates/shell/src/`. Imports use `@/...` aliases; relative cross-module imports are forbidden.

**Components** (`src/components/`): `Window` (root layout host), `TopBar`/`NavRow`/`TopTabsRail` (chrome), `UrlBar` (address input + HTTPS security indicator + vault key button), `Sidebar`/`WorkspacePill`, `TabList`/`HorizontalTabs`/`TabFolderHeader`/`PinnedTabs`/`TabFavicon`, `TabWebViewHost`/`SplitPaneHost` (mount native webviews to measured rects, one per visible pane leaf), `Content`, `SettingsPage` (with `PasswordsSection`, `SiteDataSection`, `KeybindingInput`), `HistoryPage`, `NewTabPage`, `VpnToggle` (Tor on/off), `ConfirmDialog`, `Brand`/`WisMark`, `controls`.

**Hooks** (`src/hooks/`): `useBrowserState` + `useBrowserStateEvents` (fetch + invalidate), `useTabWebviews` (webview lifecycle), `useThemeApply`, `useKeyActions` (dispatch `wis-keyaction` events), `useActivePrivacyMode`, `useNavigateOrCreateTab`, `useTabSplit`, `useIslandMenu` (top-tabs folder recolor/rename/delete menu), `usePendingRename`, `useWindowIcon` (private/normal icon swap), `useUrlbarSuggest`, `useOverlay` + per-surface overlay hooks (`useCommandPaletteOverlay`, `useClearDataOverlay`).

### Window styling

- Chrome surfaces use background tiers for contrast: `--content-bg` (inside the periwinkle border: settings/new-tab/webview, transparent in glass so it shows the OS vibrancy), and darker `--chrome-bar` / `--chrome-bar-glass` for the chrome frame (side bar, top bar, rail) and the margin **around** the content. The frame around the content is painted with a large `box-shadow` spread on `.kb-content` (clipped by `.kb-main { overflow: hidden }`) so the margins match the bars without darkening the content. Bars that float over the main area (collapsible sidebar, top-tabs rail) are left transparent so they reveal that same frame shadow rather than stacking a second dark layer.
- Split panes reuse this idea as a "cut-out": each pane `.pane-surface` is a transparent rounded window (the page shows the OS vibrancy straight through it) whose **outset** `box-shadow` draws the periwinkle pane ring (full accent on the focused leaf) and then floods everything outside the window (including the rounded-corner slivers) with the same frame tone, clipped to the pane's slot (`.pane-slot { overflow: hidden }`). An outset shadow never paints inside its own box, so the page stays fully transparent; the surface radius matches the native webview corner radius so opaque webview panes and transparent chrome panes fill identically and show no light gaps. `.kb-content.is-split` also zeroes its **border width** (not just colour) so no thin ring of bare vibrancy shows between the pane group and the chrome-bar frame.
- Scrollbars (chrome webview only) use a single global `::-webkit-scrollbar-thumb` whose colour is the `--scrollbar-thumb` token, **inverted vs the theme** (light thumb in dark mode, dark thumb in light) so it stays visible on any surface; large chrome pages just widen it.
- macOS: `titleBarStyle: Overlay` + `hiddenTitle: true` (native traffic lights via overlay); chrome webview shadow disabled to avoid a glass flash on navigation.
- Linux: `decorations: false` + `transparent: true`; re-asserted post-realize for GNOME/Mutter CSD. Windows: same via `tauri.windows.conf.json`, custom `WindowControls`.

### Cross-platform conventions

- HOME / cache dirs: use the `dirs` crate, never raw `$HOME` / `%USERPROFILE%`.

## Features

- **Workspaces**: color-accented profiles; each gets its own WebView data store, proxy, and privacy mode.
- **Private browsing**: private = an *ephemeral* workspace with a non-persistent data store; excluded from save, wiped on close. "Always launch private" setting; private window icon.
- **Split panes**: per-workspace binary `PaneNode` tree (tmux-style), resizable dividers, focused-leaf highlight; each leaf is its own native webview. Native click-to-focus routes keybinds to the focused leaf.
- **Pinned tabs**: a tab can be pinned (`Workspace.pinned_tab_ids` + `Tab.pinned`, kept in sync by `pin_tab`). Pinned tabs are pulled out of the normal tab list/strip and shown as a docked quick-access set, present in every layout. In the **collapsible sidebar** (`PinnedTabs`) they are a favicon grid (rows of three) under the workspace pill: clicking a cell activates the tab, the title is the tooltip, the active one is ringed; collapsed, the grid becomes a single workspace-pill-sized **pin glyph** (a generic pin glyph rather than many favicons, matching the workspace pill) that the sidebar reveals by expanding (auto on hover; the glyph also expands it). In the **top-tabs** layout they are favicon-only circles docked at the start of the strip (ordered by `RailSide` so they always sit nearest the rail), draggable to reorder; the active circle shrinks so bubble + ring keep the normal footprint while the favicon stays put. Pin/unpin lives on the tab context menu (the right-click directional split pill, `overlay-tabmenu`): a divider then a pin toggle that calls `pin_tab`. Pinned tabs never sleep and never sit inside a folder. Reordering the remaining tabs reorders only the non-pinned subset and merges back so pinned tabs keep their slots in `tab_order` (`reorderedWithPinned`).
- **Tab folders**: open tabs can be grouped into per-workspace, named, recolorable folders (`wis_core::tab_folder::TabFolder` { id, name, accent, collapsed, position }; `Workspace.tab_folders` + `Tab.folder_id`, mutually exclusive with pinned). Distinct from bookmarks (those save URLs; folders organise *live* tabs). In the **sidebar** (`TabList` + `TabFolderHeader`) they render as an IDE-style tree: a colored name pill + chevron + member rows beside an inset accent rail; in the **top-tabs** strip (`HorizontalTabs`) they render as **islands**: a colored circle when collapsed, an expanded glass pill (colored name chip + its tabs) when open. Both support create, inline rename, recolor (accent swatches), collapse, delete (members stay open, re-parented loose), and pointer-drag reorder; a tab can be dragged onto a folder to file it, dragged out to empty strip/loose space to unfile, reordered within a folder, or moved via the tab context menu ("Move to folder / new folder / remove from folder"). Clicking a folder **selects** it (theme-ring highlight) as the target new tabs file into: Cmd+T, link opens, and bookmark opens honour the selected folder (or inherit the active tab's folder via `with_new_tab`), while the explicit "+ New tab" button always makes a **loose** top-level tab (`with_new_loose_tab`). The selection also **tracks the focused tab**: clicking a tab activates it and points the target at that tab's folder (a loose or pinned tab clears it; in the top-tabs strip a click on empty strip space clears it too). This lives in the shared `useFolderTarget` hook (`setTarget` / `syncToTab`) used by `TabList`, `HorizontalTabs`, and `PinnedTabs` so the sidebar and top-tabs behave identically. IDE-style, Enter on a selected folder starts inline rename. Collapsing a folder **sleeps** its member tabs immediately (bypasses the idle timer), tying into the memory model. Commands: `create_tab_folder` / `rename_tab_folder` / `recolor_tab_folder` / `set_tab_folder_collapsed` / `set_tab_folder_icon` / `delete_tab_folder` / `reorder_tab_folders` / `assign_tab_to_folder` / `select_tab_folder`; persisted via migration `M0013` and skipped for ephemeral workspaces (`selected_folder_id` is session-only).
- **Folder + workspace icons**: folders and workspaces can carry an icon rendered inside their colour dot (and beside the island label in top-tabs): a wireframe or filled glyph from the bundled registry (`src/lib/iconGlyphs.tsx`, Lucide-derived closed shapes with wire+fill variants) or an emoji. Encoded as a compact string (`glyph:<name>` | `glyph-fill:<name>` | `emoji:<char>`) validated by the pure `wis_core::icon::parse_icon_ref` at the command boundary (`set_tab_folder_icon` / `set_workspace_icon`); glyph names are charset-checked in core and resolved in the chrome (unknown names fall back to the plain dot). Picked via the shared `IconPicker` (Line/Fill/Emoji tabs + None reset) inside the folder options menu and the workspace recolor expansion. **No migration**: `TabFolder.icon` rides the JSON `tab_folders` column and `Workspace.icon` repurposes the existing, previously unused column. Glyphs tint with `currentColor`; emoji render as-is.
- **History & cookies**: per-workspace deduped history with search; native cookie/site-data listing and per-domain / full clear via `WKHTTPCookieStore` + `removeDataOfTypes`; unified clear-browsing-data dialog.
- **Stay logged in across restarts**: WebKit keeps session cookies (no expiry) only in memory and drops them on quit, so logins like Canvas wouldn't survive a restart. We snapshot a workspace's session cookies (`WKHTTPCookieStore getAllCookies`, expiry-less only) to the `session_cookies` table (after each page load and on a 60s timer) and restore them (`setCookie:`) into the workspace's data store on its first tab each run, before the page loads (`cookies::persist_session_cookies` / `restore_session_cookies`, once per workspace via `AppState::restored_cookies`). Persistent cookies are left to WebKit. Empty snapshots never overwrite a saved one (avoids clobbering a valid session when a store is momentarily released). Never for ephemeral workspaces. **Encrypted at rest**: session cookies are live bearer tokens, so the snapshot is sealed with ChaCha20-Poly1305 (`wis_secrets`) under a dedicated 256-bit key in the login Keychain (`session_key_load_or_create`), distinct from the vault master key and **not** Touch ID gated, so it's available automatically at launch (mirrors Chrome's "Safe Storage"). If the key is unavailable we persist nothing rather than write plaintext; a snapshot that fails to decrypt is treated as "nothing to restore". **Blast-radius bounds**: each snapshot's `created_at` is stamped once (not refreshed by later snapshots), and a restored session **auto-expires after a fixed TTL** (`SESSION_COOKIE_TTL_DAYS` = 14), forcing periodic re-auth so a stolen snapshot is only useful for a bounded window; stale snapshots are purged from disk at launch. The whole feature is gated on the **`persist_sessions`** setting (Settings → Privacy → "Stay logged in across restarts", default on); turning it off skips persist/restore and wipes any saved snapshots.
- **Password vault**: ChaCha20-Poly1305 at rest, master key in Keychain gated by Touch ID. Save-password capture (native script-message handler -> consent prompt), saved-account picker, and origin-matched autofill (app -> page eval only; pages can't call vault commands). The capture script watches several submit signals (form submit, Enter in a password field, click on a login control, page teardown, and a MutationObserver for the filled password field disappearing) and pierces shadow DOM via `composedPath`, so SPA/modal logins (Twitch, Gmail, Canvas) are caught. Hosts are normalised `www.`-stripped on both save and lookup so the key/autofill match across `www`/bare hosts. URL-bar key button surfaces saved logins; the save prompt persists across the post-login navigation (it follows the captured login in the backend, not the current page host) until the user acts.
- **URL-bar suggestions**: overlay dropdown: recent searches, history-ranked site recommendations, inline base-website completion, favicons. Default search engine setting (DuckDuckGo/Google/Bing).
- **Vendored wry patch** (`vendor/wry`, applied via `[patch.crates-io]`): wry 0.55.1 verbatim except `url_from_webview` no longer unwraps a nil `WKWebView.URL` (clicking "go back" on WebKit's fraud-warning interstitial with an empty back stack panicked inside the navigation delegate and aborted the process). The fix is applied verbatim from upstream PR tauri-apps/wry#1729, so dropping the vendor once that ships is a zero-behavior-change swap. See `vendor/wry/WIS-PATCH.md`.
- **Strict CSP on local surfaces** (`tauri.conf.json` `app.security.csp`): the chrome/overlay webviews are the only capability-granting surfaces and render page-controlled strings (titles, URLs, suggestion text), so they carry a strict policy as defense-in-depth behind React's escaping: `default-src 'self'`, `script-src 'self'` (tauri auto-nonces its injected scripts), `img-src 'self' data:` (favicons are data: URLs), `object-src/frame-src 'none'`, `connect-src 'self' ipc: http://ipc.localhost`. `style-src` carries `'unsafe-inline'` (React style attributes); everything else is `'self'`-only because the brand fonts are **bundled locally** (`src/styles/fonts.css` + `fonts/*.woff2`: Geist/Geist Mono primary, Instrument Serif accent, DM Sans/DM Mono fallback, latin+latin-ext subsets, OFL-licensed) - the chrome performs no third-party fetch and renders offline. Applied to assets served via the tauri protocol (production); the vite dev server is uncovered, so verify CSP behavior in a bundled build. `img-src` also allows `wis-asset:` for workspace wallpapers.
- **Fraudulent website warning** (`webview_prefs.rs`): every remote webview (tabs, Peek, widget panels) enables WebKit's `fraudulentWebsiteWarningEnabled` (Apple-proxied Safe Browsing, off by default in WKWebView), showing a full-page warning before suspected phishing/malware sites; complements `link_safety`'s structural heuristics with a real threat database. Settings -> Privacy toggle (default on, since the check performs network lookups); toggling re-applies to all live remote webviews without reloads. Local chrome/overlay webviews are never touched.
- **Network privacy**: per-request DoH, HTTPS-First, tracker blocking (host-level + `WKContentRuleList`), and a per-workspace upstream proxy. Built-in **Tor VPN** (Arti) with a simple on/off toggle (sidebar + top-tabs rail); icon lit only when connected, with a connecting state; toggling re-routes by reloading workspace tabs.
- **Quick browser features**: per-tab page zoom (Cmd +/-/0) persisted across restarts, reopen-closed-tab ring (Cmd+Shift+T), hard reload, HTTPS security indicator, configurable keyboard shortcuts (every `KeyAction` is a native menu item whose accelerator is rebindable in Settings -> Shortcuts; beyond the basics: downloads popup Cmd+J, bookmarks popup Alt+Cmd+B, bookmark-this-page Cmd+Shift+B (drives the URL-bar star's full flow via a DOM event; Cmd+B is deliberately left to pages for bold), pin/unpin tab Cmd+Shift+P, duplicate tab Cmd+Shift+K, copy current URL Cmd+Shift+C (native `NSPasteboard` via `clipboard.rs`, since the chrome webview lacks a user gesture in menu handlers), and toggle floating sidebar Cmd+S), command palette, find-in-page, favicon cache. Reopening a closed tab restores its **full session** (`interactionState` captured at close into the `ClosedTab` ring entry, handed to the new webview via `AppState.pending_restore_states` keyed by the reopened tab id), so history/scroll/forms survive Cmd+Shift+T; a tab that was already slept when closed cold-loads (no live webview to read). Reopen is **folder-faithful**: the ring records the tab's `folder_id` at close, the tab is recreated loose (`with_new_loose_tab`, bypassing the workspace's currently-selected folder) and re-assigned to its original folder when it still exists, so reopening never files the tab into whatever folder happens to be selected. `restore_closed_tab` is **inert in private workspaces** (the ring never holds private tabs, and reopening would jump out of the private context).
- **Browser identity / compatibility**: remote (page) webviews present a modern Safari-class user agent by default (`wis_core::user_agent`), since WKWebView's default UA omits the `Version/.../Safari/...` tokens and sites flag it "unsupported". Configurable in Settings -> Compatibility: a default `UaProfile` (Safari / Chrome / Engine-default) plus per-host overrides (`ua_site_overrides`, `www.`-stripped host) for sites that special-case a browser. The UA is set at webview-build time on tab and Peek webviews; local chrome/overlay webviews are untouched. Stored in `UserSettings` (JSON blob, `#[serde(default)]`, no migration).
- **Open in default browser**: a URL-bar action and `external::open_in_external_browser` command hand the current `http(s)` page to the OS default browser (macOS `open` / Linux `xdg-open` / Windows `start`), an exit hatch for pages the embedded WebKit can't fully handle (e.g. Widevine video; see Known limitations). Scheme-validated to `http(s)` only. On macOS, if Wis itself is the default web handler it falls back to Safari so the handoff can't loop back in.
- **Downloads**: file downloads from remote webviews (tabs, Peek, widget panels) are intercepted via wry's download hook (`downloads.rs`) and handled safety-first. The destination is always `~/Downloads/<leaf>`: the server-suggested filename is reduced to a safe leaf by `wis_core::sanitize_filename` (final path component only, no control chars/`:`/leading dots, length-capped) and collision-resolved Finder-style by `unique_filename` against both disk and in-flight downloads, never overwriting; a destination that would escape the downloads directory is denied outright. Completed files are tagged with the `com.apple.quarantine` xattr so Gatekeeper scans them like any browser download. Items (`DownloadItem`: url, path, received bytes, status, private flag) live in `AppState.downloads` (sync mutex, since wry's callbacks are synchronous main-thread code); every change emits `downloads-changed` and the chrome refetches via `list_downloads`. macOS API limits (WKDownload through wry): the finish event carries only url+success, so completion matches the oldest in-flight download of that URL; there is no native progress or cancel callback, so progress is the destination file's growing size polled every 500 ms (total size unknown, indeterminate). Downloads from a private workspace or Peek still save (user-requested) but are flagged `private` and never recorded in persistent history. **Completed downloads persist** across restarts in the `downloads` table (append-only, global, `M0014`): a successful non-private finish writes its row off the main thread, `list_downloads` returns this session's items (all statuses) merged with prior sessions' completed history (deduplicated by id), and `remove_download` drops an entry from both the list and the table without touching the file. Engine-created popups (`window.open` allowed via `on_new_window`) carry no wry delegates, so downloads inside them are not intercepted. **UI**: a downloads glyph sits in both layouts (sidebar fixed-bubble stack above bookmarks, and the top-tabs rail controls), with a pulsing accent dot while anything is in flight; it toggles the `overlay-downloads` popup (`DownloadsMenuSurface`, bookmarks-popup styling incl. the liquid-glass toggle) showing the latest entries: in-flight rows with an indeterminate progress bar and live byte count (no total is available, see above), completed rows that **open the file on click** and show "File may have been moved or deleted" when it is gone, an X to remove an entry, and a "View all downloads" footer that opens the full page. The full page (`about:downloads` -> `DownloadsPage`, history-page styling) adds search (client-side over filename/url/host), per-row open + "Show in Finder" + remove, day grouping, and a select mode (checkboxes, select all) whose Delete asks for confirmation (red button) and removes only history entries, never files. `open_download`/`reveal_download` validate before shelling out (`open`/`open -R`): the id's recorded path must still exist as a regular file resolving directly inside its recorded directory (anchoring on the recorded parent covers custom ask-where locations while still ruling out symlink swaps); a missing file resolves `false` (the moved-or-deleted notice) rather than erroring. **Ask where to save** (Settings -> Downloads, `download_ask_where`, default off): each download runs a native `NSSavePanel` (synchronously inside wry's main-thread download callback via `runModal`) prefilled with the sanitised suggested name and starting in the **remembered last-picked directory** (`download_last_dir`, updated only by panel picks and persisted through the normal settings path); cancel denies the download, and a panel-confirmed replace deletes the existing file first since WKDownload refuses an existing destination (an explicit user gesture, so the never-overwrite rule for server-driven names is not weakened). The download callback reads these settings through `AppState.download_prefs`, a sync mirror seeded at startup and refreshed by `update_settings`, because the synchronous callback cannot await the `BrowserState` lock.

Like the window resize edges, the affordance is the `col-resize` cursor, not a visible handle. **Stacking is actively maintained** (tabs < panels < overlays): tab webviews are created lazily and each `add_child` lands on top of everything, so `create_tab_webview` re-promotes panels then overlays (`promote_panels_to_front`), and re-showing a hidden panel re-promotes too (its stale subview position may have been overtaken). An accent **header bar** (`overlay-widgetheader`, `WidgetHeaderSurface`) docks above the visible panel with a **reload** button (top right): native cache-bypassing `reloadFromOrigin` via `reload_widget_panel`, so a hung page (which would never run injected JS) still recovers; the bar tracks the panel live during resize drags. Theme-sensitive widget URLs go through `effectiveWidgetUrl` (Instagram's web dark mode is a `?theme=dark` query parameter, not `prefers-color-scheme`): applied at open time, and a live light/dark flip re-navigates affected panels immediately (`navigate_widget_panel`, watched via a `data-mode` MutationObserver in `useWidgetPanel`). The surface emits drag deltas (`wis-wresize-*` events); the chrome resizes the panel live anchored at its outer edge and persists the width in `localStorage` (clamped 300px..55vw). Dock favicons can be **drag-reordered** within their row (pointer-based, like tabs; HTML5 DnD is swallowed in the main chrome webview); the persisted `sidebar_widgets` order is the display order. It is **not a tab**: a panel dismisses on re-click, Escape, any chrome click outside the dock, a click inside a tab webview (native `wis-pane-focus`), or an active tab change (`useWidgetPanel`). Dismissal **hides** the webview rather than destroying it, so re-opening is instant with in-page state (drafts, scroll, live connections) kept; hiding also **suspends all media playback** in the panel (`setAllMediaPlaybackSuspended`, macOS 11.3+ public API, selector-guarded; resumed on re-show), so a backgrounded panel keeps its sockets but never keeps video/audio decoders running; guardrails: all panels hard-destroyed on workspace switch (each is bound to one workspace's data store + proxy), dismissal destroys outright in private workspaces, and a panel left hidden past the widget idle window (`widget_sleep_minutes`) is destroyed to reclaim memory. Favicons via `prefetch_favicon`, prefetched at startup and cached in-memory + on disk (`WidgetFavicon`, letter-tile fallback). Chosen in Settings -> Sidebar widgets (toggle chips, social / AI groups). Global across workspaces; stored in the settings JSON blob (`#[serde(default)]`, no migration). Rendered in all layouts: sidebar docks show two horizontal rows; the top-tabs rail shows a centred vertical column above the rail controls. Favicon capture falls back to the page's `<link rel="icon">` declarations (hand-rolled scanner in `favicons.rs`, no HTML-parser dep) when `<origin>/favicon.ico` yields no usable image, which is how Discord, Gemini, DeepSeek and most SPAs expose icons.
- **Per-workspace backgrounds**: each workspace can carry a custom page background (`Workspace.background: Option<Background>`, `wis_core::background`, persisted as JSON via `M0015`; ephemeral workspaces keep it in memory only). Gradients ship first: a `GradientSpec` (angle + 2..8 hex stops, validated at the IPC boundary before entering state) edited live from Settings -> Appearance -> Workspace background (`BackgroundEditor`, acting on the active workspace; the mode selector grows to gradient/image/GIF when wallpapers land) (preview, angle slider + typed degrees capped 0..=180 since larger angles mirror smaller ones, per-stop **custom colour picker** (`ColorPicker` in `controls.tsx`, hand-rolled SV square + hue slider + hex field, no library), add/remove stops, "Theme default" reset; edits debounce 150 ms into `set_workspace_background`). The launchpad paints images as a **shared canvas**: the backdrop pseudo-layers span the whole content host (each pane measures its slice offset in `NewTabPage` and the pane clips the layer), so split panes reveal contiguous regions of one wallpaper laid out against the full content area, coverage holds for any pane shape, and blur seams line up across panes; a blurred cover fill sits underneath so contain/tile letterboxes land on a blurred copy of the wallpaper, never a bare strip. The blur control (0..=40 px) blurs the wallpaper without blurring content; fit maps to cover/contain/tile (applied against the host box) and dim (0..=80%) layers a black overlay; GIFs animate natively. Each mode's last configuration **persists** (`Workspace.background_drafts`, updated by `with_background`, `M0017`), so switching Theme/Gradient/Image restores what the user built in each, across restarts. Separately, the workspace popover's accent grid ends with the saved **custom colour palette** (`UserSettings.custom_accent_palette`, shared across workspaces, settings blob) plus a dashed `+` square: clicking it spawns a tentative swatch with the colour picker open, Esc/click-away discards it, and only the picker's `+` confirm saves the colour to the palette and applies it to the workspace (`Workspace.custom_accent`, validated hex, `M0016`, painting the dot and clearing when a preset is picked).
- **Custom themes**: full chrome themes built in Settings -> Appearance -> Themes (`ThemesSection`). Stored in `UserSettings` (`custom_themes` + `active_theme`, settings blob, no migration); list edits replace-whole through the settings patch and are re-validated in `update_settings`. Editor: per-mode colour pickers with live apply (debounced), new, duplicate, delete (confirm). **Sharing**: `export_theme`/`import_theme` move versioned `.wistheme` JSON via the shared native panels (`panels.rs`, main-thread `runModal` dispatch); import size-caps the file, validates the full structure, rejects newer-versioned files, and re-mints the id so a shared theme can never collide with an existing one.
- **Motion**: all chrome transitions draw from central motion tokens in `tokens.css` (`--dur-fast/med/slow`, `--ease-standard`, `--ease-emphasized` springy, `--ease-exit`; the scattered hardcoded durations/beziers in `window.css` were folded into them). A three-tier `UserSettings.motion` (`MotionLevel`: Full/Reduced/Off, settings blob, no migration; Settings -> Appearance segmented) maps to body classes in `useThemeApply`: **Reduced** keeps every duration but flattens `--ease-emphasized` to standard (no overshoot), **Off** zeroes transition/animation durations inside the chrome, and the OS `prefers-reduced-motion` preference caps Full at Reduced live. Drag-reorder choreography builds on these tokens (`lib/tabMotion.ts`): while a drag is in flight the source element keeps its slot hidden under the floating ghost and siblings **live-part** one slot around the insertion point (transform transitions gated by `body.is-tab-dragging`; covers sidebar rows, sidebar folder rows, top-strip loose tabs, pinned circles and folder islands, replacing the old insertion-line indicators); tabs reorder **within folders** in both layouts, and a tab dragged from outside an open folder (or out of one, over the loose list) targets a **positional slot** (`insertedAmong`: assign + reorder in one drop; expanded islands widen by one slot while targeted); reorders and folder assignment apply **optimistically** (`patchTabOrder`/`patchFolderOrder` cache patches) so the drop re-renders in the new order on the same frame, and the dropped element then **glides from the ghost's rect into its slot** with a small settle pop (WAAPI; pop dropped on Reduced, skipped on Off). The sidebar's active-tab marker is a single sliding bar (`.kb-active-bar`, measured against the list root, re-measured when folder folds land) instead of a per-row `::after`; the settings section nav uses the same pattern (`.kb-settings-nav-ind` pill gliding between items). **Workspace switches** slide the tab list/strip in from the side of the new workspace's position relative to the old (`workspaceSlideIn`, imperative WAAPI, no remount). **Peek grows from the clicked link**: the Opt+click script forwards the click point, the chrome translates it to window coords against the content host (approximate in split layouts), and the card scales up from that transform-origin, with the native preview created only after the grow so it never composites over the animating card. The **downloads popup** rises in with its rows following on a small stagger, replayed per open via a shown-event nonce. The top strip reflows loose-tab widths through a flex group anchored to the corner opposite the rail, so folder collapse/expand (sized as collapsed from the closing frame, width contracting in step with the shrink sweep), spawns and closes glide without ever moving the folders or pinned circles. **Native surfaces animate by stepping webview bounds per frame over IPC**: animations never resize a live page (reflow-per-frame reads as jank). **Split entrances are a chrome-side glide**: when a split adds a pane while others persist, the webviews tuck away for ~300ms (the same preview look as divider drags), the mounting `PaneSplit` starts the new leaf's slot at zero and glides it open via a flex-grow transition (`.is-entering`, `PANE_GLIDE_MS`), then the webviews reveal at their final rects (`TabWebViewHost` diffs the leaf set during render so the same commit both arms the entrance and tucks the webviews; workspace switches and replacements stay direct). **Removals mirror it**: closing a pane or unsplitting (Cmd+Opt+U) keeps painting the outgoing tree (render-phase state adjustment, so the new tree never flashes) while every split whose entire subtree is being removed glides that slot shut (`.is-exiting`, `subtreeCloses`), then the committed tree takes over and the webviews reveal. - **Peek**: Opt+click (intercepted at `mousedown`, since macOS turns Option+click into a download) a link to preview it in a small isolated card without leaving the page. The preview (`peek-page`) is incognito (separate ephemeral data store) and routed through the workspace proxy, so a link-based scam can't touch the browser; a banner warns about suspicious links via pure heuristics (`wis_core::link_safety::assess_link`: homograph/punycode, `user@host`, deceptive anchor text, IP host, http, etc.). A reader toggle transforms the page in place inside the isolated view. Trigger is a narrow `WKScriptMessageHandler` (`wisPeek`); the card is the `overlay-peek` surface with the live page tiled into a measured hole. - **Navigation safety interstitial** (`navguard.rs` + `overlay-navguard`): complements Peek for *real* navigations, with two layers: (1) a narrow `wisNavGuard` handler + injected script intercepts a plain (non-Option) left-click on a risky link **before it navigates** (`preventDefault`), so nothing loads in the background (`navigated: false` → "Take me back" just dismisses); (2) a page-load fallback (`maybe_guard` on `on_page_load` Started) catches anything the click path can't (address bar, JS redirects), halting the load via `stopLoading` (`navigated: true` → "Take me back" goes back). Rust re-assesses the href; for High (and non-`insecure_http` Medium) hosts not already waved through (`AppState::nav_guard_bypass`, session-scoped) it raises a full-window interstitial with threat level + reasons, "Take me back", and a red "Proceed anyway" (navigates + remembers the host). HTTPS-First means plain-`http` Medium is intentionally not interrupted.
- **Bookmarks**: per-workspace, organised into optional folders (`folder_id` NULL = unfiled, rendered loose, no auto "Unfiled" folder), persisted in SQLite (`wis_storage::bookmarks`, never in `BrowserState`). A bookmarks glyph (sidebar fixed bubble / top-tabs rail control, styled like the VPN/settings bubbles) opens a palette-style overlay popup (`overlay-bookmarks`, liquid glass, aligned to the sidebar side) showing unfiled bookmarks as favicon bubbles, then folders that expand to indented favicons; folder create/rename/delete are inline (delete re-parents to unfiled). The address-bar **star** bookmarks the page into the last-used folder (persisted per workspace in `localStorage`, default unfiled) and **auto-pins** it to the quick-access row while that row has room (`PIN_CAP` = 6 = one row), then opens an anchored folder picker (`overlay-bmpicker`, vault-menu style) to confirm/change the folder; clicking the star again removes the bookmark. Disabled in private (ephemeral) workspaces. **Pinning is independent of folder membership** (`pinned`/`pin_position` columns): a bookmark can be pinned to the quick-access grid *and* live in a folder, appearing in both. The popup renders the **pinned quick-access grid** (every `pinned` bookmark, ordered by `pin_position`), then folders that show all their bookmarks (including pinned ones), then the **unfiled-and-unpinned** rest list below the folders. The popup also optimistically patches its own React Query cache on each mutation (`setQueryData`) so the open popup updates instantly without waiting on the refetch (which otherwise lags for in-popup folder create/rename/delete). The popup's queries are keyed by the active workspace and gated only on it (no `visible` flag: the overlay webview persists, so a visibility flag set once on mount would never re-enable on reopen and the popup would show stale/empty data); opening the popup re-emits `browser-state-changed` + `bookmarks-changed` so it tracks the current workspace (e.g. after adding/switching one) and shows fresh bookmarks. In the popup, favicons can be **dragged onto a folder** (`move_bookmark`, keeps the pin), **dragged onto the unfiled area below the folders** to take them out of a folder (unfiles **and** unpins, since that area lists plain unfiled+unpinned bookmarks, so the favicon lands where it was dropped instead of staying a bubble), **dragged onto the pinned grid** (pin: add while the row has room, or drop on a bubble to replace it when the row is full at `PIN_CAP`=6; already-pinned favicons reorder), or **right-clicked** for Pin/Unpin (`set_bookmark_pinned`, keeps the folder) + a "Move to" menu; a pinned bubble's X unpins (the bookmark stays in its folder). **Folders can be reordered** by dragging a dedicated **grip handle** on the folder header (`reorder_bookmark_folders`; drop above/below the target's midpoint). The reorder grip is a separate element rather than making the whole toggle button `draggable`, because a draggable element can swallow drops landing on it, so a favicon dropped on a collapsed target folder (whose only drop area is its header) would not move. The drop handler reads the drag **kind from the transfer payload** (`folder:<id>` vs a numeric bookmark id) rather than a mutable ref, which can go stale when a dragend doesn't fire (source element unmounted on drop). **Within a folder, favicons can be dragged onto each other to reorder** (`reorder_bookmarks` sets `position` by index; drop above/below the target's midpoint, shown by an insertion line); dropping a favicon from elsewhere onto a folder row files it there at that slot. Mutations apply **race-proof optimistic cache updates** (cancel in-flight refetches, `setQueryData`, then invalidate) so rapid successive changes (e.g. moving several bookmarks into a folder) all reflect instantly instead of a stale refetch clobbering the second. (Overlay webviews call `disable_drag_drop_handler()` so wry doesn't swallow in-page HTML5 DnD; the draggable source must be the `<button>` itself: a draggable `<div>` wrapping a button won't start a drag in WebKit.)
- **Memory / startup**: background tab webviews are discarded ("slept") after an idle threshold and recreated on focus; at launch only visible tabs spin up a webview (lazy session restore), the rest load on first show. Both are owned by `useTabWebviews.ts` (creation gated on layout visibility + a coarse idle sweep); the active tab and pinned tabs never sleep, and tabs inside a **collapsed folder** are slept immediately (a collapsed folder is explicitly tucked away, so it skips the idle delay). Tunable in Settings → Performance (`tab_sleep_enabled`, `tab_sleep_minutes`); slept tabs are dimmed in the tab list via `DiscardedTabsContext`. **Wake is no longer a cold reload** (`interaction_state.rs`): just before a background webview is discarded, its WKWebView `interactionState` (back/forward list, scroll position, form data; macOS 12+) is read as base64 and cached in chrome memory (bounded, most-recent 30 sleeps); on wake `create_tab_webview` starts the webview on about:blank and applies the blob, whose restore performs its own navigation with everything intact. Blobs never persist to disk, so they are always consumed by the same WebKit version that produced them; an evicted or missing blob just cold-loads like before.
- **Task manager** (`memory.rs` + `TaskManagerSection`, Settings -> Performance): a live per-webview memory readout polling every 3s while the settings page is shown. Each webview's WebContent pid comes from WebKit's `_webProcessIdentifier` (guarded behind `respondsToSelector`; skipped when unavailable) and its physical footprint from `proc_pid_rusage`'s `ri_phys_footprint`, the same figure Activity Monitor's Memory column shows. Rows map labels to friendly names (tabs by title, widget panels by widget label, chrome/overlays/Peek tagged) sorted by footprint with a total, and tabs/widget panels get a one-click Close to reclaim their process. This pid+footprint plumbing is the base for memory-pressure eviction policies (C2).
- **Resource trims**: per-workspace loopback proxies are **torn down after idling** (a 60s sweep drops a workspace's `ProxyServer` once it has had no live tab webviews for 10 minutes; `ProxyServer::drop` signals shutdown via its watch channel, and `ensure_proxy_for` lazily respawns on the next webview creation; the active workspace is exempt since Peek/widget panels always use it). `browser-state-changed` refetches are **coalesced per animation frame** (`useBrowserStateEvents` rAF guard), so a mutation burst triggers one `BrowserState` fetch. Startup widget-favicon prefetch runs through a **concurrency cap of 4** so a cold cache doesn't compete with first page loads; the launchpad quicklink prefetch is sequential by construction.
- **Resilience**: WAL + `synchronous=NORMAL` (the recommended WAL pairing: integrity-safe, only the last commit is at risk on power loss, bounded by the backup) + `VACUUM INTO` backup at launch; corrupt DB is set aside and recovered from backup (or a fresh DB) so launch is never blocked and a session is never silently wiped.
- **Coalesced persistence** (`save_coalescer.rs`): every mutation snapshots the full `BrowserState`, so high-frequency bursts (drag reorders, zoom ticks, load/title sync) queue a debounced 200 ms "latest snapshot wins" write instead of one write+fsync each. Destructive transitions (close tab, delete workspace/folder, settings) still write **immediately** with rollback-on-failure. Snapshots are sequence-stamped under the state lock and the writer refuses to write older-than-committed, so a delayed debounced write can never roll the DB back behind a later immediate one; pending saves are flushed in the tauri `RunEvent::ExitRequested/Exit` hook so quitting never loses the debounce window.

## Known limitations / engine tradeoffs

Wis renders with the OS system WebView (WKWebView on macOS) via Tauri/wry, the same engine as Safari. That choice is the source of the product's wins (tiny bundle, low RAM, Safari-class speed and battery, no bundled engine to update) and dictates these limits, which are structural rather than bugs:

- **Premium DRM video (Widevine)**: WKWebView's only CDM is Apple FairPlay, not Google Widevine, and there is no API to inject a Widevine CDM (the CDM hooks the engine's media pipeline, which WKWebView does not expose). FairPlay itself is not licensed for general third-party-app playback, and services like Netflix gate on the Safari app. Result: premium DRM streaming (Netflix/Disney+/etc., especially 1080p/4K) is degraded or blocked. Mitigation is the **Open in default browser** action, not an in-app fix. Adding native Widevine would require switching to a Chromium engine (CEF) plus a Widevine license, which would forfeit the bundle/RAM/battery wins; explicitly not pursued. Note: even Firefox forks like Zen punt DRM to Firefox for the same licensing reason.
- **Browser extensions**: an embedded WKWebView cannot load Safari Web Extensions (reserved for Safari). Wis substitutes a native blocking stack (`WKContentRuleList` + the `adblock` crate) rather than a WebExtensions runtime.
- **Site isolation**: WebKit's site isolation is weaker than Chrome's (still rolling out upstream), offset by strong OS sandboxing and out-of-process rendering.
- **Other**: no cross-device sync, no mobile companion, and some newer web APIs (WebUSB/WebBluetooth/web push/PWA install) are partial or absent under WebKit. Native feature parity (cookies, biometrics, zoom, open-in-default-browser default handler) is macOS-only today.
