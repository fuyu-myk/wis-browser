# WIS.md

Wis loads `WIS.md` from the workspace root as agent memory (similar to AGENTS.md / CLAUDE.md). This file is also the project's living architecture doc.

**Read it before making changes, and update it whenever you change architecture, add a crate/module, or ship a user-facing feature.** Keeping this file accurate is part of "done" for any change.

## Project

**Wis**: open-source, fast, safe and lightweight browser that draws inspiration from browsers like Zen and Firefox. macOS-first; Windows and Linux ship as preview builds. Windows is a growing tier-1 port (vault via DPAPI + Windows Hello, Mica glass, and a widening set of webview features reached through the `win_webview2` WebView2 helper, see Cross-platform conventions). Linux (WebKitGTK) is the next port: its page -> chrome layer (`gtk_dispatch`), a widening set of features (cosmetic filtering + element picker, find-in-page, keyboard shortcuts, camera/mic consent, peek, nav-guard, save-password capture), and the multi-webview compositing/overlay/focus stack (vendored `tao`/`tauri-runtime-wry`/`wry` patches) are wired, compile on CI (ubuntu-22.04), and the **core flows are runtime-verified in an X11 VM**; glass/transparency rendering fidelity and a few per-feature checks await real hardware (`docs/contributing/linux-vm-testing.md`). A few native pieces (session/history restore, session-cookie persistence, per-tab memory) remain macOS-only today.

- Bundle id: `app.myk.wis`
- macOS floor: **14.0** (`bundle.macOS.minimumSystemVersion`). Each workspace's cookies and storage live in their own `WKWebsiteDataStore`, which needs 14; below it wry silently falls back to one shared store.
- Package manager: **pnpm**
- Run/build: use the `Makefile` (`make dev`, `make build`, `make check`, `make test`, `make lint`, `make fmt`). `make dev` runs `pnpm tauri dev`; the built-in Tor client is a **default cargo feature**, so a plain `make dev` already includes it.
- Frontend check: `cd crates/shell && pnpm build` (= `tsc && vite build`, the typecheck gate), `pnpm lint` (ESLint: React hooks rules and `no-console`, all errors) and `pnpm test` (Node's built-in `node:test` over `crates/shell/tests`, no dependencies). `tests/lib` covers every `src/lib` module and `pnpm test` fails below 80% of lines or functions there; `tests/scripts` covers every page script embedded in Rust, read out of the Rust source (`tests/support/rustSource.mjs`) so the tests run the text that ships. A bug a test exposes but is unfixed is a `test.todo`. React hooks and components are not covered (no DOM in the runner).
- Rust checks: `make lint` (`cargo clippy --workspace --all-targets -- -D warnings`, then the frontend `pnpm lint`) and `make test` (`cargo test --workspace --all-targets`).

## Quality bar

Production-grade or it does not ship. Every change is judged against all of these, not just "it works":

- **Correctness**: edge cases, failure modes, concurrent access. No "works for now".
- **Performance**: ultra-lightweight is the product. For every change ask: how much RAM it costs, whether it adds IPC round-trips or redundant requests, whether it triggers extra re-renders or wasted work, whether it pulls a heavy dependency. Unused features consume zero resources (gate heavy deps behind cargo features, start subsystems lazily).
- **Security**: no critical security holes. Validate at every boundary (IPC, fs, network). Secrets are never logged. Page webviews (`tab-<uuid>`) are never granted Tauri capabilities.
- **UI/UX**: polished, professional, premium. Every state and detail considered.
- **Architecture**: new or changed logic lives in pure, dependency-light functions (functional core); tauri commands and React components stay thin (imperative shell). Keeps it testable without a later rewrite.

Verify before claiming done: `pnpm build` (frontend), `make lint`, `make test`. A change to a core subsystem (main browser, storage, network) needs a test that locks the invariant.

## Conventions

- **Comments**: default to none, the code should explain itself. If genuinely needed, 1-2 lines on *why*, never *what*. No AI-generic filler.
  - Avoid the use of "we" in comments, be explicit and direct: "this runs on startup" instead of "we run this on startup".
- **No em-dash** anywhere: code, comments, commits, docs.
- **No emojis** anywhere.
- **Imports**: always `@/...` on the frontend, never relative across modules.
- **Feature folders**: code is grouped by feature. A Rust folder's `mod.rs` holds only its `mod` lines and platform gates, and its main file is named for what it holds.
- **pnpm only**, never npm/npx/yarn.
- **References to plans**: references to phases in the implementation plan/roadmap should be avoided in code/comments/docs.
- **Immutability**: every state transition returns a new value; never mutate in place. (`Tab` is `Clone + PartialEq` but not `Eq` because it carries an `f64` zoom.)

## Architecture

This section orients; the deep detail lives under `docs/architecture/` (see Further reading). Those docs elaborate on WIS.md and WIS.md wins on any conflict.

### Crate layers

**Cargo workspace, six crates; dependencies flow strictly downward** (upper layers import lower, never the reverse).

```text
wis-browser-app  (crates/shell/src-tauri)  - Tauri shell, IPC commands, AppState, native macOS glue
       |       \
       |    wis-import (crates/import)      - reads other browsers' profiles (wis-core only)
       |
  wis-network    (crates/network)           - privacy decision engine, proxy, DoH, Tor
       |
  wis-storage    (crates/storage)           - Storage trait + SQLite implementation
       |                 \
   wis-core      (crates/core)   wis-secrets (crates/secrets) - vault crypto + keychain
   (pure data model, no I/O)
```

- **`wis-core`**: pure, dependency-light data model. `BrowserState` root aggregate, `Workspace`, `Tab`, `UserSettings`, typed IDs, and pure `with_*` builders. Feature folders: `tabs`, `workspaces`, `navigation`, `sites`, `privacy`, `vault`, `extensions`, `library`, `canvas`, `ai`, `appearance`, `settings`, beside `state` (the `BrowserState` aggregate), `error` and `ids`; the common types are re-exported at the crate root. Detail: `docs/architecture/data-model-and-state.md`.
- **`wis-secrets`**: vault cryptography, master-key storage and the password generator, isolated. ChaCha20-Poly1305 AEAD under a CSPRNG master key held in the OS secure store (macOS Keychain / Windows DPAPI blob), released after a biometric check and zeroized on drop. Detail: `docs/architecture/security-vault-and-permissions.md`.
- **`wis-storage`**: persistence. `Storage` trait + sole `SqliteStorage` impl (bundled SQLite, WAL, `synchronous=NORMAL`); normalized tables (not a JSON blob), append-only migrations `M0001`..`M0025`, `VACUUM INTO` backup + resilient open (a profile is set aside only on a failed integrity check; one from a newer build stops launch instead of being discarded, and dev runs under its own identifier). Detail: `docs/architecture/data-model-and-state.md`.
- **`wis-import`**: discovers other browsers' profiles on this machine and reads them with size caps, copying SQLite databases before opening them (Chromium and Firefox families). Profile files are untrusted. Detail: `docs/architecture/tabs-panels-and-media.md`.
- **`wis-network`**: privacy decision engine. `TrackerBlocker` (adblock crate, disk-memoized engine), `content_filter` (`WKContentRuleList`), `HttpsUpgrader`, `DohResolver`, `RequestPolicy`, per-workspace loopback proxy (SOCKS5 / built-in Tor via `arti-client`, `tor` feature default-on). Detail: `docs/architecture/privacy-and-network-engine.md`.
- **`wis-browser-app`** (`shell/src-tauri`): Tauri wiring. `AppState` (browser mutex, per-window active workspace, storage, blocker, resolver, proxies, vault key, screenshots, Tor); feature folders `vault`, `ai`, `canvas`, `protection`, `pages`, `tabs`, `chrome`, `platform` (the `win_*`/`gtk_dispatch` cross-platform seams), `system` and `data`, beside the IPC `commands`, `extensions`, `video_popout` and `translation` (macOS 26.4+: a Swift bridge, `swift/Translation.swift`, to Apple's Swift-only Translation framework, compiled by `build.rs` with `swiftc` and weak-linked so older macOS still launches). Detail: split across the docs below.

### IPC command pattern

**Every mutating command goes through `mutate`: lock state, snapshot for rollback, compute the next state with a pure `wis-core` `with_*` transition, persist, revert on persist failure.** After success it emits `browser-state-changed`; the frontend refetches via React-Query (the single JS source of truth). Read-only commands hold the lock only long enough to clone a slice. Detail: `docs/architecture/data-model-and-state.md`.

### Webview compositing, overlays, windows

**Native tab webviews (`tab-<uuid>`) composite above the chrome webview, so any floating UI is a separate per-window overlay webview.** The browser is one OS window per workspace (`chrome/multi_window.rs`); multi-window session/geometry restore, engine-popup routing (`popup_chrome`, `on_new_window`: geometry popups stay native, plain navigations become tabs), and Cmd/middle-click open-in-tab all live here. Off-main AppKit is marshaled via `run_on_main_thread`. Every webview, chrome and page alike, disables wry's drag-drop handler so pages keep native HTML5 DnD and file drops, and hidden child webviews are parked off-window (vendored wry) so a hidden overlay or background tab never intercepts a drag meant for the visible page. Detail: `docs/architecture/webviews-windows-and-overlays.md`.

### Capability boundary

**The security boundary is local vs remote content, not just the window.** The `default` capability grants commands only to local app webviews (chrome + `overlay-*`) on the `["main", "win-*"]` glob; tab pages and the Peek preview load remote URLs and match no command-granting capability, so they can never call a command. That holds without exception: `tab-devtools.json` used to grant the devtools toggle to `tab-*`, and was removed when Inspect moved to a command the chrome calls. Detail: `docs/architecture/security-vault-and-permissions.md`.

### Frontend (React / TypeScript)

**Lives in `crates/shell/src/`; imports use `@/...` aliases, relative cross-module imports forbidden.** Thin imperative shell over the `wis-core` model: `features/<feature>/` (vault, tabs, ai, canvas, settings, site, workspaces, extensions, bookmarks and more; larger ones split into `components/`, `hooks/`, `lib/` and `surfaces/`), with only shared code left in `components/` (the app frame and primitives), `hooks/` (`useBrowserState`, `useOverlay`, `useTabWebviews`) and `lib/` (`theme`, `url`, `toast`, `keybindings`); a feature never imports another in a cycle and `lib/` never imports a feature (`tests/structure.test.mjs`); `bindings/` (typed IPC wrappers + `wis-core`-mirroring types, camelCase to serde at the boundary). Detail: `docs/architecture/chrome-shell-and-layouts.md`.

### Window styling

**Chrome surfaces use layered background tiers and a frame `box-shadow` for contrast; glass is OS vibrancy (macOS), Mica (Windows 11), none elsewhere; the glass tint is opacity-compensated per platform (`body[data-platform]` overrides) since Mica and the bare Linux desktop show through far more than macOS vibrancy.** The native tab webview's corner radius follows the Corners design setting (`--radius-scale`, re-applied live on change). Split panes are transparent rounded cut-outs with an accent ring (square off macOS); chrome scrollbars invert vs the theme; macOS uses `titleBarStyle: Overlay`, Linux `decorations:false` + `transparent`. Linux pins corners to square (`--radius-scale: 0`, the Design > Corners control locked to Sharp) because its child webviews render with square corners; it also builds no native menu bar (keybinds are JS-dispatched). Detail: `docs/architecture/webviews-windows-and-overlays.md`.

### Cross-platform layer

**A per-feature seam ports each macOS-AppKit capability to Windows/Linux, verified per platform.** The page -> chrome channel is `WKScriptMessageHandler` (macOS) / a single `win_dispatch` receiver behind a shim (Windows) / native `gtk_dispatch` handlers (Linux); on macOS and Linux the channels whose message makes the browser act, and their scripts, run in Wis's own script world (`platform/content_world.rs`) so a page cannot post to them, and on Windows those scripts post through a private sender carrying a per-tab token (`win_dispatch::private_script`); keyboard shortcuts are native menu accelerators on macOS (a focused tab sees every non-reserved combo first, with the in-page forwarder as fallback) but JS-dispatched on Windows and Linux (native accels never fire behind a focused webview; Linux attaches no native menu at all, chrome-side capture + the in-page forwarder cover both focus states). Native UX ports cover clipboard, file panels (`rfd`), downloads shell-out, click-to-focus (`focus_self`/`focus_webview` per platform), find, and capture; a **feature-availability toast** replaces silent no-ops. On Linux, positioned child webviews (tabs, overlays, peek) required a vendored `tao`/`tauri-runtime-wry`/`wry` patch set: a full-window `gtk::Fixed` overlay for compositing (upstream tauri#10420) plus show/map lifecycle fixes (WebKitGTK neither repaints a resize applied while unmapped nor raises on show). Linux is **compile-verified on CI (ubuntu-22.04) and core-flow runtime-verified in an X11 VM**; rendering fidelity pends real hardware. Detail: `docs/architecture/cross-platform-and-page-channel.md`.

## Features

Each group maps to a `docs/architecture/` doc that carries the mechanism details; the one-liners below orient.

### Privacy & network (`docs/architecture/privacy-and-network-engine.md`)

- **Network privacy**: per-request DoH with a provider picker (Cloudflare, Quad9, Google; applied live, no restart), HTTPS-First, host-level + `WKContentRuleList` tracker blocking, and a per-workspace upstream proxy (built-in Tor, or a SOCKS5 host and port entered in settings and validated at the boundary, both reachability-probed), and Global Privacy Control (on by default: `Sec-GPC` on the plain-HTTP requests the proxy forwards, `navigator.globalPrivacyControl` in every frame).
- **Cosmetic filtering + element picker / zapper**: hides empty ad slots / nags beyond network blocking (`wisCosmetic`/`wisZap`), `:has(...)` procedural rules included; per-host user rules persist. Runs on macOS/Windows/Linux (Linux via `gtk_dispatch`).
- **Scriptlets & user scripts**: uBO `+js` (uBO's library from Ghostery's copy; only uBO's own default lists may run its trusted scriptlets) and Tampermonkey `.user.js` injected per-navigation (page world, no `GM_*`); the scriptlet/user-script swap is macOS-only for now.
- **Filter lists**: EasyList/EasyPrivacy plus user subscriptions feed the engine (YouTube ad blocking via uBO scriptlets); managed in Settings -> Privacy. Each list is fetched with uBO's `!#if` branches evaluated and its `!#include` lists pulled in (`filter_lists/directives.rs`).
- **Cookie notices and annoyances**: two switches in Settings > Privacy (`wis_core::privacy::notice_lists`). Cookie notices, on by default, subscribes the EasyList Cookie List; annoyances swaps in Fanboy's Annoyance list, which contains it. The list's hiding rules run in Wis's cosmetic layer and its network rules compile into a WebKit rule list of their own beside EasyPrivacy's, so its exceptions cannot lift Strict's script block. Banners are hidden, never answered; the site panel's blocking switch undoes it for one site.
- **Tor VPN**: built-in Arti with a simple on/off toggle; re-routes by reloading workspace tabs.
- **Fraudulent website warning**: WebKit Safe Browsing enabled on every remote webview (Settings toggle; macOS-only, the other engines expose no equivalent and their settings row says so; navguard covers risky links everywhere).

### Security & data protection (`docs/architecture/security-vault-and-permissions.md`)

- **Password vault**: ChaCha20-Poly1305 at rest, master key in the OS key store gated by a biometric (Touch ID / Windows Hello); save-capture (offering to update a saved login after a change-password form, or with the vault open a differing password), saved-account picker (key button, and a card at the focused sign-in field), origin-matched autofill (app -> page eval only, the host checked again by the fill script as it runs); on Linux a vault password (an Argon2id-sealed key file) stands in for the key store and biometric check; an unreadable stored key is reported, never replaced, and Settings offers recovery through the user's own age or SSH public key (an age-format copy of the key) or a reset that erases the vault; CSV import/export (`wis_core::vault::password_csv`, biometric-confirmed both ways, plaintext-export warning).
- **Saved addresses**: Settings > Addresses keeps postal addresses with contact details (`wis_core::vault::address::Address`, first and last name kept apart), each sealed whole with the vault key in the `addresses` table (migration 25), so nothing about them is readable while the vault is locked. They ride along with passwords in backups, count as sealed data for key creation, recovery and reset, and a "Save and fill addresses" switch (`UserSettings::address_autofill`, on by default) governs offering them at forms: a card at a focused address field (`vault/address_field/mod.rs`, channel `wisAddress`; fields known by their `autocomplete` tokens, or else from their labels and names with Chromium's patterns in `vault/address_field/patterns.js`, BSD, credited in `THIRD_PARTY_NOTICES.txt` and the About panel) fills the chosen address into that form section's visible, empty fields. After a form with a new address is submitted, the key-button menu offers "Save address?" (`vault/address_save.rs`), never in private workspaces.
- **Saved payment cards**: Settings > Payment cards (`vault/cards.rs`, `cards` table, migration 26) keeps the number, name, expiry and a nickname, never the security code. The card is sealed whole; its nickname, network, last four digits and expiry also sit in the clear so a card field can list cards before an unlock. The full number never reaches the chrome. Cards count as sealed data for recovery and reset, and are backed up with passwords and addresses. At card fields on https pages (tagged `cc-*`, or read with Chromium's card patterns), the `cards` overlay lists saved cards; every fill asks Touch ID or the vault password (`vault/address_field/card_fill.rs`). After a checkout, the key-button menu offers to save the card used (`vault/card_save.rs`), never in private workspaces.
- **Stay logged in across restarts**: encrypted session-cookie snapshot restored before first load, fixed 14-day TTL, gated by the `persist_sessions` setting; never for ephemeral workspaces.
- **Camera & microphone consent**: app-side `getUserMedia` gate + in-browser prompt with remembered decisions (macOS/Windows/Linux; the Linux prompt is wired but not yet exercised in the VM).
- **Navigation safety interstitial**: `navguard` re-assesses risky links (click-time and page-load fallback) and interrupts High/Medium threats; shares `link_safety` heuristics with Peek.
- **Open in app**: custom-scheme navigations (zoommtg://, slack://, mailto:) are cancelled at every policy seam (tabs, new-window, macOS engine popups, Peek, widget panels) and offered as an OS handoff via a prompt overlay with per-site remembered decisions (`app_launch`, `UserSettings.app_launch_permissions`); this is what completes OAuth "open in app" linkbacks. Windows/Linux popup redirects fall back to engine defaults.
- **Strict CSP** on local surfaces and the local-vs-remote **capability isolation** above; the vendored Tauri-stack patches (`wry`/`tao`/`tauri-runtime-wry`) stay clean verbatim drops of upstream PRs, dropped when those merge; feature code never patches them.

### State & storage (`docs/architecture/data-model-and-state.md`)

- **Immutable state, normalized persistence**: `BrowserState` saved across normalized SQLite tables in one transaction, coalesced debounced writes with immediate destructive writes, WAL + `VACUUM INTO` backup resilience.
- **Encrypted profile backup**: passphrase-sealed `.wisbackup` (Argon2id + ChaCha20-Poly1305), merge-on-import with id re-mint; passwords opt-in via the device vault key.

### Chrome shell & layouts (`docs/architecture/chrome-shell-and-layouts.md`)

- **Workspaces**: color-accented profiles, each with its own WebView data store, proxy, and privacy mode; **private browsing** is an ephemeral workspace (excluded from save, wiped on close) whose tabs and widget panels share one in-memory data store (`private_store`, macOS and Linux).
- **Multi-window**: one OS window per workspace, free-workspace picker, move-tab-to-new-window/workspace, session + geometry restore.
- **Split panes**: per-workspace binary `PaneNode` tree, resizable, focused-leaf highlight, native click-to-focus.
- **Pinned tabs & tab folders**: docked quick-access pins; per-workspace named/recolorable/icon-bearing folders of live tabs, rendered as a sidebar tree or top-tabs islands, with drag-reorder and selection-targeted new tabs; link-opened tabs land beside their opener in link order.
- **Folder + workspace icons**: glyph/emoji icons via `wis_core::appearance::icon`, shared `IconPicker`.
- **Theming & motion**: custom `.wistheme` themes, per-workspace gradient/image/GIF backgrounds, Light/Dark/System mode pushed to web content, and a tokenized three-tier motion system (drag choreography, FLIP close glides, pane/widget entrances). On macOS the chrome and its overlays draw at the display's full rate (120 Hz on ProMotion); web pages keep WebKit's 60 fps cap.
- **Accessibility**: Tab reaches every control in Wis's own UI whatever the macOS keyboard-navigation setting, with one focus ring; menus, groups and tab strips work by arrow keys (Delete closes a tab, Shift+F10 opens its menu, Alt+arrows move tabs, folders, pins and widgets, F6 cycles address bar, tabs and page); overlays take focus and give it back on close (runtime-verified on macOS; the Windows and Linux arms are runtime-unverified); tabs, menus, the address bar, prompts and Settings carry proper roles, names and descriptions; toasts, downloads and confirmations are spoken through a native macOS announcement; Reduced motion keeps fades only. Detail: `docs/architecture/chrome-shell-and-layouts.md` (Keyboard focus).
- **AI assistant (bring your own key or run it locally)**: a docked chrome-side panel for free chat, page summaries, and questions about the open page, against Anthropic or any OpenAI-compatible endpoint (Ollama, LM Studio, OpenRouter). Dormant by default: it activates on a key sealed in the OS key store, or on an OpenAI-compatible base URL (a local server authenticates nothing, so the key is optional there and the bearer header is omitted entirely). Until one of those is set there is no entry point and no code path, and none at all on Linux, which has no key store. The model is picked in the panel's header from the provider's list, or typed. Requests route through the workspace proxy, except a loopback endpoint, which is dialled direct so a local model's traffic never leaves the device; the transcript is in-memory for the window, dropped on workspace change and never persisted; page text is shared only by an explicit action, per send, or by the opt-in local-data tools below, and every turn that carried it says so. A reasoning model's working streams into its own collapsible disclosure (labelled with how long it thought) and is never replayed as conversation history; answers render as markdown via a pure subset parser mapped to escaped React elements, never injected HTML, with links opening as new tabs behind an http(s) allowlist. An opt-in **web access** toggle (both providers; runtime-verified on macOS, wired for Windows and Linux via their message dispatchers) lets the model call `web_search` and `web_fetch`, so a local model can pull current answers: pages load in a hidden incognito webview with no Tauri capabilities, routed through the workspace proxy, and every URL, entry and redirect alike, must pass a public-web SSRF gate (`is_public_web_url`), with fetches further allowlisted to search results and user-given URLs; each round shows as an expandable "using tool" indicator that settles into what it found, capped at four rounds, and Answer now breaks a failing tool loop. A second opt-in, **read tabs, history and bookmarks** (off by default), adds `list_tabs`, `read_tab`, `search_history` and `search_bookmarks`, scoped natively to the asking window's workspace; each read shows as one of those rows, and once a turn has read local data any web search waits for the user to approve its query. A third opt-in, **manage tabs**, lets the model open, switch to, close and group tabs, each shown on a card the user cancels, retries or accepts before anything happens. With web access on, a **Research** toggle on the composer turns the next question into a fixed pipeline: the model plans two or three searches, Wis reads the top results three at a time in the same hidden incognito webviews until six usable pages are in (stubs and duplicates skipped), keeps the passages of each that match the question, and the answer is written from those sources only, with numbered citations that jump to a source list under it.
- **URL-bar suggestions** and a **configurable launchpad + homepage** (editable shortcut tiles, boundary-sanitized).
- **Custom search engines**: user-defined engines (`wis_core::navigation::search`, `{searchTerms}`/`%s` templates, boundary-sanitized) with address-bar keyword triggers (`kw query`); built-in engines can carry optional keywords too (custom wins on collision); any engine can be the default (Settings > Search), resolved consistently across URL bar, launchpad, and palette.

### Tabs, panels & media (`docs/architecture/tabs-panels-and-media.md`)

- **Tab memory & sessions**: idle-sleep + lazy restore with `interactionState` wake, full session restore across restart (`tab_sessions`, `M0018`), and a per-webview **task manager** (macOS; empty off macOS).
- **Quick browser features**: per-tab zoom, find-in-page with match count (Linux count-only), numbered/next/prev tab switching, reopen-closed-tab, hard reload, print/Save-as-PDF, and configurable rebindable shortcuts.
- **Load-failure error pages**: a failed navigation (DNS, connection refused, timeout, TLS) renders a chrome-side error page with retry in the tab's place (webview hidden but alive); `wis_core::LoadError` normalizes each engine's native code. macOS surfaces the failure via a vendored-wry side channel (a sixth patch, since `PageLoadEvent` cannot gain a Failed variant without vendoring tauri too), Windows via `add_NavigationCompleted`, Linux via WebKitGTK `load-failed` (kind is coarse there).
- **Peek**: Opt+click isolated incognito link preview with a safety banner and reader toggle.
- **Reader mode**: in-place clean-article transform shared with Peek.
- **Page translation** (macOS 26.4+): on-device, through Apple's Translation framework; `ToggleTranslation` (`Alt+Cmd+T`), the View menu or the palette translates what is on screen first, main content before menus, and restores the original in place. Plain text uses the faster low-latency model when it is installed.
- **Video popout**: always-on-top mini player (the tab's own reparented webview on macOS; native Picture-in-Picture on Windows; toasts on Linux), automatic on tab-hide and manual.
- **Tab audio**: per-tab audibility indicator + engine-level mute (macOS/Windows/Linux).
- **Site usage**: active time per site, workspace and local day (`wis_core::library::usage`, table `site_usage`). The focused pane's site counts while there is input or it plays audio; quiet seconds are held until input confirms them and dropped once idle passes the timeout (default 2 minutes). An audible site in a visible window counts while another app is in front. Private workspaces, Wis pages and error pages never count, and clearing history clears it. A Usage panel docked beside the sidebar shows today by hour or this week by day, with each site's time and share, in the theme's accent ramp. `about:usage` shows one week at a time: total (compared with the same weekdays of the week before), daily average, busiest day, a dot-and-line chart of time per day, weekly totals for the last 8 weeks against their average (each chart also as a table), and sites. Weeks start on the region's first day unless Settings picks Sunday or Monday.
- **Canvases** (macOS; Linux without the agent, dictation or document reading, and with HTML cards only on WebKitGTK 2.42+; Windows without HTML cards, dictation or document reading, not yet run on Windows hardware): named spaces of Markdown cards, one set per workspace, opened from the dock's Canvases button or "Open canvases" in the palette. A canvas tab is Wis's own page on the `wis-canvas` scheme, without Tauri IPC, reading and writing only its workspace's canvases over the `wisCanvas` channel; documents reach the disk every two minutes, when the tab closes, and on quit (table `canvases`, `M0022`). Private workspaces keep their canvases in memory only. The name pill top left switches canvases (fuzzy search, "New canvas"), renames by double-click or right-click, and deletes; canvases have their own Light/Dark theme (Settings > Appearance) and take the browser's accent, and they travel in `.wisbackup` with their workspaces (on by default). Pan, pinch and drag write transforms directly once per frame, at the display's full rate; box select, multi-card moves, arrows between cards, groups, titled frames that carry their cards, live HTML cards (each in a sandboxed frame with no network, running only while on screen, and paused after one freezes the canvas), a canvas agent that builds and edits cards from a prompt, with text, PDF and word processor attachments (long ones read up to the limit, with a warning), on-device dictation, its own model choice and web search when allowed (BYOK, same provider as the assistant), a right-click menu, a props panel on the side away from the sidebar (size, position, colour, align and arrange, arrow styles and labels), undo/redo, and a zoom pill.
- **Page capture**: clipboard-default screenshots (visible / region / whole-window composite) with a Save toast; window composite is macOS-only (page-only fallback elsewhere).
- **Downloads**: safety-first `~/Downloads` handling (sanitized names, quarantine xattr, no overwrite), persisted history (`M0014`), ask-where option, popup + full page; a navigation that becomes a download leaves the tab on its current page, a tab opened only for a download closes itself, and main-frame PDFs and attachment responses download rather than opening WebKit's inline viewer (macOS).
- **Sidebar quick-launch widgets**: a curated catalog (social, AI, productivity) plus user-added custom-URL sites placeable in any dock row (picker at add time, or drag across rows; curated widgets stay in their own row), validated at the IPC boundary (`Widget::validate`: http(s) + bounded label + group override customs-only); per-widget floating panels sharing the workspace store/proxy, with LRU count + memory caps, keep-loaded/idle-sleep, and a header bar; a plain click on a link to another site opens it as a foreground tab (`wisOpenInTabFg`), same-site links stay in the panel, and Cmd/middle-click opens a background tab as in tabs. Every remote-webview destroy path (widgets, tabs, peek, window close) closes the WebKit page first via `webview_close`, which makes the WebContent process exit deterministically; panel creation is serialized against a WebView2 message-pump deadlock.
- **Bookmarks**: per-workspace foldered + independently pinnable quick-access, star flow, drag organize (SQLite, never in `BrowserState`); HTML (Netscape) import/export via Settings > Bookmarks (`wis_core::library::netscape`, duplicates skipped, nested folders flattened); direct import from Chromium- and Firefox-family browsers on this device via Settings > Import (`wis-import`).
- **Breach check**: saved passwords can be checked against public breach data without being revealed. Each is hashed on the device and only the first five characters of the hash are sent, so the service never learns which password was asked about, and the request follows the workspace's own network route.
- **Recently closed**: the last 200 closed tabs are remembered across restarts and browsable in the command palette, which lists the last few before you type anything, and in History's Recently closed view (`ClosedTabsList`, `features/history/closedTabs.ts`), scoped to this workspace or all like history, grouped by day, searchable, with archived tabs labelled (`closed_tabs.archived`, migration 24) and listed by when they were last used. A row reopens the tab in its workspace and place; one can be removed (`forget_closed_tab`) or the scope cleared (`clear_closed_tabs`). Every change emits `closed-tabs-changed` so the view stays current. Reopening restores the live session when the tab was closed in the same run. Web pages, Wis pages and canvas boards are recorded, blank new tabs are not, and deleting a canvas drops its rows. Private windows record nothing, and clearing history clears the list.
- **Archive idle tabs**: Settings > Performance closes tabs left unused for 12 hours, 1, 7 or 30 days (off by default; `UserSettings::tab_archive_after`) into Recently closed, by the clock, so time away counts. `BrowserState::idle_tabs` (`wis_core::tabs::archive`) spares pinned tabs, tabs in folders, the tabs a workspace shows (its active tab and split panes), non-web pages (canvas boards, Wis pages) and private workspaces, whose closes are never recorded. Every transition touches the tabs it stops showing (`with_hidden_tabs_touched`, applied in `mutate_with`), so idle time runs from when a tab was last on screen, whether it was left by switching, opening a new tab or link, or closing a split. The shell's sweep (`tabs/archive.rs`, a minute after launch, then every 10 minutes) also spares tabs playing audio and a popped-out video, closes every still-idle tab in one transition under the state lock (`with_idle_tabs_closed`), and records them in one transaction stamped with when each was last used (`record_archived`), so they sort behind tabs closed since and a reopen brings back the latest close first. The cap keeps the last 200 recorded rather than the 200 most recently closed, or an archived tab would be pruned on arrival. Only the 25 newest closes keep their live session in memory; the palette lists all 200. A restored backup's tabs count as used when they land, so they are not archived at once.
- **Zoom**: page zoom belongs to the site, not the tab. Zooming is remembered per host and applies in every tab and on every later visit; a default zoom covers the rest. Reset forgets the site.
- **Autoplay**: a global policy (allow, block sound, block all; block sound by default) with per-site rules. Engine-level on macOS per page load and on Linux per webview; Windows keeps WebView2's own rule.
- **Lockdown Mode**: a per-workspace switch in Settings > Network (`Workspace.lockdown`, macOS 14+) for WebKit's Lockdown Mode, which turns off the JIT, WebAssembly, WebGL, WebRTC, service workers, camera and microphone. WebKit reads it from the configuration a webview is created with: each tab, Peek, widget panel and assistant page-reading creation marks its label (`hardening::mark`, set or cleared every time, from a read taken just before `add_child`) and the configuration hook in `platform/webkit_features.rs` reads the mark, since Tauri's `add_child` only posts the creation to the main thread. Switching rebuilds the workspace's open tabs through the sleep path (`wis-rebuild-tabs`, audible tabs included, a tab still being created rebuilt once it exists) and closes its Peek and widget panels; popped-out videos keep their mode until replaced. Canvas tabs are never locked down. The Tor route suggests it; it stays off by default.
- **Fingerprinting protection**: Safari's Advanced Tracking and Fingerprinting Protection (`_setNetworkConnectionIntegrityEnabled:`, macOS 13.3+) in every workspace but Permissive ones, private included. It adds noise to canvas and audio readouts, reports the window as the screen and drops click identifiers such as `fbclid` from cross-site links. It rides the same creation-time marks as Lockdown Mode (`protection/hardening.rs`, `Hardening { lockdown, fingerprinting }`) on `defaultWebpagePreferences`, and changing a workspace's privacy mode to or from Permissive rebuilds it the same way. Canvas tabs go without.
- **CNAME uncloaking**: in Balanced and Strict, on direct routes, a host whose DNS chain runs through an alias the lists block (judged with the host as its source, so `$third-party` vendor rules apply) is refused like the tracker (`cloaking.rs`, `proxy/uncloak.rs`), except an alias on the host's own site, a host a list excepts, a site with blocking off, and a page its workspace is opening, as in uBO. Not on Linux, whose navigation handler cannot tell iframes apart.
- **Strict mode's script block**: Strict privacy blocks third-party scripts except those from the page's owner's other domains (quoracdn.net on quora.com, fbcdn.net on facebook.com), from Wis's own owner list and Google's Related Website Sets (`site_entities.rs`); the filter lists still apply after.
- **Clean links**: links lose their tracking parameters as they are followed (`protection/clean_links.rs`, `wis_core::clean_followed_link`), by the table behind "Copy clean link" except that subscriber ids (`mkt_tok`, `_hsenc` and the like) stay on unsubscribe and email-preference pages, and not at all when the destination site has blocking off in the site panel. On macOS a main-frame GET of type link-activated is cancelled and re-navigated clean through wry's main-frame navigation hook (seventeenth patch). The server redirects a click sets off keep that type, so a link shim's `fbclid` goes too, while typed loads, `location` changes, reloads, back/forward, jumps within the page and downloads are left alone. The re-navigation drops the Referer. Cmd/middle-click, `target=_blank`, widget panels' cross-site clicks, Peek, the page menu's open-link actions, the navigation guard's carry-out and links from other apps are cleaned on every platform. On Windows wry's navigation start hook (eighteenth patch) does the same for a user-initiated new-document start and the redirects that share its navigation id; WebView2 reports no method, so a start with a `Content-Type` header counts as a form POST, and since it counts its own API loads as user-initiated, typed and restored loads are cleaned there too (runtime-unverified). Linux same-tab clicks are not cleaned: WebKitGTK's decide-policy cannot tell a main-frame navigation from a subframe's, so cleaning could load an iframe's link in the whole tab.
- **Site panel**: the padlock icon opens a panel for the tab's site with three switches, saved per host (`wis_core::sites::protection`, `UserSettings.site_protection_overrides`) and applied on reload. Turning off blocking stops the in-page layers on that site (Wis's own rule lists through `_setContentRuleListsEnabled:exceptions:`, so extensions' rules keep applying; list-based element hiding and scriptlets; the user's own hidden elements stay), while the workspace proxy still refuses listed servers, since it cannot tell which page a request came from. The JavaScript switch is macOS only (`allowsContentJavaScript`; Wis's injected scripts keep running), as is the fingerprinting protection switch, which turns the workspace's protection off for that site's navigations and is hidden in Permissive workspaces. In a private workspace a change is held in memory until Wis quits (`AppState.site_protection_session`) and applies to that host everywhere until then. All ride the one per-navigation hook in `pages/preferences.rs`, which also sets autoplay; the padlock shows a dot while a site has any switch off that applies in the tab's workspace. On macOS the panel also counts what was blocked on the page, by server (`protection/page_blocks.rs`, polled while the panel is open): loads Wis's rule lists blocked, reported through the `_webView:contentRuleListWithIdentifier:performedAction:forURL:` delegate method (wry's sixteenth patch), and loads the proxy refused, seen as failed loads through `_resourceLoadDelegate` whose host the filter engine blocks (`TrackerBlocker::blocks_tunnel`, the proxy's own judgement). Counts live in memory per tab and reset when a new page commits. Below the switches the panel lists what is saved for the site, gathered from the per-site maps by `features/site/lib/siteRules.ts` (camera and microphone, autoplay, zoom, user agent, open in app, hidden elements), each with a forget button that patches settings; Settings > Privacy lists the sites with protection off.
- **History & cookies**: per-workspace deduped history with search, and import of the last 180 days from Chromium- and Firefox-family browsers (Settings > Import); native site-data listing + per-domain clear. The clear-data dialog takes a time range (1 hour, 24 hours, 7 days, all time) and separates history, cookies, cache and site storage.
- **Browser identity**: modern Safari-class UA by default with per-host overrides (`wis_core::sites::user_agent`), OS-following platform token; **open in default browser** exit hatch.
- **Extensions** (macOS 15.4+, early): WebExtensions installed from the Chrome Web Store (from the extensions menu on an item's page, its package checked against Google's signature, and kept up to date about daily unless an update asks for more; folder installs can be linked to their listing to update too), a folder or a `.zip` after a review (what they can do, permissions WebKit cannot give, very large blocking rule sets), copied into Wis's data folder, and run in each workspace's tabs (switchable per workspace; private workspaces only when allowed) by a controller per workspace whose store and background traffic follow the workspace's proxy; open pages are rebuilt with their session when the set changes. A puzzle button in the address bar lists them its popup to be expanded on click. Its popup is anchored to the button, with options pages opening in a window of their own. Pinned ones show their own button and badge beside it. When a running extension asks for more access, Wis asks under the extensions button and remembers the answer until Settings takes it back. Each runs on every site it asks for, or only on the sites allowed from the extensions menu.
- **Default browser**: registrable as the OS default on all three platforms (Compatibility settings row; macOS system prompt, Windows Default Apps hand-off, Linux `xdg-settings`); links clicked in other apps open as tabs, queued until the chrome is ready (`system/default_browser.rs`); a local file handed over opens as its `file://` URL when it exists.
- **Link routing**: Settings > Compatibility sends links from other apps to a workspace by site (`UserSettings::link_routes`, `wis_core::workspaces::link_routing`). A rule is a site with an optional path, stored as a URL host and an encoded, lowercased path so Unicode domains, trailing dots and `..` match as URLs do; the site covers its subdomains and the path its own segments. The most specific site wins, then the longest path, whatever the order. `update_settings` refuses more than 200 rules before locking and keeps only valid patterns pointing at existing, non-private workspaces; deleting a workspace drops its rules. A restored backup's rules join the current ones, remapped to the fresh workspace ids, or to the existing lasting workspace of the same name when the restore skipped its own; rules for workspaces not on this device are dropped before the merge, so they never displace a current rule. The shell asks `route_external_link` for each link and switches the front window to the target workspace before opening the tab; unmatched links open in the workspace the front window shows. Links are opened one at a time so a burst cannot interleave switches.

## Known limitations / engine tradeoffs

Wis renders with the OS system WebView (WKWebView on macOS) via Tauri/wry, the same engine as Safari. That choice is the source of the product's wins (tiny bundle, low RAM, Safari-class speed and battery, no bundled engine to update) and dictates these limits, which are structural rather than bugs:

- **Premium DRM video (Widevine)**: WKWebView's only CDM is Apple FairPlay, not Google Widevine, and there is no API to inject a Widevine CDM (the CDM hooks the engine's media pipeline, which WKWebView does not expose). FairPlay itself is not licensed for general third-party-app playback, and services like Netflix gate on the Safari app. Result: premium DRM streaming (Netflix/Disney+/etc., especially 1080p/4K) is degraded or blocked. Mitigation is the **Open in default browser** action, not an in-app fix. Adding native Widevine would require switching to a Chromium engine (CEF) plus a Widevine license, which would forfeit the bundle/RAM/battery wins; explicitly not pursued. Note: even Firefox forks like Zen punt DRM to Firefox for the same licensing reason. **MSE + EME/FairPlay**: Wis does enable WebKit's Media Source + Encrypted Media Extensions on remote webviews (`webview_prefs::apply_media_extensions`, guarded SPI `_setMediaSourceEnabled:`/`_setEncryptedMediaAPIEnabled:`/`_setLegacyEncryptedMediaAPIEnabled:`; `UserSettings.media_extensions_enabled`, default on, toggle in Settings -> Privacy). MSE alone (off by default in embedded WKWebView) restores adaptive streaming on many non-DRM video sites; EME exposes the FairPlay key system to services that request it. This does not unlock Widevine-gated services, and Safari-app-gated FairPlay services (Netflix) still refuse, those remain the Open-in-Safari handoff.
- **Browser extensions**: macOS 15.4+ only, through WebKit's `WKWebExtensionController`; WebView2's extension API is planned and WebKitGTK has no public equivalent. WebKit supports a subset of the WebExtensions API (no `userScripts`, `identity`, `downloads`, `history`, `sessions`, `tabGroups`, `sidePanel`, `offscreen` or blocking `webRequest`), so some Chrome extensions only partly work. Ad blocking stays with Wis's native stack (`WKContentRuleList` + the `adblock` crate, cosmetic filtering, scriptlets, the element picker) and the user-script runner.
- **Site isolation**: WebKit's site isolation is weaker than Chrome's (still rolling out upstream), offset by strong OS sandboxing and out-of-process rendering.
- **Other**: no cross-device sync, no mobile companion, and some newer web APIs (WebUSB/WebBluetooth/web push/PWA install) are partial or absent under WebKit. Some native parity still lags off macOS: session/history + session-cookie restore, per-tab task-manager memory, remain macOS-only. Linux's remaining gaps beyond those: per-site data management (list/delete/clear render an honest "not available yet"), uBO `+js` scriptlet injection, the theme -> page color-scheme push, and the media-consent gate on widget panels and Peek (tabs are gated); each degrades visibly or deny-safe, never silently. Private tabs on Linux also still get an ephemeral context each (wry's `new_ephemeral`), so a login does not carry across them. Site usage there counts focused time without an idle cutoff (no OS idle source yet).

## Build & release

- **CI** (`.github/workflows/ci.yml`): on push / PR to `main`, a matrix over macOS / Windows / Ubuntu installs deps (Linux pulls `libwebkit2gtk-4.1-dev` + packaging tools), builds the frontend, then runs `cargo fmt --check`, `clippy -D warnings`, and `cargo test`. This is the **only place the Windows (WebView2) and Linux (WebKitGTK) cfg-gated code is fully compiled**: a macOS host cannot cross-compile the `ring` C build, so platform code is otherwise isolate-verified against `webview2-com`/`windows` in throwaway crates. The first Windows/Linux run is the real validation gate for those ports (and may surface platform-specific lints to fix).
- **Release** (`.github/workflows/release.yml`): on a `v*` tag (or manual dispatch), a serialized matrix builds each OS installer via `tauri-action` and attaches them to one draft release: a universal `.dmg` (macOS), `.msi` / NSIS `.exe` (Windows), `.deb` / `.AppImage` (Linux). `bundle.targets: "all"` + `createUpdaterArtifacts` produce the signed updater artifacts, and `includeUpdaterJson` merges the per-platform entries into one `latest.json` (the matrix runs `max-parallel: 1` so that merge never races). The Linux leg additionally **strips the bundled `libwayland-*` libs from the `.AppImage` and re-signs it**: the Ubuntu 22.04 build host ships libwayland 1.20, which AppImage puts ahead of the host copy on its library path, so on newer-Mesa systems (Fedora 43 / Arch / Bazzite) EGL fails with `EGL_BAD_PARAMETER`; removing the three libs makes the AppImage fall back to the host's (every GTK system has them). A final `patch-appimage-updater` job then rewrites the now-stale Linux signature in the merged `latest.json` to match the re-signed AppImage. The Tauri updater signing key is wired; **Apple code-signing / notarization is deferred** (an unsigned `.dmg` still builds), so the updater stays effectively dormant until signing is configured.
